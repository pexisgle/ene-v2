# 利用シナリオ

この文書では [用語集](terms.md) の定義に沿って、5 つの機能仕様（[対話・音声・キャラクター](features/interaction.md)・[記憶とスキル](features/memory.md)・[感情とキャラクターの成長](features/mind.md)・[作業・見守り・スケジュール](features/tasks.md)・[環境設定・権限・拡張](features/setup.md)）を組み合わせた 4 つの代表的な利用シナリオをまとめます。
各シナリオでは日常の具体的な場面に沿って、ene を使って何ができるかとシステム内部の振る舞い、および途中で起きうる例外的な場面の流れを示します。
いずれの場面でもクライアント画面には文字入出力、設定、承認カードだけを置き、進捗パネルや作業一覧、記憶一覧の専用画面は持たず、やり取りや相談はコンパニオンとの対話で進みます。

## 1. 雑談しながら調査を任せ、方針変更からメール送信まで進める

デスクトップに常駐するコンパニオンと音声で話すことができる状態で、手元のフォルダには取引先 3 社の見積書が入っており、標準の判定モードに「外部への送信は常に確認する」という自由文ポリシーを設定しています。

1. 利用者は作業の合間に口パクや仕草を交えて音声で雑談でき、発話の途中で話しかけて読み上げを止めたり、声を出しにくい場面ではそのまま文字入力へ切り替えたりすることができます。
2. 続けて「このフォルダにある 3 社の見積もりとネット上の最近の評判を見比べてまとめておいて」と話しかけると、作業用のモードへ切り替えなくても「頭」が「手」へ裏側の調査を引き継ぎ、コンパニオンは自然な口調で引き受けます。
3. 「手」が資料の読み込みと Web 検索を進めている間も利用者は普段どおり雑談を続けることができ、会話の途中で割り込んで読み上げを止めても裏側の作業は中断されずに進みます。
4. 途中で「安さよりサポート体制と解約条件を重視してほしい」と伝えると、「頭」が同じ作業セッションのまま「手」へ方針変更を届け、重複ファイルが見つかったときも「2026 年版の方で比べていい？」とコンパニオン自身の言葉で相談してきます。
5. フォルダ内の比較や要約の作成は承認カードを出さずに完了して出典付きの報告が会話で返る一方、「この要約を取引先へメールで送って」と依頼すると自由文ポリシーに沿って第 3 段階の承認カードが表示され、カードを押すか会話で「いいよ、進めて」と答えることで送信が実行されます。
6. さらに会話の中で「ブラウザを使ってメールを確認していいよ」と伝えると、その条件が自由文ポリシーへ自動で追加され、今回の調査でうまくいった手順もスキル記憶として蓄えられて後日の似た依頼へ活かされます。

作業の途中で「やっぱりその調査は止めて」と伝えれば「手」だけが安全に停止し、LLM による判定がエラーや時間切れになった場合は安全側へ倒れて承認カードが表示され、確認なしで進めたい場面では FullAccess モードへ切り替えることもできます。

## 2. 日々の会話で記憶と心の状態が育ち、複数コンパニオンと暮らす

同じホスト上で 2 人のコンパニオンがデスクトップへ同時に常駐しており、それぞれに作者が定めた静的な人格設定と架空の背景や会話例が登録されています。

1. 利用者が 1 人目のコンパニオンへ普段の呼び方や譲れない前提、好みを話すと、重要度が最大になった事実は毎回検索しなくても会話の前提として参照され、複数のコンパニオンに共通する基本事項は共有エピソードにも残ります。
2. 2 人目のコンパニオンへ話しかけると名前呼びや話題に応じて応答する相手が分かれ、1 人目と交わした個別の思い出までは無条件に共有されず、それぞれが自分の文脈を保って会話に加わります。
3. 作業報告を喜ばれた直後は一時的な表情や仕草、言い回しや声の調子にその場の気持ちが表れ、時間が空くと一時的な気分は人格設定に基づく本来の落ち着いた気質へ自然に戻る一方、築かれた関係性や関心は保たれます。
4. 長いやり取りを重ねて裏側で会話の圧縮と記憶の整理が進むと、過去の話題へ触れた際に重要度や経過時間、関連度に応じた記憶が自然に呼び出され、作者が用意した架空の会話例と実体験が混ざることはありません。
5. 記憶違いを会話で正したり「さっきの話は忘れて」と伝えたりすると、訂正はその場の会話文脈で扱われて次の記憶の整理で定着し、忘れるよう求められた記憶は日常の会話で表に出にくくなります。

こうした記憶と心の状態は別のクライアントへ移ったり使用する LLM を変えたりしても引き継がれ、日々のやり取りだけで作者の定めた静的な人格設定が書き換わることはありません。

## 3. 「目」の見守りで声をかけられ、予定や作業を複数端末で引き継ぐ

ホストが常時稼働しており、利用者は PC に加えて外出先からも Tailscale Serve などの安全な経路を通じてスマートフォンや Web から同じコンパニオンへ接続できます。

1. PC で作業を続けていると、クライアント側の軽量なメタデータやローカル処理をもとに「目」が変化のない情報や重複を省き、伝える価値のある変化だけを「頭」へ渡して声かけや無言の仕草につなげます。
2. 利用者が「今は集中したいから静かにして」と伝えれば「頭」は声かけを控えて静観し、逆に自発的な声かけへ返答するとそのまま自然な雑談や相談へつながります。
3. 見守りとは別に、利用者が「毎朝 9 時に注目ニュースを 3 本まとめて」「18 時に連絡を思い出させて」と話しかけると「頭」が定期予定と単発予定を登録し、後から予定の一覧を尋ねたり不要な予定を取り消したりできます。
4. 翌朝に PC を閉じたまま 9 時を迎えてもホスト側で予定が発火して「手」がニュースの要約を進め、不在中に PC 側の端末能力や利用者の確認が必要になった操作だけは勝手に進めず保留されます。
5. 外出先でスマートフォンや Web から呼び出すと対話の窓口がその端末へ切り替わり、帰宅して PC を再びつないだ際には不在中の作業結果や保留中の確認事項をコンパニオンが対話で自然に伝えます。

利用しているクライアントが未接続の状態でその端末能力が必要な操作が起きた場合も、無理に実行を進めず保留またはエラーとして安全に扱われます。

## 4. キャラクターを作って配布し、モデル設定やプラグインで拡張する

ホストとデスクトップクライアントが起動しており、利用者は設定画面からプロバイダー、キャラクター、プラグインを自由に調整できます。

1. まずプロバイダー設定で認証情報の保存、利用可能なモデル一覧の取得、疎通確認を段階ごとに進め、外部へ送られるデータの種類と送信先を把握したうえで、「頭」「手」「目」および会話の圧縮や記憶の整理へクラウド AI やローカル LLM を割り当てます。
2. 次に「姿」の VRM モデル、「声」の音声合成設定とプリセット、「心」の初期の人格設定を組み合わせてキャラクターを作成し、初対面や作業失敗時の返答をプレビューで整えたうえで、同じキャラクターから複数のコンパニオンを作ってウィンドウ上への常駐やクリック透過、ドラッグ移動を日常の操作として利用します。
3. 作成したキャラクターを友人へ渡すときは「姿」「声」「心」ひとまとめのパッケージとしても各要素の単体パッケージとしても書き出しや再取り込みができ、API キーなどの秘密情報や育った記憶、会話履歴、心の状態は含まれません。
4. 普段の実務を広げたくなったら、最小限の「手」へ Web 検索やファイル操作、外部サービスをつなぐ MCP、外部の作業エージェントを取り込む ACP、あるいは自作のプラグインを追加や差し替えで組み込み、あわせて「目」の知覚センサーや「体」のモーションと表情のプラグインも設定画面で有効化や無効化を行います。
5. プラグインを導入する際はリスクと送信先が明示され、実際に動かすときも選択中の標準の判定モードまたは FullAccess モードに従って安全に動作します。

認証の不備や外部サービス側の制限でエラーが起きても原因が切り分けて示されて未許可の外部先へ自動で切り替わることはなく、API キーなどの秘密情報も「頭」や「手」、各クライアント、ログや記憶へ露出せずに守られます。
