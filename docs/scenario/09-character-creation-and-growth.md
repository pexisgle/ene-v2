# 09. 「体・声・心」の作成・プレビュー・分割配布と成長

VRMの「体」、TTSの「声」、詳細な振る舞い定義を含む「心」を組み合わせてキャラクターを作成し、プレビューで応答品質を確かめたうえで、パッケージとして共有・分割再利用し、さらに日々の交流で感情と受け答えが育っていくシナリオです。

## 対象機能

- [キャラクターの作成](../features/character/create.md)（体・声・心の登録、統合/個別パッケージの入出力、秘密・記憶・成長の除外、1キャラから複数コンパニオン作成）
- [感情システム](../features/character/mind.md)（LLMによる文脈に沿った感情整理・保持、発話・声・仕草への反映、再起動・モデル変更をまたぐ維持）
- [キャラクターの成長](../features/character/grow.md)（対話・経験の蓄積による「現在の心」と受け答えの傾向の変化）
- [心の設定とキャラクター定義](../design/character-profile.md)（名前・核・話し方・側面・会話例・背景・表現語彙、プレビュー）

## 前提条件

- 作者（ユーザー）が新しいオリジナルキャラクター「凪」を用意し、VRMファイルと利用可能なTTSエンジンを持っている。

## シナリオの流れ

### 1. 「体・声・心」の登録とプレビュー検証

1. キャラクター登録画面で以下を設定する：
   - **体**：用意した VRM 3Dモデルを割り当てる。
   - **声**：TTSモデルと音声接続設定を登録し、用途や場面に合わせて複数の音声プリセットを保持する。
   - **心**（[記入例「凪」](../design/character-profile.md#記入例凪) に準拠）：
     - 名前（`name`）、人格の核（`core`）、話し方（`persona`）、性格の側面（`facets`）、短い会話例（`examples`）、背景（`background`）、表現語彙（`expression`）を設定。
2. 登録時に設定画面の**プレビュー機能**で、初対面の一言、疲れている場面、曖昧な依頼、作業失敗時の報告などを試す（本番の会話履歴や記憶には混ぜない）。
   - 「もう頭が回らない」と試したときに作業継続を迫らず区切りを受け入れるか、「作業失敗」で未完了と原因・次の一手を伝えるかを確認し、心の設定を微調整する。

### 2. パッケージの統合／個別エクスポートとテンプレートからの複数運用

1. 作者は完成した「凪」を友人へ共有するため、統合「eneキャラクターパッケージ」として書き出す。さらに「体だけ」「声だけ」「心だけ」の単体パッケージとしてもエクスポート／インポートできるようにする。
   - **システム動作**：書き出されるのは配布用の初期プロファイルのみで、**APIキー等の秘密情報、個人的な記憶、会話履歴、交流を通じて育まれた性格・関係性の変化は含まれない**。
   - 取り込んだ友人は自分の環境でAPIキー等を安全に設定し、すぐに「凪」との対話・表示・読み上げを楽しめる。
2. 作者自身は、登録された「凪」をテンプレートとして、**「仕事用の凪」**と**「日常用の凪」**など個別の会話文脈や記憶を持つ複数のコンパニオン実体を作成・運用する。

### 3. 日々の対話を通じた感情の反映と成長

1. ある日の夜、ユーザーが落ち込んだ様子で話しかける。
   - **ユーザー（音声）**：「今日の発表、準備したのにうまくいかなかったよ…」
   - **システム動作**：単語の加点式や固定の好感度数値ではなく、LLMが文脈に沿って感情状態を整理・保持する。その状態は発話ニュアンス、声のトーン、デスクトップ上での仕草・リアクションへ補助情報として反映される。
   - **凪（音声）**：「それは悔しかったね……。今日はもう無理に振り返らず、少し休もうか。」
2. また別の日に作業報告を受けた際、以前に「短い結論の報告が役に立った」と感謝された経験が蓄積されている。
   - **システム動作**：交流から形成された対話の傾向が「現在の心」に保持され（Compaction時の振り返り等を通じて更新）、次の作業報告から自然に簡潔な報告スタイルが活かされるようになる。
   - 保持された感情や関係性・成長はホストに保存され、再起動・再接続・会話モデルの変更をまたいでも引き継がれる。

## 例外・境界ケース

- **自己像・価値観の編集**：作者自身が「人格の核」や価値観を変えたい場合は、[心の設定](../design/character-profile.md) から明示的に編集できる。
- **配布データとの分離**：どれほど長く寄り添って関係性が育っても、配布用パッケージを書き出した際にその私的な変化が漏れることはない。
