# 11. プラグインによる「手」「目」「体」の拡張と差し替え

「Everything is a plugin」の考え方に沿って、「手（外部ツール・MCP・ACPラッパー・Wasm）」「目（知覚センサー）」「体（モーション・挙動）」のそれぞれをプラグインとして追加・差し替えし、判定パイプラインで安全に保ったまま対話から自然に活用するシナリオです。

## 対象機能

- [機能の拡張](../features/extensions/README.md)（「手」「目」「体」のプラグイン追加、ACP対応エージェントラッパーの組み込み、Wasm/Extism実行、設定画面での有効化・無効化・差し替え）
- [作業の実行（「手」の役割）](../features/task/request.md)（プラグインAPIを通じた「手」の実装・組み込み）
- [権限とデータの管理](../features/settings/permissions.md)（拡張機能への3段階判定パイプラインの適用）

## 前提条件

- 標準状態のホストおよびデスクトップクライアントが稼働している。

## シナリオの流れ

### 1. 「手」「目」「体」の拡張プラグインを有効化する

1. ユーザーは設定画面から必要な拡張機能を選んで有効化する：
   - **「手」のプラグイン**：
     - 課題管理システムを操作する **外部MCPサーバー** を追加。
     - コーディング作業向けに、外部の **ACP（Agent Client Protocol）対応エージェントをラップした「手」** をプラグインAPI経由で組み込み、切り替える。
     - 軽量なデータ変換用に **Wasmプラグイン（Extism）** を追加し、安全に隔離された実行環境で利用する。
   - **「目」の拡張（クライアント側知覚センサー）**：
     - 特定エディタやブラウザの文脈をより詳しく取得してホストの「目」へ送る知覚プラグインを追加。
   - **「体」の拡張（クライアント側モーション・挙動）**：
     - 待機モーション、発話時の仕草、感情に応じた表情リアクションを増やすアバター表現プラグインを追加。

### 2. 拡張を意識しない自然な対話からの利用と安全な制御

1. ユーザーが作業中にプラグイン名やコマンドを意識せず、普段どおり話しかける。
   - **ユーザー（音声）**：「さっき見てたテスト失敗の件、関連チケットを探して修正案まで進めておいて」
2. **システム動作**：
   - クライアント側の **「目」の拡張** がエディタの文脈を捉え、ホスト側の「目」が価値ある変化として「頭」へ渡す。
   - **「頭」** が **「手」のプラグイン**（外部MCPサーバーやACPラッパー）へ作業を委譲する。
   - 拡張機能による操作もすべて [権限とデータの管理](../features/settings/permissions.md) の判定パイプライン（機械的許可 → Decision API → 必要時のみ承認カード／会話代理承認）を通って安全に実行される。
   - 返答や待機中には、追加された **「体」の拡張** の仕草・表情リアクションが自然に連動する。

### 3. 設定画面からの無効化と差し替え

1. 別の開発フェーズへ移ったため、ユーザーは設定画面から先ほどのMCP連携を無効化し、別の「手」プラグインや別のモーションプラグインへ差し替える。
2. **システム動作**：設定変更後は不要な拡張が無効化され、新しいプラグインが即座に利用可能になる。

## 例外・境界ケース

- **クライアント能力に依存する拡張**：クライアント側で動く「目」「体」の拡張は、そのクライアントが `RegisterClient` で能力を登録している環境でのみ利用可能になり、未導入クライアントへ移動した際は公開されない。
