# 06. 機械的許可・Decision API・承認カードと会話代理承認

ユーザーに複雑な権限マトリクスを意識させず、**「機械的な許可 → Decision API（安全確認＋自由文ポリシー判定）→ ユーザー承認」** の3段階パイプラインによって、日常操作の確認を減らしつつ危険・ポリシー違反時だけ安全に確認を求めるシナリオです。

## 対象機能

- [権限とデータの管理](../features/settings/permissions.md)（3段階判定、自由文ポリシー、「常に承認」ルール保存・削除、承認カードと `resolve_approval` による会話代理承認、エラー時の安全側倒し、秘密情報の保護、離席中保留と実行履歴）
- [Tools](../features/tools/README.md)（`resolve_approval(request_id, decision)`）

## 前提条件

- 設定画面の「自由文ポリシー」に「外部への送信は常に確認」と記載されている。
- APIキーやメール認証情報などの資格情報はホスト側の資格情報ストアで保持されており、エージェントには直接見えない。
- 本アプリは OS ネイティブの Sandbox 隔離を持たず、`process-wrap` によるプロセス管理とこの3段階判定パイプラインおよび承認で安全性を担保する。

## シナリオの流れ

### 1. 第1段階（機械的な許可）：ホスト管理ツールや「常に承認」一致は確認なし

1. ユーザー（音声）：*「作業メモの内容整理して、さっき決めたルールも記憶に足しておいて」*
2. **システム動作**：
   - 記憶更新などのホスト管理の安全なツールは、第1段階の機械的許可により確認なしで即座に実行される。

### 2. 第2段階（Decision API）：安全かつポリシーに反しない操作は自動通過

1. ユーザー（音声）：*「ワークスペースの `draft/` にあるメモをまとめて `summary.md` を作っておいて」*
2. **システム動作**：
   - 第1段階に一致しないため、第2段階の **Decision API** へ送られる。
   - 操作内容・ユーザーの依頼文脈の安全性と、自由文ポリシー（「外部への送信は常に確認」）への適合性が評価され、ワークスペース内の整理だけで問題ないと判定されるため、**承認カードを出さずに実行**される。

### 3. 第3段階（ユーザー承認）：ポリシー該当時の承認カードと会話での代理承認

1. ユーザー（音声）：*「できた `summary.md` を、取引先の田中さん（`tanaka@example.com`）にメールで送っておいて」*
2. **システム動作**：
   - Decision API が自由文ポリシー「外部への送信は常に確認」に照らして要確認と判断し、第3段階のユーザー承認へ進む。
   - 画面上に **「承認 / 常に承認 / 拒否」** を選べる承認カードが表示され、キャラクターも確認する。
3. **凪（音声）**：「田中さん宛てにメールを送ってもいい？」
4. **ユーザー（音声）**：「うん、いいよ。進めて」
   - **システム動作**：画面の承認ボタンだけでなく、会話の中でユーザーがOKしたと「頭」が判断したため、「頭」が `resolve_approval(request_id, decision)` を呼び出して代理承認を確定し、メール送信が実行される。
5. 別の宛先（`team@example.com`）への送信時にユーザーが画面カードで **「常に承認」** をクリックした場合：
   - 操作ルールが保存され、次回以降同じ操作は**第1段階の機械的許可**で即座に通過するようになる。
   - 設定画面からは「自由文ポリシー」の編集や、保存済み「常に承認」ルールの一覧確認・削除が可能。また、実行履歴には判定結果と適用されたポリシー／ルールが記録され、あとから確認できる。

### 4. Decision API の異常時（安全側）と離席中の保留

1. **Decision API のエラー・タイムアウト時**：
   - 判定中に Decision API がタイムアウトやエラーになった場合は、無断で実行せず**安全側（ユーザー承認）**へ回し、承認カードを出す。
2. **離席中の保留**：
   - ユーザーが離席している間に要確認の操作が発生した場合は保留状態として保持され、戻った際の対話や画面の承認カードからまとめて確認できる。

## 例外・境界ケース

- **秘密情報の非露出**：メール送信や外部API呼び出しに必要な資格情報はログ・記憶・通知にも一切残らない。
- **ツールごとの権限マトリクス非採用**：`purpose / destination / data_kind` のような複雑なマトリクス設定UIは設けず、自由文ポリシーと「常に承認」ルールのみで管理する。
