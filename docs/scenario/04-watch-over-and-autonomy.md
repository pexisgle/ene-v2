# 04. 「目」による見守り・価値ある変化の選別と自発声かけ

軽量・高速・安価なモデルで動く「目」エージェントが、クライアントから送られる画面や入力の変化・時間経過を常時読み込み、**「頭」に伝える価値のある情報だけを選別して渡す**ことで、邪魔にならない見守りと自然な声かけを実現するシナリオです。

## 対象機能

- [Autonomy](../features/autonomy/README.md)（「目」による知覚評価と「頭」への選別伝達）
- [自発的な働きかけ（見守り）](../features/autonomy/watch-over.md)（「目」によるノイズ除外と要約、「頭」のSpeak/Work/静観判断、性格・指示に応じた調整、対話への移行）
- [デスクトップでのキャラクター表示](../features/character/desktop.md)（待機・視線・リアクション）

## 前提条件

- デスクトップクライアントが稼働中。クライアント側の「目」のセンサーが、アクティブウィンドウ変化・入力状況・経過時間等の軽量メタデータをローカル解析優先でホストへ送っている（クライアント画面に知覚の常設表示は設けない）。
- ホスト側では「目」（知覚評価エージェント）に軽量・高速・安価なモデルが割り当てられている。
- コンパニオン「凪」は「相手が自分のペースを取り戻せることを大切にする相棒」という性格を持つ。

## シナリオの流れ

### 1. 日常のウィンドウ切り替え（ノイズ）は「目」の段階で落とす

1. ユーザーがブラウザ・エディタ・チャットツールを普段どおり行ったり来たりしながら集中して作業している。
2. **システム動作**：
   - クライアントから送られる操作環境やアクティブウィンドウ変化を、ホストの「目」が常時読み込んで評価する。
   - 単なる通常のウィンドウ切り替えや変化の乏しい状態は「頭」に伝える価値のないノイズと判定され、**「目」の段階で落とされる**。
   - 「頭」（高コストな会話モデル）は不要に呼び出されず、凪はデスクトップ上でまばたきや視線追従など静かな待機を続ける。

### 2. 価値のある変化を「目」が拾い、「頭」が自発的に声をかける

1. 15分ほど経ち、ユーザーの動きが変わる。VS Code で同じソースファイルを開いたまま入力が止まり、ブラウザで同じエラー文言のページを何度も行き来している。
2. **システム動作**：
   - 「目」がこの変化と経過時間を「文脈上価値のある変化」と判断し、要点だけを要約して「頭」へ渡す。
   - 情報を受け取った「頭」は、過去の記憶や凪の性格を踏まえて **話しかける（Speak）／「手」に裏タスクを頼む（Work）／静かに見守る** の中から、軽く声をかけることを選ぶ。
3. **凪（音声）**：「さっきから同じエラーのページを行き来してるみたいだけど、少し詰まってる？ もしよければ、原因の手がかりをこっちで調べておこうか？」

### 3. 双方向対話へのシームレスな移行と裏タスク発注

1. ユーザーが手を止めて応じる。
   - **ユーザー（音声）**：「あ、見てた？ そうなんだよ、設定の書き方がドキュメントのどこにあるか見つからなくて」
   - **凪（音声）**：「じゃあ、手元の資料と公式ドキュメントの方を裏で探しておくね。」
   - **システム動作**：自発的な声かけを起点に通常の対話（Chat）へスムーズに移行し、「頭」が「手」に調査タスクを委譲する（あるいは状況によっては、話しかけずに「手」へ裏タスクだけ頼むこともできる）。

### 4. ユーザーからの指示による声かけ抑制

1. 調査結果を聞いた後、ユーザーは一気に集中して書き上げたい時間帯に入る。
   - **ユーザー（音声）**：「ありがとう！ ここから1時間は集中して書き切りたいから、しばらく静かにしてて」
2. **システム動作**：
   - 「頭」がその指示を文脈として踏まえるため、以降「目」から通知が上がってきても、緊急時を除き静かに見守る判断を取り、ユーザーの集中を妨げない。

## 例外・境界ケース

- **知覚情報のプライバシーと通信負荷**：画像キャプチャを無暗にクラウドへ送り続けるのではなく、アクティブウィンドウ等の軽量メタデータや端末内でのローカル解析を優先する。
- **発話のない静観時**：クライアント画面上に「目」が今何を見ているかを示す常設ビューアは表示しない。
