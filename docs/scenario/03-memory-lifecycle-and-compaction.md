# 03. 記憶の形成・時間減衰・対話での忘却とCompaction連動整理

日々の会話から何がどう記憶され、トークン使用率が閾値を超えたタイミングの Compaction に合わせて記憶・感情・成長が一括整理される流れと、FTS5＋ベクトル検索・時間減衰・引用ガード・対話での確認/訂正/忘却を確認するシナリオです。

## 対象機能

- [記憶機能](../features/memory/README.md)（エピソード記憶、重要度0〜10、`emotion`・`embedding`・`memory_edges`、Pinned/Core Memory、Compaction連動の一括整理、FTS5＋ベクトル検索と時間減衰、引用ガード `cited_in` / `estimated_cited_in`、対話での確認・訂正・忘却）
- [Chat](../features/chat/README.md)（トークン使用率閾値によるCompactionと連動した記憶・感情・成長の一括処理、会話ログと長期記憶の独立）
- [Tools](../features/tools/README.md)（`mind_recall`, `mind_read`, `mind_update`）

## 前提条件

- ユーザーはコンパニオン「凪」と数週間にわたり対話を続けている。
- クライアントに人間が管理するための記憶一覧UIは存在しない。

## シナリオの流れ

### 1. Compaction に連動した記憶・感情・成長の一括整理

1. **数週間前の会話（些細な雑談と重要な事実の混在）**：
   - ユーザーは会話の中で *「コンビニで新作の抹茶ラテ買ったけど甘すぎた」* という雑談と、*「実は甲殻類アレルギーなんだよね。来週の海鮮居酒屋、正直ちょっと気が重いんだ」* という大事な事情・感情を話した。
2. 会話が積み重なり、プロンプトのトークン使用率が閾値を超えたタイミング（ターン境界・会話の区切り）で **Compaction** が実行される。
   - **システム動作**：Compaction の実行に合わせて、同じ会話ログの振り返りとして **記憶の整理・統合（Consolidation）**、**感情・関係性の更新**、**キャラクターの成長** がまとめて処理される。
   - 「抹茶ラテが甘すぎた」は低重要度、「甲殻類アレルギーで海鮮居酒屋が気が重かった」は高重要度・感情タグ（`emotion`）・関連する記憶とのつながり（`memory_edges`）とともにベクトル埋め込み（`embedding`）付きで永続化される。
   - ユーザーの呼称やアレルギーのような譲れない前提・基本プロファイルは、検索に頼らず常にコンテキストの動的文脈枠へ注入される常時注入記憶（Pinned / Core Memory）として扱われる。

### 2. FTS5＋ベクトル検索、時間減衰、引用ガード

1. 数週間後の昼休み、ユーザーが食事の相談をする。
   - **ユーザー（音声）**：「今度の歓迎会のお店探し、手伝ってくれる？美味しいお店がいいな」
   - **システム動作**：
     - 記憶想起は **FTS5による全文検索とベクトル埋め込みの類似度検索** を組み合わせ、Relevance（関連度）・Importance（重要度）・Recency（直近性）でスコアリングする。
     - 過去の些細な「抹茶ラテ」は時間経過でスコアが下がり、唐突に持ち出されない。一方、「甲殻類アレルギー」は高い基礎スコアを保つため自然に配慮される。
   - **凪（音声）**：「いいね、探してみようか。エビやカニがメインじゃないお店、たとえばイタリアンとか焼き鳥中心で絞ってみようか？」
2. 別の雑談でユーザーが古い話題を直接尋ねる。
   - **ユーザー（音声）**：「そういえば前にコンビニで買って甘すぎたって言ってた飲み物、なんだっけ？」
   - **システム動作**：直接の言及で Relevance が高くなり、低重要度の古い記憶でも遡って想起される。
   - **凪（音声）**：「たしか新作の抹茶ラテだったよね。」
3. **引用ガードによる自己汚染防止**：
   - 仮に類似検索で無関係な記憶が候補としてコンテキストに載っただけでも、`last_accessed_at` は無条件に更新されない。プロンプト注入実績と照合し、LLMが発話や行動で実際に参照・利用したと判定された記憶（`cited_in` / `estimated_cited_in`）のみ `last_accessed_at` が更新される。

### 3. 対話だけで完結する記憶の確認・訂正・忘却

1. ユーザーが自分の記憶内容を確認する（記憶一覧画面は存在しない）。
   - **ユーザー（テキスト）**：「私の食べ物の好みとか前提について、今覚えてること教えて」
   - **システム動作**：「頭」が `mind_recall` / `mind_read` で記憶と関係性コンテキストを参照して答える。
   - **凪（テキスト）**：「甲殻類が食べられないことと、辛いものが苦手だったのは覚えてるよ。」
2. ユーザーが訂正と忘却を指示する。
   - **ユーザー（テキスト）**：「辛いものは最近好きになったから直しておいて。あと、前に話した元カノとの旅行の話は忘れて」
   - **システム動作**：
     - 「頭」が `mind_update` で記憶を訂正・忘却する。
     - 「忘れて」と指示された記憶は想起優先度（重要度）が下げられ、以降の日常会話で思い出されにくくなる。
   - **凪（テキスト）**：「わかった、辛いものは好きになったんだね。旅行の話はもう持ち出さないようにするよ。」

## 例外・境界ケース

- **過去の生ログ圧縮後の継続**：すべての会話ログをプロンプトへ載せ続けることは前提とせず、Compaction 後の要約と抽出された長期記憶・Pinned記憶によって対話が破綻なく継続する。
- **モデル変更・端末切替をまたぐ永続化**：記憶はホスト側で永続化されるため、端末や利用モデルを変えても失われない。
