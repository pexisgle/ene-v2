# 02. 作業・横断リサーチの依頼、並行雑談、方針変更と相談

単発の質問ではなく、複数のローカル資料とWeb情報を突き合わせる実務タスクをプラグイン化された「手」へ委譲し、作業中に雑談や方針変更を挟みながら、定期的な情報交換を通じた相談、結果の受け取り、スキル学習までを対話の中で完結させるシナリオです。

## 対象機能

- [作業の実行（「手」の役割）](../features/task/request.md)（「頭」からプラグイン化された「手」への委譲、定期的な情報交換による進捗共有・相談・方針変更、並行雑談、報告形式の自律判断）
- [調査の依頼](../features/task/research.md)（Web＋ローカル資料の横断リサーチ、比較表・要約レポート、深掘り）
- [記憶機能（スキル記憶）](../features/memory/README.md)（HermesAgent方式 `SKILL.md` の自律書き出しとプログレッシブ・ディスクロージャー）
- [Tools](../features/tools/README.md)（`start_work`, `send_work`, `stop_work`）

## 前提条件

- ワークスペース内の `proposals/` ディレクトリに、取引先3社（A社・B社・C社）のPDF見積書が入っている。
- クライアントには専用の進捗パネルや作業一覧・質問カードは存在せず、すべてのやり取りは「凪」との対話で行う。

## シナリオの流れ

### 1. ゴールを伝えてプラグイン化された「手」へ任せる

1. ユーザーが作業内容を音声で依頼する。
   - **ユーザー（音声）**：「`proposals/` にある3社分の見積もり資料と、各社のネット上の最近の評判を調べて、どこに頼むのがよさそうか比較してまとめておいて」
2. **システム動作**：
   - 「頭」（凪）は手順を要する実務作業と判断し、`start_work` でプラグイン化された「手」へ非同期に依頼する。
   - 「頭」の会話プロンプトにはスキル一覧を入れない一方、「手」の開始時にはコンパクトなスキル一覧（名前と1行概要）が渡される。
3. **凪（音声）**：「わかった。3社の資料と最近の評判を見比べて整理しておくね。」

### 2. 作業中の並行雑談と途中の方針変更

1. 「手」がバックグラウンドで資料読み込みとWeb検索を進めている間、ユーザーは普通に雑談を続ける。
   - **ユーザー（音声）**：「いやー、今日の午後眠すぎない？」
   - **凪（音声）**：「午後の頭って重くなりやすいよね。コーヒーでも淹れる？」
   - **システム動作**：「頭」と「手」が分離しているため、裏の作業を止めずに普段どおりの対話を続けられる。
2. 数十秒後、ユーザーが比較軸を変えたくなる。
   - **ユーザー（音声）**：「あ、さっき頼んだ比較だけど、安さよりも導入後のサポート体制と解約条件を重視して見比べてほしい」
   - **システム動作**：「頭」が `send_work(work_id, text)` を呼び、進行中の「手」へ方針変更と追加要望を伝達する。
3. **凪（音声）**：「了解、価格よりもサポート体制と解約条件を優先して見直すように伝えておくね。」

### 3. 定期的な情報交換を通じた途中経過の共有と相談

1. 「頭」と「手」が定期的な情報交換を行う中で、「手」から「`proposals/` に `B社_見積_2025.pdf` と `B社_見積_2026.pdf` の2つがあり、どちらを使うべきか確認が必要」という途中経過と相談事項が「頭」へ共有される。
2. 「頭」は自分の判断だけでは決められないため、対話の中で自然にユーザーへ相談を持ちかける。
3. **凪（音声）**：「いま進めてもらってるんだけど、B社の見積もりファイルが2025年版と2026年版の2つ入ってるんだ。新しい2026年版の方で比較していい？」
4. **ユーザー（音声）**：「あ、古いのも入れっぱなしだった。2026年版だけで大丈夫だよ」
   - **システム動作**：「頭」が `send_work` で回答を「手」へ伝え、作業が再開される。

### 4. 結果の受け取り、追加深掘り、スキル記憶の蓄積

1. 調査と整理が完了し、「手」から「頭」へ最終結果が共有される。
2. **システム動作**：結果をどう伝えるか（口頭で要約を伝えるか、ファイルとして保存するか等）は「頭」の自律判断に任される。今回は「詳細な比較表をワークスペースに `comparison.md` として保存し、会話では結論の要点を伝える」と判断する。
3. **凪（音声）**：「3社の比較がまとまったよ。サポート体制と解約条件で選ぶならC社が一番バランスがよさそう。細かい比較表は `comparison.md` に保存してあるからね。」
4. ユーザーが追加の深掘りを頼む。
   - **ユーザー（音声）**：「C社の解約条件のとこだけ、もう少し詳しく教えて」
   - **システム動作**：同じ対話フローで要点を詳しく説明し、必要なら追加調査も「手」へ繋ぐ。
5. **スキル記憶（HermesAgent方式）**：
   - 作業の成功を通じ、今回得られた手順・利用ツール・注意点（「複数社の見積と公開評判の比較手順」「年度重複時の確認」）が `SKILL.md` として自律的に書き出される（Closed Learning Loop）。
   - 次回ユーザーが類似タスクを依頼した際、「手」は開始時のコンパクトな一覧から該当スキルを見つけ、詳細手順をオンデマンド取得して実行に活かす。

## 例外・境界ケース

- **途中中断の依頼**：ユーザーが *「やっぱりその調査、もう止めちゃっていいよ」* と伝えた場合、「頭」が `stop_work(work_id)` を呼び出し、進行中タスクの中断を要求する。
- **複数ツールの利用制限**：親エージェント（「頭」）に作業用ツールを直接持たせず「手」に委譲することで、「頭」の会話テンポを維持する。
