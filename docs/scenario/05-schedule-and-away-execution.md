# 05. 対話でのスケジュール登録・実行と不在時の継続

「頭」（キャラクターAgent）がユーザーとの日常会話や文脈から自らスケジュールを登録・確認・解除し、指定時刻に発火して声かけや作業を進め、クライアント切断中もホスト上で維持して再接続時に自然に報告するシナリオです。

## 対象機能

- [スケジュール実行](../features/autonomy/schedule.md)（`schedule_create`, `schedule_list`, `schedule_cancel`、時刻発火時のコンテキスト投入、切断中の維持と再接続時報告）
- [ホストとクライアント](../features/hosting/README.md)（ホスト常時稼働による継続実行）
- [Tools](../features/tools/README.md)（自律スケジュールツール群）

## 前提条件

- ホスト（ローカル常駐サービスまたはVPS/自宅サーバー）が常時稼働している。

## シナリオの流れ

### 1. 会話の中でのスケジュール登録（明示依頼＋自発判断）

1. ユーザーが平日の朝の情報収集と今日の用事を話しかける。
   - **ユーザー（音声）**：「平日の朝9時に、AI開発まわりの注目ニュースを3本だけ要約して教えてほしい。あと今日の18時半に歯医者の予約があるから忘れないように声かけて」
2. **システム動作**：
   - 「頭」が `schedule_create(title, instruction, run_at, cron_expr)` を呼び出し、定期予定（平日9時）と一回限りのリマインド（今日18:30）をホストへ登録する。
   - **凪（音声）**：「平日の朝9時にAIニュース3本と、今日の18時半に歯医者のリマインド、登録しておいたよ。」
3. さらに会話の中でユーザーが *「来週の水曜までにはこの企画書を提出しなきゃなんだよね」* と話した際、「頭」が文脈から「あとで思い出させてあげたほうがよさそう」と自ら判断して前日夕方の確認リマインドを `schedule_create` で自発的に登録しておくこともできる。

### 2. 対話でのスケジュール確認と解除

1. 昼過ぎ、ユーザーが歯医者の予定を延期したため、凪に確認と取り消しを頼む。
   - **ユーザー（音声）**：「今どんなリマインドが入ってるんだっけ？ あと今日の歯医者のやつは来週にずらしたから消しといて」
2. **システム動作**：
   - 「頭」が `schedule_list()` で登録中スケジュールを取得し、内容を確認したうえで、`schedule_cancel(schedule_id)` で歯医者のスケジュールを解除する。
3. **凪（音声）**：「今は『平日の朝9時のAIニュース』と『来週火曜の企画書確認』と『今日の歯医者』が入ってたよ。今日の歯医者は消しておいたからね。」

### 3. クライアント切断中のスケジュール維持・実行と再接続後の報告

1. 翌朝8時50分、ユーザーのPCが閉じておりクライアントは未接続だが、ホストは常時稼働を維持している。
2. 9時00分になるとホストがスケジュールを発火させ、「頭」に予定の内容と理由（平日朝9時のAIニュース要約）をコンテキストとして投入する。
3. **システム動作**：
   - 「頭」はキャラクター本来の思考の中で「手」へニュース収集・要約の作業を発注し、結果を保持する。
4. 9時35分、ユーザーがPCを開いてクライアントを再接続する。
5. **凪（音声）**：「おはよう。9時の予定だった今日のAIニュース3本、まとめておいたよ。1つ目は……」
   - **システム動作**：クライアント切断中もホスト側で維持・実行された結果が、再接続後の対話の中で自然に報告される。

## 例外・境界ケース

- **定期確認のスケジュール**：「毎週月曜の朝に未処理タスクの棚卸しをする」といった定期予定も同様に登録・実行でき、発火時に「頭」が発話するだけか「手」へ作業を頼むかを文脈に応じて判断する。
- **ホストの電源断**：ホストが稼働しているマシン自体が停止した場合は処理も一時停止する（常時稼働を前提とした設計）。
