# 07. 複数コンパニオン同席時の会話・タスク・共有記憶

ひとつのクライアント画面上に性格や役割の異なる複数のコンパニオンを同時に常駐させ、名指しや文脈に応じた会話参加、コンパニオンごとのタスク分離、個人／共有スコープによる記憶連携を確認するシナリオです。

## 対象機能

- [音声対話](../features/voice/README.md)（複数コンパニオン同席時の文脈や名前呼びに応じた会話参加）
- [ホストとクライアント](../features/hosting/README.md)（1クライアント画面上での複数コンパニオン同時常駐）
- [自発的な働きかけ（見守り）](../features/autonomy/watch-over.md)（複数コンパニオン存在時の性格・文脈に応じた自律応答）
- [記憶機能（共有記憶プール）](../features/memory/README.md)（個人／共有スコープを分けた記憶管理）
- [Chat](../features/chat/README.md)（コンパニオンごとの履歴管理と共有プール経由の連携）

## 前提条件

- デスクトップクライアント上に、2人の異なるコンパニオンが同時に常駐している：
  - **凪**：落ち着いた相棒タイプ（整理・見守り役）
  - **レイ**：明るく発想豊かなムードメーカー（企画・リサーチ役）
- ユーザーの基本属性（名前「悠太」、デザイン業、来週金曜がイベント本番）は**共有記憶プール**（共有スコープ）に保存されている。特別な別システムではなく、通常の記憶と同じ仕組み・検索機構のままスコープだけ分かれている。

## シナリオの流れ

### 1. 共有記憶プールとコンパニオン別の個別文脈

1. ユーザーは前日に**凪**とだけ「最近ちょっと寝不足気味」と話し、**レイ**とは「イベントのノベルティ案」を話し合っていた。
2. 今日、レイに話しかける。
   - **ユーザー（音声）**：「レイ、来週金曜の本番に向けて、ノベルティの候補もう1回整理してくれる？」
   - **システム動作**：レイは共有スコープから「ユーザーが悠太」「来週金曜が本番」を参照しつつ、自分の個別会話履歴・記憶にあるノベルティ案を引き継いで応答する。

### 2. 名前呼びと文脈に応じた会話参加

1. ユーザーが画面上の2人に話しかける。
   - **ユーザー（音声）**：「凪、このトップページの配色案どう思う？」
   - **システム動作**：名前を呼ばれた「凪」が文脈に沿って応答し、レイは無理に割り込まない。
   - **凪（音声）**：「余白がきれいで見やすいと思うよ。ボタンのコントラストだけ少し強めてもよさそう。」
2. 続けてユーザーが2人共通の話題を振る。
   - **ユーザー（音声）**：「ねえ2人とも、今日の晩ごはん何がいいかな？」
   - **システム動作**：それぞれのキャラクターの性格と文脈に応じて、たとえばレイが明るく提案し、凪がそれを受ける形で自然に会話に加わる。
   - **レイ（音声）**：「今日は寒いし、あったかいスープカレーとかどう？」
   - **凪（音声）**：「スープカレーいいね。野菜も摂れそうだし、ちょうどよさそう。」

### 3. 自発的な見守り時の個別判断と、タスクの分離

1. ユーザーが作業中にエラー画面の前で止まっているとき、2人のコンパニオンはそれぞれの性格や直前の文脈に応じて「自分が声をかけるべきか、見守るべきか」を自律的に判断する。
2. ユーザーが特定のコンパニオンへ実務を依頼する。
   - **ユーザー（音声）**：「レイ、近所で遅くまで開いてるスープカレー屋を調べておいて」
   - **システム動作**：依頼を受けたレイ側の「頭」から「手」へ作業が渡され、凪の会話文脈や作業とは独立して進行・報告される。

## 例外・境界ケース

- **同一コンパニオンの複製との違い**：同じキャラクター設定をテンプレートにして別の記憶・履歴を持つ別コンパニオンを複数運用することもでき、共有したい情報だけを共有スコープへ置くことで役割分担を保てる。
