# 作業・見守り・スケジュール

この文書では [用語集](../terms.md) の定義に沿って、作業や調査の依頼、プラグインによる機能の拡張、「目」による見守り、および「頭」によるスケジュール実行の機能仕様をまとめます。
システムの内部では対話や判断を受け持つ「頭」と実務を進める「手」に役割を分けていますが、利用者への報告や相談は常にコンパニオン自身の言葉として伝えます。
「頭」は会話のテンポを保つため、記憶の参照や更新、作業の委譲と中断、確認が必要な操作の承認、スケジュールの管理、および端末能力の呼び出しという軽い操作だけを持ちます。
一方で、Web 検索やファイル操作、複数の資料を横断する調査、外部サービスの操作といった手順を要する実務は「手」が対話と並行して裏側で進めます。

## 作業と調査の依頼

作業や調査の依頼は [Claude Cowork](../references.md#claude-cowork) の通常対話と実務の境界をなくす体験を基準とし、利用者がモードを切り替えなくても日常会話の流れから自然な言葉で依頼するか、「頭」自身の判断で「手」へ引き継ぎます。
「手」が裏側で作業を進めている間も利用者との雑談や相談は止まらず、会話や読み上げを途中で遮っても進行中の作業自体は独立して動き続けます。
進行状況や確認事項は「頭」が会話の中で伝え、専用の進捗パネルや作業一覧画面を設けなくても、同じ作業セッションのまま追加の指示で方針を変えたり作業を中断したりすることができます。
Web 上の情報や手元の資料をまたぐ本格的な調査も同じ流れで任せることができ、「手」が情報を集めて比べた結果を、出典付きの要約や比較として「頭」が返します。
作業を通じて得られた再利用できる手順や注意点は [記憶とスキル](memory.md) で扱うスキル記憶として蓄えられ、次の作業へ引き継がれます。

## 最小限の「手」とプラグインによる拡張

作業を受け持つ「手」の本体は最小限の実装にとどめ、[deepseek-harness](../references.md#deepseek-harness) のように構成要素をプラグインとして追加や差し替えをする仕組みと、[Pi](https://pi.dev/) のように最小限の基盤へ自作の拡張を加えていく考え方を取り入れます。
これにより Web 検索やファイル操作、外部サービスとつなぐ MCP、外部の作業エージェントを取り込む ACP の仕組みなどは最初からすべてを抱え込まず、既存のプラグインを導入したり利用者自身が新しいツールや手順を自作して加えたりすることができます。

## 「目」による見守りの仕組み

「目」は利用者の明示的な指示や予定とは別に働き、クライアントから届く操作環境や入力状況、経過時間などの情報を軽量なモデルで評価して、「頭」へ知らせる価値のある変化だけを選び出します。
変化のない情報や重複した内容は「目」の段階で省き、画面や状況の取得でもクライアント側の軽量なメタデータやローカル処理を優先して通信負荷や不要な情報送信を抑えます。
「目」から知らせを受け取ると、「頭」は集中したいという利用者の意向やその場の文脈を踏まえて言葉で声をかけるか、無言の仕草にとどめるか、静観するかを決め、声かけに利用者が返答すればそのまま通常の対話へ移ります。
見守りでは声かけの場面や頻度を固定の仕様として決め打ちにせず、情報を集めて選別する仕組みだけを備えたうえで、実際の動作を見ながらプロンプトや判定の決まりを調整していきます。

## 「頭」によるスケジュール実行

周囲を観測する「目」とは別に、「頭」は [Hermes Agent](../references.md#hermes-agent) のホスト側で単発や定期の予定を管理して発火させる仕組みを取り入れ、会話や文脈から自らスケジュールを登録、確認、解除します。
指定の時刻に達するとホストが「頭」へ予定の内容を渡し、「頭」はその時点の記憶や文脈をもとに利用者へ声をかけたり「手」へ作業を任せたりします。
スケジュールや進行中の作業はホスト側で保たれるためクライアントを閉じても途切れず、不在中に発生した端末依存の操作や利用者の確認が必要な判断は保留して、再びつながった際の対話で自然に伝えます。
