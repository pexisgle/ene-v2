# 作業の依頼

やりたいことを対話で伝えるだけで、情報整理からファイルの作成、外部ツールの操作まで、多彩な実務をキャラクターに任せられます。

## 具体的な振る舞い

1. ユーザーが対話の中で、依頼したい作業のゴールや要望を特定のコンパニオンに伝えます。
2. 依頼を受けたコンパニオンが内容を咀嚼し、必要な作業工程やタスク計画を立案します。
3. コンパニオン本体の対話セッションとは独立したサブエージェント（エージェント）を内部で起動し、コンパニオンから作業指示を下達します。複数コンパニオンが存在する場合も、タスクは依頼されたコンパニオンが一貫して担当・管理します。内部の複雑な実行ログは表層には現れず、コンパニオンが窓口として対応します（開発者向け画面等で詳細ログの閲覧は可能）。
4. [許可された機能と権限の範囲](../settings/permissions.md)内で、ホスト上のファイルや外部連携ツール、対応クライアントから提供された端末内のリソースを活用して作業を自律的に進行します。
5. **作業中の雑談と並行対話**: エージェントがバックグラウンドで作業を進めている最中であっても、ユーザーはコンパニオンと普段通り自由に雑談や相談を続けられます。
6. **対話の中での自然な相談**: エージェントから新たな権限の許可や未決の重要判断が求められた場合、コンパニオンは「作業を見守りながら雑談している」という自然な文脈を保ちながら、対話の流れの中でユーザーへ相談を持ちかけます。
7. **進捗のリアルタイム共有**: エージェントとコンパニオンの間ではステップごとに緊密な情報連携が行われます。ユーザーが進捗を尋ねた際にも、コンパニオンが現在の進行状況を的確に把握しており、その場で淀みなく回答します。
8. **進捗に応じた軌道修正**: 進捗状況を踏まえてユーザーが方針の変更や追加の要望を伝えた場合も、コンパニオンを通じてエージェントへと速やかに指示が伝達されます。
9. **作業結果と最終報告**:
   - 作業が完了すると、何を行い、どうなったかをコンパニオンが対話の中で報告します。実行できなかった工程がある場合は、完了した部分と未達の部分を明確に区別します。ファイルの作成・編集や外部サービスへの操作など、作業結果は依頼内容に応じた形で対象環境へ反映されます。
   - **保存・反映先**: クライアント端末内でのファイル編集やComputer useの結果は、その端末環境へ直接保存・反映されます。外部サービスへの操作は対象サービスへ反映されます。ホスト上で作成するファイルは、別途指定がなければホスト上に保存されます。
   - **最終報告の閲覧**: 最終報告はホストに保持され、どのクライアントからでも閲覧できます。作成・編集したファイル自体を別端末へ同期することは前提とせず、詳しい内容を知りたい場合は、その端末からコンパニオンへ説明を依頼できます。
10. ユーザーは報告や作業結果を確認し、そのまま対話の中で詳しい説明や追加の手直しを依頼できます。
11. 過去の決定事項や学習済みの有用な手順は、[記憶機能](../memory/README.md)を通じて今回の作業へとスムーズに引き継がれます。過去の記憶のみを過信して完了を独断することはなく、現在のタスク状態、環境、権限を確実に検証しながら進めます。

## 制約事項

- 実行結果の成否が不確実な操作を独断で完了と見なして報告することや、エラーの原因を精査しないまま無作為に再試行を繰り返すことはありません。
