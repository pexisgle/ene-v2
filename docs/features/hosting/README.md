# ホストとクライアント

eneの実行基盤およびデータ管理を担う「ホスト」と、ユーザーインターフェースや描画を担う「クライアント」を分離して設計します。ホストは常時稼働を前提とし、1台のPC上で動かすローカル運用はもちろん、VPSや自宅サーバーでホストを動かし、PC・Web・スマートフォンなど多様なクライアントから同一のコンパニオンに接続できます。

## 利用形態と役割

| 構成要素 | 役割（認知・身体モデル） | 主な機能 |
| --- | --- | --- |
| **ホスト** | **「頭」**（思考・対話・判断）<br>**「手」**（実務実行プラグイン）<br>**「目」**（知覚の選別） | コンパニオンの常時稼働、記憶・感情・成長の永続化、Compaction、スケジュール実行、モデルや外部APIとの通信 |
| **クライアント** | **「目」**のセンサー<br>**「耳・口」**（音声入出力）<br>**「体」**（アバター描画） | ユーザーとのボイス／チャット対話、デスクトップ常駐アバターの描画、音声入出力、端末固有ツール・知覚情報の提供 |

ホストはGUIを持たないヘッドレス環境でも常時稼働します。会話や記憶・設定はホスト側で一元管理され、キャラクターの表示位置や音声のオン・オフといった表示設定はクライアント側で保持します。

### ホストへの接続とアクセス制御

- **接続経路の保護**: 遠隔接続は利用者が用意した Tailscale Serve や Cloudflare Tunnel + Access などの安全な経路で保護し、無保護のままインターネットへ直接公開しません。ローカル接続はローカル環境やOS権限で保護されたソケットを前提とします。
- **複数コンパニオンの常駐**: ひとつのクライアント画面上に複数の異なるコンパニオンを同時に常駐・表示させることができます。

## 具体的な振る舞い

1. クライアントをホストへ接続すると、過去の会話履歴や記憶・作業の進捗を共有した状態で対話を始められます。別の端末から呼び出した場合は、現在のアクティブな端末へシンプルに切り替わります。
2. クライアントを閉じたり通信が切断されたりしても、ホストは稼働を維持し、任された作業やスケジュールを継続します。
3. クライアントは自分が持つ能力（端末内ツール、知覚センサー、アバター表現など）をホストへ登録でき、登録された能力は「頭」や「手」からツールとして自動的に利用可能になります。
4. 端末内能力の実行にも[権限とデータの管理](../settings/permissions.md)の判定パイプラインが適用され、未接続時は安全にエラー・保留として扱います。

## 制約と検討事項

- 初期段階では個人の利用を主眼としており、複数ユーザー間でのホスト共有やホスト間の分散同期は対象外とします。
- 複数タスクが同じファイル等を同時に操作する場合の競合制御は、設計段階で具体化します。
