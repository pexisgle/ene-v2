# ホストとクライアント

eneの実行基盤およびデータ管理を担う「ホスト」と、ユーザーインターフェースや描画を担う「クライアント」を明確に分離して設計します。ホストは常時稼働を前提とし、1台のPC上でバックグラウンド稼働させる手軽なローカル運用はもちろん、VPSや自宅サーバーでホストを動かし、PC・Webブラウザ・スマートフォンなど多様なクライアントから同一のコンパニオンに接続することも可能です。

## 利用形態と役割

基本構成は、PC上で常時稼働するホストとデスクトップクライアントを動かすローカル環境です。必要に応じてホストを外部のサーバーへ配置し、外出先からスマートフォン等でアクセスするといった運用にも対応します。クライアントが閉じられたり端末が切断されたりしても、ホストは停止せず自律的にタスクやスケジュールを進行します。

| 構成要素 | 役割 |
| --- | --- |
| ホスト | コンパニオンおよびエージェントの常時稼働、会話履歴・キャラクター設定・タスク・最終報告の管理、自律実行スケジューリング、モデルや外部ツールとの通信 |
| クライアント | ユーザーとの対話、キャラクターの描画、音声の入出力、作業進捗や最終報告の閲覧、必要な確認への応答 |

ホストはGUIを持たないヘッドレス環境でも常時稼働します。会話や作業の状態はすべてホスト側で一元管理され、キャラクターの表示位置や音声のオン・オフといった設定は各クライアント側で個別に保持されます。なお、デスクトップ、Webブラウザ、スマートフォンなど、クライアントの実行環境によって利用できる機能の範囲は異なります。

### ホストへの安全な接続

- **接続経路のアクセス制御を利用する**: 遠隔接続は、利用者が選んだTailscale ServeやCloudflare Tunnel + Accessなどの仕組みで保護します。ホスト独自の端末ログイン・トークン管理は、保護された経路だけからAPIを受け付けられる場合は原則不要とします。Tunnel単体は利用者認証ではありません。
- **接続手段を交換できる**: クライアント側で接続先の発見、外部サービスへのログイン、通信経路の選択を拡張できるようにします。ホストの会話・設定APIは接続方式に依存させず、ホスト側のTailscaleやCloudflareの導入・設定はホスト外のサービスに任せます。外部アプリの導入を許容しつつ、可能な範囲で設定をGUIから案内・自動化します。
- **許可と取り消しの管理元を明示する**: 接続できる端末・ユーザーは外部サービス側で管理し、その管理画面や設定へ案内します。制御できる単位は選んだサービスに依存し、特定端末だけの取り消しができない方式で、その機能を提供済みと表示しません。接続を許可されたクライアント間でホスト管理権限の階層は設けません。
- **無保護の公開を禁止する**: ホストAPIをインターネットや無制限のLANへ直接公開しません。ローカル接続はOSの権限で保護したソケット等、またはローカル利用者全員を信頼できる環境に限ります。アクセス制御を確認できない遠隔経路では、認証なしAPIを有効にしません。

具体的な信頼境界、方式ごとの条件、現行コードからの移行は[ホスト接続の設計](../../design/host-access.md)に定めます。

### 複数コンパニオンの常駐と調停ルール

同一のコンパニオンが複数のクライアント上に同時にアクティブとして現れることはできません。ユーザーが別のクライアントから呼び出すと、その指示に応じて移動します。ユーザーの指示なしに別のクライアントへ移動することはありません。ただし、ひとつのクライアント上で複数の異なるコンパニオンを同時に常駐・表示させることは可能です。

複数コンパニオンが同一画面に存在する場合、以下の調停ルールが適用されます。
- **発話と応答の調停**: 各コンパニオンは宛先や会話の文脈から、自分が発言すべきかを思考の段階で判断し、発言しないことも選べます。「A、この資料を整理して」と呼びかけられた場合、Bは自分への依頼ではないと判断して応答しません。複数のコンパニオンが発言しようとする場合は、先に発話を開始したコンパニオンが優先され、同時に喋ることはありません。
- **タスクの管轄**: タスクは**依頼された特定のコンパニオン**が担当し、そのコンパニオンのサブエージェントとして実行されます。

## 具体的な振る舞い

1. クライアントから接続先のホストと接続方式を選択し、その方式が要求する認証・アクセス制御を通して接続します。接続先と通信状態を確認でき、端末や利用者の接続許可の追加・取り消しは、選択した外部サービスの管理機能で行います。
2. 同一ユーザーの複数端末から同一ホストへ接続することで、過去の会話履歴や作業の進捗、最終報告をどこからでも参照できます。PCで始めた対話や作業の続きをスマートフォンで行いたい場合は、コンパニオンを呼び出して引き継ぎます。作成・編集したファイル自体を全端末から直接閲覧できることは前提とせず、詳しい内容はコンパニオンへ説明を依頼できます。
3. クライアントを閉じたり通信が切断されたりしても、ホストは常時稼働を維持し、任された範囲内でホスト側のタスクやスケジュール実行を自律的に継続します。新たなアクセス権やユーザーの判断が必要な工程のみを保留とし、それに依存しない作業は進めます。処理結果や保留事項はホスト上に保持され、他の接続中クライアントや再接続時の対話からまとめて確認・回答できます。保留事項を重複して何度も通知することはありません。
4. 対応するクライアントは、手元の端末内にあるファイルやツールをホスト側から利用できるように安全に提供できます。[端末ごとの権限設定](../settings/permissions.md)で明示的に許可した範囲に限り、どのホスト・端末上で操作するか、どのデータを送信するかを厳密に区別して扱います。クライアントを接続しただけで端末全体への自由なアクセスを許諾することはありません。
5. 操作対象の端末がオフラインになった場合、その端末に依存する処理（Computer useや端末内ファイル操作など）を安全に保留し、その理由を明示します。成否が不明な操作を自動で安易に再試行することはせず、再接続後に安全な状態を確認したうえで再開を判断します。

## 制約と検討事項

- ホストは常時稼働を基本としますが、ホストが稼働するマシン自体の電源切断や障害時には処理が一時停止します。また、ホストが稼働していても、オフライン状態のクライアント端末に対して直接ローカル操作を行うことはできません。
- Webブラウザやスマートフォンにおいて、デスクトップ常駐や端末内ツールの自由な操作がPCと同様に利用できるとは限りません。利用可能な機能と制限事項は、クライアント上で明確に判別できるようにします。
- 初期段階では個人の複数端末利用を主眼としており、複数ユーザー間でのホスト共有、ホスト間の分散同期やデータ移行、ホスト不在クライアント単体での独立動作は対象外とします。
- Connect RPCは維持し、ローカルのアクセス制御と遠隔の信頼された入口を分けます。初回のVPS導入・GUIだけでの設定手順、Webブラウザ対応時のセッション・CSRF対策、クライアントの提供優先順位、プッシュ通知の連携基盤は引き続き具体化します。
- コンパニオンの端末間移動や切断・再接続の細かな制御、複数タスクが同じファイルやブラウザを操作する場合の競合制御は、設計段階で具体化します。
