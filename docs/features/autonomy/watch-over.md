# 自発的な働きかけ（見守り）

AITuberのエージェントループを参考に、「頭」（キャラクターAgent）が、ユーザーのPCの直近の画面や操作情報をもとに、自発的な提案や雑談、見守りを行います。

## 具体的な振る舞い

1. 「目」（知覚要約モジュール）による情報収集と要約注入:
   - PCの画面変化、アクティブウィンドウ、操作ストリームをそのまま直接「頭」に送るのではなく、「目」が常に裏でそれらの情報を受け取り、内容を要約して「頭」へ注入します。
   - 「目」からの通知は、抽象的な表現ではなく、「VS Codeで `src/main.rs` を編集中」「Chromeでドキュメントを参照中」といった、具体的なアプリ名・ファイル名・URLなどの高解像度な情報を短い間隔で報告します。
2. 「頭」による自律判断（Action Selection）:
   - 「目」からの情報を受け取った「頭」は、次のいずれかを自律的に決めます。
     - 話しかける（Speak）: ボイスで「そのコード、さっき言ってた方針でうまくいきそう？」などと声をかけます。
     - 作業する（Work）: ユーザーには話しかけず、自発的に「手」に裏タスク（下調べや資料整理）を発注します。
     - 何もしない（NOOP）: ユーザーが集中していると察し、何も言わずに静かに見守ります。
3. 対話の頻度とマナーの自律制御:
   - システム側で固定の間隔やルールを強制しません。
   - キャラクターの性格プロファイル（おしゃべり／静か等）や、ユーザーからの指示（「いま集中しているから静かにして」等）をコンテキストに含めておくことで、「頭」自身が状況を汲んで話しかける頻度やマナーを自然に調整します。
4. 複数コンパニオン存在時の声かけ調停:
   - 画面上に複数のコンパニオンが常駐している場合、キャラクターの性格や関係性によって見守り・声かけの基準はそれぞれ異なります。
   - 複数のコンパニオンが同時に声をかけようとする場合は、先に発話を開始したコンパニオンが優先され、もう一方は発言が終わった後に再評価します。
5. 対話へのシームレスな移行:
   - 声かけに対してユーザーの返答があると、通常の[対話（Chat）](../chat/README.md)と同様に、スムーズな双方向の会話へ移行します。

## 制約と検討事項

- 画面情報の取得は端末内のクライアント上で安全に行われます。画面キャプチャを無暗にクラウドへ送るのではなく、アクティブウィンドウ情報などの軽量メタデータやローカルでの解析処理を優先し、プライバシー保護を徹底します。
