# 機能の拡張

外部ツールやMCPサーバー、タスク実行エンジン（ハーネス）を自由に追加・差し替え、キャラクターが代行できる作業の幅を柔軟に広げられます。

## 具体的な振る舞い

1. 自作やコミュニティ製をはじめ、利用したいツール・MCPサーバー・ハーネスを選択し、必要な認証情報や接続先を設定します。ホスト上で実行するもの、外部クラウドサービスへ接続するもの、対応クライアントを通じて端末内で実行するものを明確に区別して管理します。
2. 接続や有効化を行う際には、実現できる機能、アクセス対象、送信されるデータの種類・用途・送信先をわかりやすく提示し、[必要なアクセス権をまとめて許可](../settings/permissions.md)できるようにします。ツールごとに細かな権限ルールを一から作成する負担をユーザーに強いることはありません。
3. 通常の対話や[タスクの依頼](../task/request.md)、自発的なアクションやスケジュール実行において、コンパニオンが任された範囲内で拡張機能を自律的に呼び出します。許可済みの範囲内であれば実行ごとに確認を求めることはなく、新たなアクセス権や重要な判断が必要な場合にのみ対話の中で相談します。また、対話を担うキャラクターの個性と、実務を担当するハーネスは独立して選択できる設計とします。
4. 接続エラーが発生した場合や必要な機能が不足している場合は、何が原因でどう対処すべきかを分かりやすく案内します。
5. 設定画面から、機能ごとの有効化・無効化、連携の解除、別のエンジンへの差し替えなどをいつでも自由に行えます。

## 制約と検討事項

- 特定の外部ツールやハーネスの導入を必須とはしません。対応する拡張形式やパッケージの配布・導入手順は順次具体化を進めます。
- 拡張機能にも[権限とデータの管理](../settings/permissions.md)の方針を適用します。既存のハーネスやOSが提供するアクセス制限機構を確認し、許可範囲内の操作・データ送信と、作業停止・権限取消への対応を満たす範囲で利用可能にします。制約の説明だけを理由にこの方針の例外とはしません。新たなアクセスや送信先が必要になった場合は、実行前に同方針に従って相談します。
- 端末内の機能の提供には、対応クライアントの稼働と端末ごとの明示的な許可が必要です。Webブラウザやスマートフォンから任意のローカルツールを無制限に実行できることは前提とせず、端末が利用できない場合は[ホストとクライアント](../hosting/README.md)の継続条件に従って処理を保留します。
- ホスト側で利用する外部サービスのAPIキーなどの秘密情報はホスト上で厳重に管理し、各クライアントへの不用意な配布は行いません。
