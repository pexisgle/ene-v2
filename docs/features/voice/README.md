# 音声対話

eneにおける主たる対話体験であり、クライアント端末のマイクを通じてキャラクターへ直接語りかけ、そのキャラクター固有の声による返答を耳で受け取ることができます。[ホスト](../hosting/README.md)側にマイクやスピーカーを用意する必要はなく、手元のクライアント端末だけで低遅延な音声対話が完結します。

## 具体的な振る舞い

1. **音声パイプラインとリアルタイムLive APIの選択肢**:
   - 従来の「STT（音声認識） ➔ キャラクターAgent ➔ TTS（音声合成）」によるパイプラインに加え、GPT-LiveやGemini Live APIといった**低遅延・リアルタイム双方向音声API**も選択可能です。
   - STT/TTSパイプラインを用いる場合でも、`Shizuku-Duplex` を参考にフル二重音声対話、自然な相槌、高速なレスポンスを追求します。
2. **音声入力のトリガー方式（VADとPush-to-Talk）**:
   - 発話を自動検出する**常時発話検出（VAD: Voice Activity Detection）**と、特定キーを押している間だけ聞き取る**プッシュ・トゥ・トーク（Push-to-Talk）**のいずれも自由に選択・切り替えが可能です。
3. **割り込み（バージイン / Barge-in）と相槌**:
   - キャラクターが発話している最中にユーザーが声を挟んだ場合、キャラクターの発話を即座に中断してユーザーの聞き取りへと自然に切り替わります（`Shizuku-Duplex` 方式）。
   - 単なる相槌（相づち）や短い反応に対して過剰に発話を停止させず、人間らしい会話のリズムを維持します。
4. **リップシンクと発話モーション**:
   - 音声の出力に合わせて、デスクトップ常駐のアバター（VRM等）がリアルタイムに**リップシンク（口パク）**および**発話モーション**（身振り、感情豊かな表情変化）を連動させます。
5. **複数コンパニオン存在時の応答調停とターン制掛け合い**:
   - コンパニオン同士は互いに他のコンパニオンが存在していることを認識しています。
   - **指名時の優先**: ユーザーが特定のコンパニオンの名前を呼んだ場合、呼ばれていない側のコンパニオンは発声せず、呼ばれた側のみが発言します。
   - **先着優先**: 複数のコンパニオンが同時に発声しようとした場合、先に発声を開始したコンパニオンが優先されます。
   - **発声完了後の再評価（掛け合い）**: 先に発声したコンパニオンが話し終えた際、発声できなかった側のコンパニオンは、**「先に発言したコンパニオンの発言内容」を踏まえて、自分も続けて発言すべきかを再評価**します。これにより、複数コンパニオン間の自然な会話のキャッチボールや相槌が生まれます。
6. 音声入力と読み上げは独立してオン・オフ可能であり、周囲の環境に応じてテキストによる対話へも柔軟に切り替えられます。

## 制約と検討事項

- 音声認識および音声合成の処理場所（端末ローカルかクラウドか）は、採用するエンジンとクライアントの環境に応じて個別に決定されます。
- クライアント端末のマイク・スピーカーのアクセス権限はOSの許可方針に従います。
