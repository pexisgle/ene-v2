# 音声対話

クライアント端末のマイクを通じてキャラクターへ直接語りかけ、そのキャラクター固有の声による返答を耳で受け取ることができます。[ホスト](../hosting/README.md)側にマイクやスピーカーを用意する必要はなく、手元のクライアント端末だけで音声対話が完結します。

## 具体的な振る舞い

1. 音声認識（STT）や音声合成（TTS）の接続先を指定し、[キャラクターに設定された声](../character/create.md)を割り当てます。音声データやテキストが端末から外部サービスへ送信される場合は、[データ送信範囲](../settings/permissions.md)をあらかじめ確認・許可します。
2. 音声入力を有効にすると、マイクに向かって話した言葉がリアルタイムにテキストへと変換され、AIへの入力として処理されて自然に対話が進みます。
3. 音声読み上げが有効な場合、設定された声でAIが滑らかに発話します。返答のテキストはチャット画面上にも同時に表示・記録されるため、後から文字として読み返すことも容易です。
4. **複数コンパニオン存在時の音声応答調停**:
   - 画面上に複数のコンパニオンが常駐している場合、ユーザーの発話に対して複数のコンパニオンが同時に喋り出すことはありません。
   - 各コンパニオンは、宛先や文脈を踏まえて発言するかどうかを判断し、思考しても発言しないことが可能です。複数のコンパニオンが発言しようとする場合の優先関係は、[ホストとクライアントの調停ルール](../hosting/README.md#複数コンパニオンの常駐と調停ルール)に従います。
5. 音声入力と音声読み上げは、クライアントごとにそれぞれ独立してオン・オフを切り替えられます。声を出せない静かな場所ではテキスト入力に切り替えるなど、周囲の環境に応じた柔軟な使い分けが可能です。

## 制約と検討事項

- 特定の音声エンジンや専用ハードウェアの利用を強制しません。利用可能な声のバリエーションや音声認識の精度は、選択したプロバイダやエンジンの仕様・性能に依存します。
- 音声認識および音声合成の処理場所（端末ローカルかクラウドか）は、採用するエンジンとクライアントの対応状況に応じて個別に決定されます。マイクへのアクセス権限は各OSの許可方針に従い、音声機能が無効な環境であってもテキストによる対話は問題なく継続できます。
- プッシュ・トゥ・トーク（ボタン押下中のみ認識）や常時発話検出（VAD）といった音声入力のトリガー方式、および発話中・聞き取り中の視覚的フィードバック表現については順次設計を進めます。

参考：[AIRI](../../references.md#airi) の音声入力連携と複数プロバイダ対応。
