# 音声対話

eneの中心となる対話体験で、クライアント端末のマイクを通じてキャラクターへ直接語りかけ、そのキャラクター固有の声による返答を耳で受け取ることができます。[ホスト](../hosting/README.md)側にマイクやスピーカーを用意する必要はなく、手元のクライアント端末だけで低遅延な音声対話が完結します。

## 具体的な振る舞い

1. 音声対話には従来の「STT（音声認識） ➔ キャラクターAgent ➔ TTS（音声合成）」によるパイプラインに加え、GPT-LiveやGemini Live APIといった低遅延・リアルタイム双方向音声APIも選べます。STT/TTSパイプラインを使う場合でも、`Shizuku-Duplex` を参考に、フル二重音声対話、自然な相槌、高速なレスポンスを追求します。
2. 音声入力の開始方法は発話を自動で検出する常時発話検出（VAD: Voice Activity Detection）と、特定のキーを押している間だけ聞き取るプッシュ・トゥ・トーク（Push-to-Talk）から選べます。どちらも自由に切り替えられます。
3. キャラクターが発話している最中にユーザーが声を挟む割り込み（バージイン／Barge-in）が起きた場合、キャラクターの発話を即座に中断して、ユーザーの聞き取りへ自然に切り替わります（`Shizuku-Duplex` 方式）。単なる相槌（相づち）や短い反応で過剰に発話を止めることはせず、人間らしい会話のリズムを維持します。
4. 音声の出力に合わせて、デスクトップ常駐のアバター（VRM等）がリアルタイムにリップシンク（口パク）と発話モーション（身振り、感情豊かな表情変化）を連動させます。
5. 複数のコンパニオンがいるときの応答調停と、ターン制の掛け合いは次のとおりです。
   - コンパニオン同士は、互いに他のコンパニオンが存在していることを認識しています。
   - 指名時の優先: ユーザーが特定のコンパニオンの名前を呼んだ場合、呼ばれていない側のコンパニオンは発声せず、呼ばれた側だけが発言します。
   - 先着優先: 複数のコンパニオンが同時に発声しようとした場合、先に発声を開始したコンパニオンが優先されます。
   - 発声完了後の再評価（掛け合い）: 先に発声したコンパニオンが話し終えたとき、発声できなかった側のコンパニオンは、先に発言したコンパニオンの発言内容を踏まえて、自分も続けて発言すべきかを再評価します。これにより、複数のコンパニオン間で自然な会話のキャッチボールや相槌が生まれます。
6. 音声入力と読み上げは独立してオン・オフでき、周囲の環境に応じてテキストによる対話へも柔軟に切り替えられます。

## 制約と検討事項

- 音声認識と音声合成の処理場所（端末ローカルかクラウドか）は、採用するエンジンとクライアントの環境に応じて個別に決まります。
- クライアント端末のマイク・スピーカーのアクセス権限はOSの許可方針に従います。
