# Chat

テキストでのやりとりもできますが、中心になるのはキャラクターとの会話です。テキスト会話とキャラクター会話は別々の機能ではなく、ひとつの対話体験として統合されています。

対話の根幹には、キャラクターの頭脳となるAIエージェント（コンパニオンAgent）がいます。ユーザーがAgentの内部状態やAgentそのものを直接意識したり操作したりすることはありません。入力されたチャットや音声がAgentのコンテキストに追加され、Agentが「ユーザーの入力に何を言うか」を判断して送信します。ユーザーに対するすべての窓口は、このキャラクターAgentが一貫して担います。

## 具体的な振る舞い

1. 作成または取り込んだキャラクターを選んで対話を始められます。
   - テキスト入力と音声入力（[ボイス対話](../voice/README.md)）のどちらにも対応し、設定した口調・語尾・感情・関係性を反映した自然な返答が返ってきます。テキストでの会話とキャラクターとの会話は分けず、一体のものとして扱います。
   - ユーザーの入力（テキスト・ボイス）は裏側のキャラクターAgentにコンテキストとして追加され、Agentがキャラクターとしての発言を決めて生成します。
   - このキャラクターAgentは、実務や調査を担う「手」（[タスク用エージェント](../task/request.md)）とは完全に独立していて、ユーザーとの対話・判断・窓口に専念します。
2. ユーザーはGrokBotのように複数のコンパニオンを作成して保持し、運用できます。
   - 会話履歴や文脈はコンパニオンごとに管理されます。複数のコンパニオン間の情報連携は[記憶機能](../memory/README.md)の共有プールを通じて行われます。
3. 直近の会話ログ（セッションログ）と[長期記憶](../memory/README.md)は、独立した仕組みです。
   - すべての会話ログを永久に保存し続けることは前提とせず、過去の生ログが破棄された後でも、抽出・保存された記憶をもとに対話を続けられます。
4. キャラクターAgentのコンテキストの肥大化を防ぐCompaction（自動要約・圧縮）は、ユーザーとの対話が途切れてしばらくたったアイドル時（60秒以上無操作）に自動で実行されます。
   - 会話からのエピソード記憶の固定・整理（Consolidation）は、Compactionとは独立したライフサイクルで動作し、ターン終了時やアイドル時に増分カーソルに基づいて自律的に実行されます。
5. Compactionの処理中にユーザーが発言や入力を行った場合でも、ユーザーを待たせることはありません。
   - Compactionを始める前の分岐（直前のコンテキスト状態）からAgentがそのまま続けて即座に応答します。
6. 日常の雑談や相談に加え、[実務タスクの進行や相談](../task/request.md)、[自発的な声かけ](../autonomy/watch-over.md)、外部ツールの実行結果まで、ユーザーに対するすべての窓口はこのキャラクターAgentが一貫して担います。

参考：[Grok Bot](../../references.md#grok-bot) の複数コンパニオン管理、および [AIRI](../../references.md#airi) のキャラクター対話体験。
