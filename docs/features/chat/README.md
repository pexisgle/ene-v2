# Chat

テキストによるやりとりも行いますが、メインはキャラクターとの会話です。これらは分離した別々の機能ではなく、同一の対話体験として統合されています。

対話の根幹には、頭脳となるメインキャラクター用のAIエージェント（コンパニオンAgent）が存在します。ユーザーがその内部状態やAgent自体を直接意識・操作することはなく、入力されたチャットや音声がAgentのコンテキストへ追加され、「ユーザーの入力に何を言うか」を判断して送信します。このキャラクターAgentが、ユーザーに対するすべての窓口（フロント）を一貫して担当します。

## 具体的な振る舞い

1. **キャラクターとの統合対話体験**:
   - 作成または取り込んだキャラクターを選択して対話を開始します。
   - テキスト入力および音声入力（[ボイス対話](../voice/README.md)）の両方に対応し、設定された口調・語尾・感情・関係性を反映した自然な返答が得られます。テキスト会話とキャラクター対話は分離せず、一体のものとして扱われます。
   - ユーザーからの入力（テキスト・ボイス）は裏側のキャラクターAgentへコンテキストとして追加され、キャラクターとしての発言を決定・生成します。
   - このキャラクターAgentは、実務や調査を担う「手」（[タスク用エージェント](../task/request.md)）とは完全に独立しており、ユーザーとの対話・判断・窓口に専念します。

2. **複数コンパニオンの運用**:
   - ユーザーはGrokBotのように複数のコンパニオンを作成・保持できます。
   - 会話履歴や文脈はコンパニオンごとに個別に管理されます。複数コンパニオン間の情報連携は[記憶機能](../memory/README.md)の共有プールを通じて行われます。

3. **会話ログと記憶の分離**:
   - 直近の会話ログ（セッションログ）と[長期記憶](../memory/README.md)は独立した仕組みです。
   - 会話ログをすべて永久に保存し続けることを前提とはせず、過去の生ログが破棄された後であっても、抽出・保存された記憶をもとに対話を継続できます。

4. **アイドル時Compaction（自動要約・圧縮）と記憶の増分整理**:
   - キャラクターAgentのコンテキスト肥大化を防ぐCompactionは、ユーザーからの対話が途切れてしばらく経過した**アイドル時（60秒以上無操作）に自動で実行**されます。
   - 会話からのエピソード記憶の固定・整理（Consolidation）は、Compactionとは独立したライフサイクルで動作し、ターン終了時やアイドル時に増分カーソルに基づいて自律的に実行されます。

5. **割り込み耐性と分岐継続**:
   - Compaction処理中にユーザーからのアクション（発言や入力）が発生した場合、ユーザーを待たせることはありません。
   - **Compaction開始前の分岐（直前のコンテキスト状態）からAgentがそのまま継続**して即座に応答します。

6. **ユーザー窓口の一元性**:
   - 日常の雑談や相談はもちろん、[実務タスクの進行や相談](../task/request.md)、[自発的な声かけ](../autonomy/watch-over.md)、外部ツールの実行結果に至るまで、ユーザーに対するすべての窓口はこのキャラクターAgentが一貫して担います。

参考：[Grok Bot](../../references.md#grok-bot) の複数コンパニオン管理、および [AIRI](../../references.md#airi) のキャラクター対話体験。
