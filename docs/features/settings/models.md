# AIの選択・接続

用途や好みに合わせて、会話や実務に利用するAIプロバイダおよびモデルを自由に選択・設定できます。

## 具体的な振る舞い

1. 利用したいクラウドAIサービスやローカルLLM環境を選択し、APIキーなどの認証・接続情報を登録します。設定情報は[接続中のホスト](../hosting/README.md)側で一元管理され、ホストからアクセス可能な接続先を指定します（手元のPC上で稼働するローカルモデルを別マシンのホストから利用する場合は、ネットワーク経路の確保が必要です）。
2. 指定したプロバイダで利用可能なモデル一覧から、実際に使用するモデルを選択します。設定時には、対話文脈や参照資料、記憶データなど、処理のために送信されるデータの種別と用途を分かりやすく提示します。許可された範囲内での通常利用において毎回確認ダイアログを表示することはなく、未許可の外部サービスへ勝手にデータが送られることもありません。現在の接続状態や利用モデルは、いつでも画面上で確認・変更できます。
3. 選択したモデルを用いて対話やタスクを実行します。万が一APIのエラーや通信障害が発生した場合は、その原因を明快に案内し、設定の見直しや代替モデルへの切り替えをスムーズにサポートします。
4. 日常の対話を担うコンパニオン用と、専門的な調査や実務を担うエージェント用とで異なるモデルを割り当てるなど、用途やコスト、処理速度に応じた柔軟な使い分けが可能です。

## 制約と検討事項

- プラットフォームが公式に対応している接続先を標準とし、未検証のモデルを含むすべての環境での完全な動作を保証するものではありません。新たなプロバイダや推論エンジンの追加・差し替えは[機能の拡張](../extensions/README.md)を通じて行います。
- ホスト側で使用するAPIキーなどの秘密情報はホスト上で安全に保持され、各クライアントへ不必要に共有されることはありません。
- ローカルモデルの手軽なセットアップ手順や、タスクの種類に応じた動的なモデル自動選択ルールについては順次検討を進めます。既存ツールの過度に複雑な設定体系を踏襲せず、誰でも直感的に扱える分かりやすさを最優先とします。

参考：[OpenClaw](../../references.md#openclaw) のキー管理・接続確認UI、および [OpenCode](../../references.md#opencode) の用途別モデル選択の考え方。
