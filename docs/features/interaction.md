# 対話・音声・キャラクター

この文書では [用語集](../terms.md) の定義に沿って、対話や音声のやり取り、キャラクターの作成と表示に関する機能仕様をまとめます。
クライアント画面に置く要素は文字入出力、設定、操作の許可を求める承認カードに限り、進捗パネルや作業一覧、記憶一覧の専用画面は設けません。
作業の進捗や相談、記憶の確認といったやり取りもすべてコンパニオンとのテキストと音声の対話を通じて行います。

## テキストと音声の対話

テキスト入力と音声対話は 1 つの対話体験としてつながっており、将来的には音声対話を利用の中心に据えます。
将来的には [Shizuku-Duplex](../references.md#shizuku-duplex) のように、自然な相槌や発話中の割り込み、裏で思考や作業を進めながらの即時応答を低遅延でこなす掛け合いを理想の基準として目指します。
返答の生成と裏側の作業処理を分けて動かすことで、長い調査やツール実行の途中でも会話を止めずにやり取りを続けることができます。
当面はターン制の音声対話を基本としながら将来の全二重に近い機能拡張にも対応できる余地を残し、リアルタイムの双方向音声 API は現時点の対象から外します。
音声入力は発話の自動検出とボタンを押している間だけ聞き取る方式を切り替えることができ、入力と読み上げはそれぞれ独立してオン・オフできます。
コンパニオンの発話中に利用者が話しかけると、発話を中断して聞き取りへ切り替わります。
音声の出力に合わせてキャラクターの口パクや発話モーションが連動し、周囲の環境に応じてテキスト入力へ切り替えることもできます。
複数のコンパニオンを同時に稼働させて画面へ並べることもでき、それぞれが自分の会話履歴と文脈を保ったまま、名前呼びや話題に応じて会話に加わります。

## キャラクターの作成と配布

キャラクターは「姿」「声」「心」の 3 つの要素を組み合わせて作成します。
「姿」には VRM などの 3D モデルや Live2D モデルを割り当て、初期段階では VRM を優先して Live2D には順次対応します。
「声」には音声合成エンジンの接続設定や声のプリセットを複数登録でき、利用環境や API の料金などに応じて選択できます。
「心」の初期の人格設定では名前、口調、価値観、背景、短い会話例などを決め、初対面や作業失敗時の応答をプレビューで確認できます。
作成したキャラクターは「姿」「声」「心」をひとまとめにしたパッケージとしても、各要素の単体パッケージとしても書き出しや取り込みができます。
配布するパッケージには初期設定だけを含め、API キーなどの秘密情報や、日々の対話で育った記憶・会話履歴・心の状態は含めません。
登録したキャラクターはホストで一元管理し、同じキャラクター設定から複数のコンパニオンを作成して運用できます。

## クライアントでの表示と常駐

キャラクターの設定はホスト側で管理し、実際の描画は接続している各クライアントが受け持ちます。
デスクトップでの常駐表示は [Desktop Mate](../references.md#desktop-mate) のように、ウィンドウの縁に腰掛けて移動に追従したり、クリックや頭を撫でる操作、マウスポインタの動きに反応したりする体験を基準とします。
画面の最前面でまばたきや呼吸といった待機モーションを表示し、表示サイズの調整や作業の邪魔にならない画面端への一時退避にも対応します。
ドラッグ操作で画面上の好きな位置へ移動でき、キャラクター以外の透明な領域はクリックが背後へ抜けるため普段の作業を妨げません。
Desktop Mate が備える表示や反応に加えて、利用者が登録した任意のキャラクターをそのまま常駐させ、会話や作業の窓口として直接やり取りできます。
アクティブウィンドウの切り替えや、聞き取り中・思考中・作業の報告といった会話や作業の状況に合わせて、表情、仕草、視線、声のリアクションも低遅延で変化させます。
Web ブラウザやスマートフォンではそれぞれの画面構成に合わせて表示し、表示位置や音声のオン・オフといった設定はクライアントごとに保持します。
