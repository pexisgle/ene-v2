# 記憶機能

日々の対話で知った好みや一緒に過ごした思い出、協働を通じて得た知見や手順を記憶し、以後の対話や実務に活かします。記憶システムと[感情システム](../character/mind.md)が連携することで、人間らしい一貫した振る舞いを実現します。

記憶はコンパニオンごとに[ホスト](../hosting/README.md)側で永続化されます。同一ホストへの再接続、利用端末の切り替え、[利用モデルの変更](../settings/models.md)を行っても、培われた記憶が失われることはありません。

## 記憶の種類と構造

eneの記憶システムは、実務手順を扱う「スキル記憶」、好みや思い出を扱う「エピソード記憶」、全コンパニオン共通の「共有記憶プール」で構成されます。

### 1. スキル記憶（HermesAgent方式）
実務タスクの遂行や協働を通じて得られた手順・ノウハウは、HermesAgentの仕組みを踏襲して管理されます。
- 構造化されたスキル形式（`SKILL.md`）:
  - 作業の成功時や対話での指示を通じ、LLMが手順・利用ツール・注意点をまとめたプレイブック（スキル）として自律的に書き出します（Closed Learning Loop）。
- プログレッシブ・ディスクロージャー（「手」への段階的読み込み）:
  - 親エージェント（頭）の会話プロンプトにはスキル一覧を一切入れず、会話のトークン消費を抑えます。
  - 実務作業を行うエージェント「手」のタスク開始時にコンパクトなスキル一覧（名前と1行概要）を渡し、必要と判断した際に詳細手順をオンデマンド取得して実行します。

### 2. 好み・思い出・関係性（エピソード記憶）
同じキャラクターとして破綻せず自然に振る舞うために必要な記憶と関係性を蓄積します。
- LLM主導の柔軟な抽出:
  - システム側から保存項目や固定スキーマを強制せず、キャラクターとして自然であるために何が必要かをLLM自身が判断して抽出します。
- 保存メタデータと関係性:
  - 出来事の要約（事実）に加え、重要度（Importance: 0〜10）、発生日時（`occurred_at`）、最終アクセス日時（`last_accessed_at`）、当時の感情タグ（`emotion`）、ベクトル埋め込み（`embedding`）を保持します。
  - 記憶同士のつながりや由来を関係性グラフ（`memory_edges`）として管理し、文脈を辿れるようにします。
- 常時注入記憶（Pinned / Core Memory）:
  - 検索に頼らず常にコンテキストへ置いておくべき高重要度の基本事実（ユーザーの呼称、譲れない前提、基本プロファイル）は、プロンプトの動的文脈枠に一時注入します。

### 3. 共有記憶プール
複数のコンパニオンが共通して把握しておくべきユーザーの基本属性や共通事項は、共有記憶プールに保持されます。特別な別システムは設けず、通常の記憶と同じ仕組み・同じ検索機構のまま保存スコープ（個人／共有）だけを分けて管理します。

## 具体的な振る舞い

### 1. Compaction連動の記憶形成・整理（Consolidation）
- 記憶の抽出・統合・重複整理は、[Compaction](../chat/README.md)のタイミングに合わせて会話ログを振り返りながら一括で実行します。
- 対話から重要な出来事や好みを抽出し、重要度と関係性を評価して永続化します。

### 2. ベクトル検索と時間減衰を伴う想起
記憶の想起では、FTS5による全文検索とベクトル埋め込みの類似度検索を組み合わせ、Relevance（関連度）・Importance（重要度）・Recency（直近性）の3要素でスコアリングします。
- 時間減衰（忘却）:
  - 些細な日常会話（低重要度）は時間経過とともにスコアが下がり、日常会話で自然に持ち出されなくなります。
  - 深い感情を伴う出来事や約束（高重要度）は高い基礎スコアを保ち、忘れにくくなります。
  - 昔の些細な記憶でも、ユーザーが直接話題にした場合はRelevanceが高くなり、遡って想起できます。
- 引用ガード（`cited_in` / `estimated_cited_in`）による最終アクセス日時の更新:
  - 検索候補に引っかかっただけでは `last_accessed_at` を更新しません。
  - プロンプト注入実績と照合し、LLMが発話や行動で実際に参照・利用したと判定された場合のみ `last_accessed_at` を更新することで、無関係な記憶が勝手に優先度を上げ続ける自己汚染を防ぎます。

### 3. 多様な想起トリガー
記憶の想起は、ユーザーからの入力時だけでなく、[「目」を通じた自発的な声かけ](../autonomy/watch-over.md)や[スケジュール実行](../autonomy/schedule.md)の発火時にも行われます。

### 4. 確認・訂正・忘却（対話での完結）
- 人間が管理するための記憶一覧UIは設けず、記憶の確認・訂正・忘却はキャラクターとの自然な対話の中で完結させます。
- ユーザーが「忘れて」と指示した場合、該当する記憶の想起優先度（重要度）を下げて、日常の対話で思い出しにくくします。

## 制約と関連機能

- [キャラクターの配布パッケージ](../character/create.md)には、ユーザー固有の個人的な記憶、会話履歴、交流を通じて育まれた関係性の変化は含まれません。
