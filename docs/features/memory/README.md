# 記憶機能

日々の対話で知った好みや一緒に過ごした思い出、協働を通じて得た知見や手順を記憶し、以後の対話や実務に活かします。毎回一から説明し直す必要がなく、ひとりのパートナーとして関係性と作業の文脈を自然に引き継ぐことができます。

記憶はコンパニオンごとに[ホスト](../hosting/README.md)側で永続化されます。同一ホストへの再接続、利用端末の切り替え、[利用モデルの変更](../settings/models.md)を行っても、培われた記憶が失われることはありません。

---

## 記憶の種類と構造

eneの記憶システムは、実務手順を扱う**「スキル記憶」**、好みや思い出を扱う**「エピソード記憶」**、全コンパニオン共通の**「共有記憶プール」**から構成されます。

### 1. スキル記憶（HermesAgent方式）
実務タスクの遂行や協働を通じて得られた手順・ノウハウは、HermesAgentの仕組みを踏襲して管理されます。
- **構造化されたスキル形式（`SKILL.md`）**:
  - 作業の成功時や対話での指示を通じ、LLMが手順・利用ツール・注意点をまとめたプレイブック（スキル）として自律的に書き出します（Closed Learning Loop）。
- **プログレッシブ・ディスクロージャー（段階的読み込み）**:
  - 全スキルの詳細を常時プロンプトに載せるのではなく、セッション開始時には**コンパクトなスキル一覧（名前と1行概要のインデックス）**のみを注入します。
  - キャラクターAgentが必要と判断した際、またはユーザーが特定の作業を指示した際に、該当するスキルの詳細手順をオンデマンドでコンテキストへ引き込みます。

### 2. 好み・思い出（エピソード記憶）
どのようなときに対話しても同じキャラクターとして破綻せず、実在する存在として自然に振る舞うために必要な記憶を蓄積します。
- **LLM主導の柔軟な抽出**:
  - システム側から保存項目や固定スキーマを強制することはしません。キャラクターとして自然であるために何が必要かをLLM自身が判断して抽出します。
- **保存メタデータ**:
  - 出来事の要約（事実）に加え、**重要度（Importance: 1〜10）**、**発生日時（occurred_at）**、**最終アクセス日時（last_accessed_at）**、**その時のキャラクター自身の受け止め・感情（emotion）**をワンセットで保持します。
- **常時注入記憶（Pinned / Core Memory）**:
  - ベクトル類似度検索に依存せず、常にコンテキストに存在すべき高重要度の基本事実（ユーザーの呼称、譲れない前提、基本プロファイル）は、プロンプトの固定枠へ常時注入されます。

### 3. 共有記憶プール
複数コンパニオンが存在する環境において、全コンパニオンが共通して把握すべきユーザーの基本属性（名前、共通の好み、全社・共通ルールなど）は**共有記憶プール**に保持され、すべてのコンパニオンが自然に参照できます。

## 具体的な振る舞い

### 1. 自然な記憶形成と整理（増分Consolidation）
- 記憶の抽出・整理（Consolidation）は、ターン完了時または対話が途切れたアイドル時に、Compaction（会話ログ要約）とは独立したライフサイクルで自律実行されます。
- 増分カーソル（`processed_turns_cursor`）により未処理ターンのみを走査し、対話ログから重要な出来事や好みを抽出して、LLMが重要度（日常の些細な雑談は1〜3、継続的な趣味・仕事は4〜6、重大な出来事や約束は7〜10）を評価してSQLiteへ保存します。重複抽出や過去ログの二重処理は発生しません。

### 2. 想起と時間減衰（忘却メカニズム）
記憶の想起は、**Relevance（関連度）**、**Importance（重要度）**、**Recency（直近性）**の3要素をスコアリングして行われます。
- **時間減衰（忘却）**:
  - 些細な日常会話（低重要度）は、時間経過とともに直近性スコアが低下し、日常会話で自然に持ち出されなくなります（自然な忘却）。
  - 深い感情を伴う出来事や約束（高重要度）は、時間が経過しても高い基礎スコアを維持するため忘れにくくなります。
  - 昔の些細な記憶であっても、ユーザーが直接その話題を尋ねた場合はRelevanceが高くなるため、記憶の底から遡って想起できます。
- **最終アクセス日時の更新ガード（汚染ループの防止）**:
  - 類似度検索で「候補として引っかかっただけ」ではアクセス日時は更新されません。
  - **実際にLLMが発話や行動でその記憶を有意義に参照・利用したと判定された場合のみ** `last_accessed_at` を更新し、無関係な記憶が勝手に優先度を上げ続ける悪循環を防ぎます。

### 3. 多様な想起トリガー
記憶の想起はユーザーからの入力時だけに限定されません。
- ユーザーからのボイスやチャット入力時。
- [自発的な声かけ](../autonomy/watch-over.md)（見守り・雑談）の判断時。
- [スケジュール・タイマー](../autonomy/schedule.md)の発火時。
- 作業監視による環境変化の検知時。

### 4. 確認・訂正・忘却（対話での完結）
- 記憶が膨大になることや日常的なユーザー体験を考慮し、**人間が管理するための記憶一覧UIは設けません**。
- 記憶の確認・訂正・忘却は、すべて**キャラクターAIとユーザーとの自然な対話の中だけで完結**します。
- ユーザーが「忘れて」と指示した場合、該当する記憶の想起優先度（重み）を最小化し、日常の対話やタスクで思い出しにくくします。

## 制約と関連機能

- [キャラクターの配布パッケージ](../character/create.md)には、ユーザー固有の個人的な記憶、会話履歴、交流を通じて育まれた性格・関係性の変化は一切含まれません。
- 長期的な信頼関係や作業の継続性は「記憶」が担い、直近の[会話履歴](../chat/README.md)のログ管理とは明確に区別して扱われます。
- 記憶の永続化ストレージは特定のDBに固定せず、高機能なベクトルDB等への差し替えが可能な抽象レイヤーとして設計します。

参考：[Hermes Agent](../../references.md#hermes-agent) のスキル学習、[Generative Agents](../../references.md#generative-agents) の重要度・時間減衰想起モデル、[Mem0](../../references.md#mem0) のエージェント記憶ライフサイクル。
