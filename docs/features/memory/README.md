# 記憶機能

日々の対話で知った好みや一緒に過ごした思い出、協働を通じて得た知見や手順を記憶し、以後の対話や実務に活かします。毎回一から説明し直す必要がなく、ひとりのパートナーとして関係性と作業の文脈を自然に引き継ぐことができます。

記憶はコンパニオンごとに[ホスト](../hosting/README.md)側で永続化されます。同一ホストへの再接続、利用端末の切り替え、[利用モデルの変更](../settings/models.md)を行っても、培われた記憶が失われることはありません。

## 扱う記憶と隔離構造

各コンパニオンが持つ基本的な記憶（対話履歴、思い出、固有の好みなど）は、**コンパニオンごとに個別に保持**されます。他のコンパニオンへ伝える情報や相手は、会話の文脈、情報の性質、ユーザーの意向を踏まえてコンパニオンが適切に判断します。

一方で、これら個別記憶とは独立して**「共有記憶プール」**が存在します。全コンパニオンが共通して把握すべきと判断されたユーザーの基本属性（名前や共通の好みなど）は、この共有記憶プールを通じて連携されます。共有のたびにユーザーの明示的な指示を求めることはありません。

| 記憶の分類 | 管理スコープ | 具体例 | 活用方法 |
| --- | --- | --- | --- |
| ユーザーに関する基本情報 | 共有記憶プール | 共通の呼び名、基本属性、全社・共通ルール | すべてのコンパニオンによる共通認識・対応 |
| ユーザー固有の嗜好・こだわり | コンパニオン個別 | 特定コンパニオンに伝えた好み、成果物の形式 | 相手に最適化された対話、提案、成果物の作成 |
| 共に経験した思い出 | コンパニオン個別 | 出会った日、一緒に悩んだテーマ、達成の喜び | 共有体験を踏まえた情緒的な対話と関係性の深化 |
| 進行中タスクの文脈 | コンパニオン個別 | 依頼目的、決定事項、残課題、関連ファイルの所在 | 中断した作業の再開や、次回以降の依頼への引き継ぎ |
| 習得した作業手順（スキル） | コンパニオン個別／共有 | 成功した進行パターン、過去の失敗から得た注意点 | 現在の実行環境に適した作業手順のスマートな再利用 |

長期的な信頼関係や作業の継続性は「記憶」が担い、直近の[会話履歴](../chat/basic.md)のログ管理とは明確に区別して扱います。

## 具体的な振る舞い

### 自然に覚える・思い出す

1. 対話のやりとりや作業の成果から、ユーザーの好み、重要な出来事、合意事項、有用な手順を自動的に抽出して記憶します。「これを覚えておいて」と指示して明示的に記憶させることも可能です。
2. 記憶の保存時には、いつ・どのような文脈（対話や作業）から得られた情報であるかというメタデータを併せて保持します。
3. 現在の話題との親和性、重要度、新しさに応じて、必要な記憶を適切なタイミングで自律的に想起します。
4. 時間が経過した古い記憶は、日常会話で自発的に持ち出す優先度が自然と下がりますが、経過時間のみを理由に消去されることはありません。例えば「以前一緒に話したこと」について尋ねられた場合は、古い記憶や参照可能な履歴を遡って想起します。
5. 好みや状況が変化した場合は、最新の情報を以後の対話や作業へ優先的に反映します。「過去の事実」と「現在の事実」を適切に区別し、該当する記憶が見つからない場合に不誠実な知ったかぶり（ハルシネーション）をすることはありません。

### 関係性と仕事に活かす

1. 個別の思い出は、その体験を共にした特定のコンパニオンとの関係性に深く結びつきます。共有記憶プールから知った情報については「知っている客観的事実」として扱い、自分自身が直接体験したかのような不自然な語り方はしません。
2. 蓄積された記憶は、[感情システム](../character/mind.md)のパラメータ更新や[キャラクターの成長](../character/grow.md)の判断材料となります。
3. 実務タスクの遂行を通じて得られたノウハウや手順をスキルとして蓄積し、現在の指示内容、動作環境、利用可能なツールに合わせて賢く再利用します。

### 確認・訂正・忘却（明示的な削除は非実装）

1. **記憶の確認**: 記憶内容の確認は、主に対話の中で自然に行われます。開発者向けに記憶一覧の閲覧UIも提供しますが、日常の操作でそれを前提とすることはありません。
2. **訂正と忘却の仕組み**: 本ソフトウェアには**明示的な記憶の削除（データベースからの消去ボタン等）は存在しません**。
   - **訂正**: 対話の中で新たな事実を伝えると、最新の記憶として高い優先度で更新され、古い情報との時系列的な関連づけが保持されます。
   - **忘却**: ユーザーが「忘れて」と指示した場合、該当する記憶の想起優先度（重み）を最小化し、日常の対話やタスクで思い出しにくくします。記憶は残り、文脈やきっかけによって再び思い出すこともあります。

### 共有記憶プールとコンパニオン間の共有

1. コンパニオンは、会話の文脈、情報の性質、ユーザーの意向を踏まえ、共有の要否、内容、相手を自律的に判断します。全コンパニオンで共有すべき基本情報は共有記憶プールに保持され、すべてのコンパニオンが参照できます。
2. 特定の相手に伝えることが適切な情報は、そのコンパニオンへ共有します。ユーザーが共有先や共有しない情報を指示した場合も、その意向を判断に反映します。共有を受け取ったコンパニオンは、情報そのものに加えて、共有された経緯や文脈を理解して活用します。

## 制約と関連機能

- [キャラクターの配布パッケージ](../character/create.md)には、ユーザー固有の個人的な記憶、会話履歴、交流を通じて育まれた性格・関係性の変化は一切含まれません。配布される初期プロファイルと、ユーザーとの間で個別に培われた関係状態は厳格に分離されます。
- 記憶が保存されている場合であっても、あらゆる問いかけに対して常に完璧な想起ができることを保証するものではありません。元ログが破棄された後でも記憶データは利用可能ですが、記憶として抽出されなかった細部ログを復元できるわけではありません。

## 想定シナリオ

以下は記憶機能の振る舞いを確認するための想定場面です。

| シナリオ | 期待される振る舞い |
| --- | --- |
| 雑談で好みを伝え、後日訂正する | 次回以降の提案に反映され、訂正後は最新の内容が優先される |
| 過去の思い出を尋ねる | 普段は過度に持ち出さないが、尋ねられた際には古い記憶を遡って自然に応答する |
| 元の会話ログが残っていない過去の出来事を尋ねる | 保存されている長期記憶をもとに応答しつつ、詳細なログがない場合は「少し前のことだから曖昧かもしれないけれど」といった自然なニュアンスを交える |
| 別のコンパニオンと対話する | 適切と判断されて共有された情報を活用し、共有されていない話題を知っているように語ったり、他者の体験を自身の体験として語ったりしない |
| PCからスマートフォンへ端末を変え、利用モデルも変更する | 同一ホスト上の同一コンパニオンとして、これまでの記憶や作業文脈がそのまま引き継がれる |
| 忘れるよう依頼する | 記憶は残るが、想起優先度が最小化され、日常の対話やタスクでは思い出しにくくなる |
| 過去と類似した実務タスクを依頼する | 過去に学習した手順や注意点を活かしつつ、現在の権限・環境・ツール状況を再確認して実行する |
| キャラクターをファイルとして書き出す | 配布パッケージに個人的な記憶や交流による変化が含まれず、初期状態のみが出力される |
