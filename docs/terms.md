# 用語集

ene のドキュメント全体で共通して使う用語をまとめます。
仕様と設計の間で言葉の意味がずれないよう、基本的な概念と重要な単位をここで定義します。

## キャラクターとコンパニオン

### キャラクター

キャラクターは、利用者が向き合う存在の設計や配布の単位です。
「姿」「声」「心」の3つの要素から成り、1つのパッケージとして管理や配布ができます。

| 要素 | 説明 |
| --- | --- |
| 姿 | 画面に映す見た目データです。VRM などの 3D モデルや Live2D モデルを指します。 |
| 声 | 発話に使う声の設定です。音声合成エンジンの接続設定や声のプリセットを指します。 |
| 心 | 作者が決める初期の人格設定と、対話を通じて育つ記憶や感情のまとまりです。 |

「心」のうち配布できる初期の人格設定と、日々の対話で育つ記憶や感情は分けて管理します。

### コンパニオン

コンパニオンはキャラクターの設定をもとにホスト上で動く対話の実体です。
利用者との会話履歴と、個別の記憶や心の状態を持ちます。
同じキャラクターから複数のコンパニオンを作成して同時に動かすこともでき、それぞれがテキストと音声の窓口になります。

## 実行の仕組みと拡張

### ホスト

ホストはコンパニオンを常時動かす実行基盤です。
会話履歴や記憶の保存、作業の実行、スケジュール管理、外部の AI やツールとの接続を受け持ちます。
手元の PC の裏側でも、VPS や自宅サーバーのように画面のない環境でも動き、クライアントを閉じても止まりません。

### クライアント

クライアントはホストにつないで対話やキャラクターの表示を行うアプリです。
デスクトップ、Web、スマートフォンから接続でき、画面操作やファイル操作などその端末ならではの操作も仲介します。
専用の進捗パネルや報告一覧画面は前提にせず、作業の進捗や相談もテキストと音声の対話でやり取りします。

### 端末能力

端末能力は、クライアントが「この端末でできる操作」としてホストへ伝える機能の一覧です。
画面操作、ファイル操作、モーション再生などを含み、コードでは `capability` と呼びます。

### プロバイダー

プロバイダーはLLM、音声合成、音声認識、埋め込み、MCP、ACP、検索など、外部のサービスやエンジンへつなぐ設定の単位です。
用途に合わせて複数のプロバイダーを登録して使い分けることができ、コードでは `Connection` として扱います。

### プラグイン

プラグインはプロバイダーのアダプターや外部の作業エージェント、ツールなどをあとから追加・差し替えできる拡張モジュールです。

## システム内部の 4 つの役割

システムの内側では「頭」「手」「目」「体」の 4 つの役割に分けて動かします。

| 役割 | 動く場所 | 受け持つ仕事 |
| --- | --- | --- |
| 頭 | ホスト | コンパニオン本人として会話と判断を動かし、「心」をもとに返答を作る中核の仕組みです。 |
| 手 | ホスト・外部連携 | 頭からの指示を受けて、調査、ファイル操作、外部ツールの実行などを裏で進める作業役です。 |
| 目 | クライアント・ホスト | 画面や操作、時間の変化を見張り、必要な変化だけを頭へ知らせる知覚の仕組みです。 |
| 体 | クライアント | キャラクターの「姿」を描画し、表情、仕草、口パク、音声の再生を受け持つ仕組みです。 |

キャラクターの「姿」や「心」がデータや状態を指すのに対し、「体」や「頭」はそれらを動かす仕組みの役割を指します。
内部で「手」が作業を分担しても、利用者への報告や相談は「頭」がコンパニオン自身の発話として伝えます。

## 記憶と作業で区別する単位

設計文書やコードの中で混同しやすい記憶と作業の単位は、次の名前で区別します。

| 用語 | コード上の名前 | 説明 |
| --- | --- | --- |
| 人格設定 | `Companion` / `Profile` | 作者が決める口調、価値観、背景、会話例などの静的な設定です。配布でき、日々の会話だけでは書き換わりません。 |
| 記憶 | `MemoryRecord` | 対話や作業の出来事から抽出し、いつどこから得たかの由来とあわせて残す長期の記録です。生の会話ログとは分けて管理します。 |
| 心の状態 | `State` | 今の感情、関係性、関心など、対話を通じて変化する動的な状態です。発話ごとに出す一時的な表情の指示とは別です。 |
| 記憶の整理 | `consolidate` | たまった会話や未処理の出来事から記憶を抽出し、心の状態を更新する裏側の処理です。 |
| 会話の圧縮 | `compaction` | 長くなった会話履歴を要約して畳み、文脈の長さを収める処理です。 |
| 作業セッション | `WorkSession` | コンパニオンが「手」に任せた 1 つの仕事の流れを保持する枠です。途中の追加指示でも同じ文脈を引き継ぎます。 |
| 実行ターン | `Run` | 作業セッションの中で、1 回の指示から完了・中断・失敗までを区切る 1 回分の実行です。 |

各機能や設計の詳細を知りたいときは、[ドキュメント一覧](README.md)から目的に合う文書を開いてください。
