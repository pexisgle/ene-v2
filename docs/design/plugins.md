# プラグイン拡張の設計

この文書では [用語集](../terms.md) と [全体アーキテクチャ](../architecture.md) を前提に、機能追加の原則・拡張領域の役割・`プロバイダー` の接続仲介・ライフサイクルフックの整合性・隔離とプライバシー保護の設計境界をまとめます。
実装変更に左右されない全体境界だけを対象とするため、バージョン番号・コード上の型やモジュール名・設定項目名・数値上限は実装コードへ譲ります。
利用手順は [作業・見守り・スケジュール](../features/tasks.md) と [環境設定・権限・拡張](../features/setup.md)、通信契約は [ホスト API の概要](../api.md)、端末連携は [クライアント設計](client.md) を参照する構成です。

## 拡張の基本方針と「手」「目」「体」の拡張領域

ene は [deepseek-harness](../references.md#deepseek-harness) に倣って本体を最小限に保ち、能力の追加や差し替えを外部拡張へ開く方針として、次の図のとおりホスト側の「手」や `プロバイダー` とクライアント側の「目」「体」を拡張領域に定めます。

```text
+------------------------------------------------------------------------+
| 利用者・クライアント側（端末固有の拡張領域）                           |
|  ・「目」（知覚）: エディタ・ブラウザ連携などのセンサー拡張            |
|  ・「体」（表現）: 表情・モーション・デスクトップ演出の追加            |
+------------------------------------+-----------------------------------+
                                     | 宣言された `端末能力` と承認境界
                                     | （無条件に信用せず検証・判定）
+------------------------------------v-----------------------------------+
| ホスト側（本体は最小限・「頭」の一貫性を保持）                         |
|  ・「手」（実務）: 通常の MCP による外部連携と任意の作業ハーネス接続   |
|  ・`プロバイダー` 拡張: LLM・埋め込み・音声の接続と単一 HTTP 仲介      |
|  ・ライフサイクルフック: 知覚や発話の限定的加工と実行前後の観察        |
+------------------------------------------------------------------------+
```

「手」の拡張では外部ツールや外部サービスとの連携に通常の MCP をそのまま使い、外部の作業エージェントをつなぐ場合も外部エージェント接続規格の ACP と同様に開始・追加指示・確認・中断・進捗報告を扱う小さな一項目を「手」のプラグイン仕様へ含める構成とします。
「目」と「体」の拡張はクライアント側のセンサーや表現エンジン側へ置いて `端末能力` の仕組みを通じて連携し、高度な専門作業が増えても実務処理は「手」の拡張へ分離することで「頭」の人格や口調を一貫して保つ設計です。

## プロバイダーのプラグイン化と通信仲介

LLM・埋め込み・音声合成・音声認識の接続先はホストを再構築せずに追加や差し替えが可能な形で `プロバイダー` 単位のプラグイン化に対応しつつ、標準の内蔵接続経路とプラグイン経路は接続設定ごとに排他的に選び、障害時に未許可の他経路へ自動で切り替えません。
ホストは起動時にプラグインの配置を読み込んで現行の接続設定が参照するものだけを起動して待機させ、未使用プラグインの常駐や利用開始時の読み込み待ちを抑える構成とします。
ホスト内で隔離実行されるプラグインは自身で直接の外部ネットワーク接続や認証情報の保持を行わず、外部への HTTP 通信をすべてホスト側の単一仲介経路へ通す仕組みです。
この単一仲介経路が接続ごとの許可宛先一致の検査・リダイレクト抑止・ホスト側での認証情報付与・応答量や通信時間の資源上限管理を担い、進行中のプラグイン呼び出しが取り消された場合もそのプラグインを読み直して残留状態を持ち越しません。

## ライフサイクルフックと承認制御の整合性

処理の流れへ介入するフックは役割ごとに加工の可否を厳格に分け、受信直後の知覚情報から不要な個人情報を隠す加工と発話直前の演出調整だけを許容する一方、操作やツールの実行前後に入るフックは監査と観察を目的とする読み取り専用に制限します。
利用者が承認した操作の引数を実行前フックが事後に書き換えた場合は [作業実行・操作確認・接続保護の設計](work.md) の確認境界で不一致として承認を即座に失効させ、失敗した操作結果を実行後フックで成功へ書き換えることも許しません。
また発話直前の演出調整であっても会話ログの本文や `記憶` 自体は改変せず、発話完了後や実行前後などの観察用フックで障害が起きても、対話や進行中の作業は止めずに継続する方針です。

## 実行環境の隔離とプライバシー保護

プラグインは配置先と実行形態に応じて段階的に隔離し、ホスト内で隔離実行されるプラグインは宣言された能力・宛先・参照範囲・計算資源の上限内に閉じ込めます。
外部プロセスとして動く MCP サーバーや作業ハーネスは、[作業実行・操作確認・接続保護の設計](work.md) に基づく子プロセス回収と承認手順のもとで実行する方針です。
ホストの外側で動くクライアント側の知覚拡張や表現拡張はその環境固有の権限や制約へ従う一方で、ホストはクライアント由来の能力宣言・入力値・知覚報告を無条件に信用せず、入力検査・許可範囲の照合・操作ごとの承認境界を通して扱います。
利用者の長期的な `記憶` や会話ログ全文をプラグインへ無条件に渡すことは行わず、プラグインが明示的に要求し利用者が許可した範囲の知覚要約や作業文脈だけに限定して引き渡す規則です。
