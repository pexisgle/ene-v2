# 作業相手APIとバックエンド接続

状態：Alphaの採用設計（2026-11-03）。関数名・型は論理契約の表記であり、現行protobufやWasm契約の実装済みAPIではない。[全体構成](../architecture.md)、[権限](permissions.md)、[クライアントAPI](../api.md)を併せて参照する。

## 1. 責任の分担

キャラクターの親は会話・ロールプレイ・軽いツール操作・子への委譲を担う。重さ、報告時期、相談、結果の検証、追加指示は文脈から判断する。子は親が渡した目的と必要な情報で作業し、説明・相談・結果を返す。親の全会話や心を自動で公開しない。

一つの用事に対し、eneが複数の専門子を編成する仕組みは作らない。子が自身のハーネスのサブエージェントを使うことは妨げない。別件は独立した作業セッションとして並列実行できる。親の会話生成と子の完了を同期して待たせない。

内蔵の子はRigを使い、親と同じモデル・ツール実行機構を共有する。指示、履歴、能力、記憶・秘密情報へのアクセスは分離する。外部の子の推論・認証・内部ツールは、そのバックエンドに委譲する。

## 2. 三つの識別

| 概念 | 意味 |
| --- | --- |
| BackendProfile | 実装、接続・認証、モデルと設定、公開するツール・許可の設定。実行一件そのものではない |
| WorkSession | 親に属する作業相手との継続的な文脈。ホストの安定IDと必要なら外部の不透明な再開参照を持つ |
| Run | 受け付けた入力から始まる一回の処理。終了理由と操作結果を持つ |

同じ設定から複数のWorkSessionを作れる。Runが終わってもWorkSessionを必ず破棄しない。子の応答が正常に終わったことを、依頼の目的を達成したことと同一視しない。ユーザーにこれらの内部区分を操作させる必要はない。

親の同一性、backend profile、作業セッション、run、入力、メッセージ、相談要求は代用できないIDとする。ホストが所属・対象を検証し、ECS Entityや外部プロセスIDを永続APIへ露出しない。

## 3. 最小操作

| 操作 | 入力と意味 | 応答の意味 |
| --- | --- | --- |
| describe | バックエンドの能力と設定項目を読む | 利用可能性。モデル・認証・任意機能の対応範囲を含む |
| open | 親、設定、初期の文脈・作業環境を指定 | WorkSessionの作成結果。まだ作業の成功ではない |
| send | session、入力、再送キー、配送の希望を指定 | input_idと配送状態。開始した場合はrun_id |
| respond | 特定のRequestへ回答する | 回答の受付。元の要求の内容・版・選択肢を検証する |
| cancel | 対象runを停止する | 停止要求の受付。停止完了は後続の状態・結果で確認する |
| close | sessionの利用を終了する | 終了結果。稼働中処理があれば明示的な停止手順を通る |
| get / subscribe | 状態と更新を読む | 保存状態と追跡可能なイベント |
| resume / configure | 過去のsessionや設定を扱う | 対応能力がある場合のみ。非対応は明示する |

名前や引数の厳密なwire形式は実装時に公開SDKへ定義し、プロトコル間で同じ意味を維持する。型を名前だけ変えた委譲ラッパーは作らず、内蔵Rust呼び出しにJSON-RPCを強制しない。

### 入力と配送

入力はテキストを基本とし、添付・成果物参照等は能力に応じて扱う。参照を渡しただけで、その資源へのアクセス権を増やさない。モデルが呼び出すsendでは親の主体と許可をホストが束縛する。

受付、待機、実行への配送、応答の終了を分ける。実行中へ注入できたか、次の入力として待っているか、非対応・失敗・結果不明かを返す。silent drop、独断の別セッション作成、失敗からの正常終了への補完をしない。

同じsessionの入力には順序を付ける。複数runを同時に受けられるかは能力で示す。非対応の実行中追加指示に対し、アダプターは待機や非対応を返し、待つか停止するかを親が選べる。停止せず同じ実行へ渡したふりをしない。

## 4. 更新イベント

イベントはsession_id、必要なrun_id、イベントIDまたは順序、時刻、対応する入力・要求を識別する。通信の文字片と意味のあるメッセージを分け、partialと確定を区別する。

| 種類 | 意味 |
| --- | --- |
| Message | 子が相手へ伝える説明・進捗・結果。出所を保ち、ユーザーの発言として保存しない |
| Request | 通常の質問、選択、権限要求等。要求ID、対象、回答形式、解決状態を持つ |
| Activity | 実行・ツール・成果物等の状態。通常は詳細参照に用い、全ログを親へ自動投入しない |
| RunFinished | 正常応答、キャンセル、出力・回数制限、拒否、失敗、不明などを区別する |
| SessionChanged | 設定、利用可能性、再開情報等の変更 |
| Extension | 名前空間付きの追加情報。必須の意味と無視可能な付加情報を区別する |

子の対外的な説明・相談・結果を親への主要な連絡にする。内部推論やすべてのツールログは標準で親へ送らない。別の報告要約エージェントを必須にせず、親が必要なときに詳しく問い合わせる。

文字片単位で親を起こさず、メッセージの区切りや進捗のスナップショットとしてまとめる。重要な相談・終了・失敗は、単なる進捗の間引きで失わない。親への通知には現在状態を参照できるIDを含める。通知を受けた親が必ずユーザーへ話しかけるルールは作らない。

## 5. ACP互換の境界

eneの全APIをACPにするのではなく、対応する機能を薄く写像する。初期はACP v1を検証基準とし、採用SDKの版と実エージェントの能力を固定して試す。Draftの将来仕様を必須要件にしない。[資料](../references.md#alpha-work)

| eneの意味 | ACP v1への主な写像 | 制約 |
| --- | --- | --- |
| 能力・設定 | initialize等の能力・設定 | 実際に広告された機能だけを利用する |
| session作成 | session/new | ホストIDと相手のsessionIdを対応付ける |
| 指示・追加情報 | session/prompt | v1の応答はターン終了。eneの受付だけを正常完了として返さない |
| 子からの更新 | session/update | 通常のメッセージ、思考、ツール等を区別する |
| 権限への回答 | session/request_permission | 通常の自由な質問をすべて権限選択へ押し込まない |
| 停止 | session/cancel | 要求と完了、接続終了とプロセス停止を混同しない |
| 再開・設定・途中介入 | 相手が対応する標準機能／拡張 | 能力と版を確認し、未対応を隠さない |

ACPの外部エージェントをeneから呼ぶクライアント側アダプターと、eneの作業プラグインを既存ACPクライアントへ公開する逆方向を、小さく検証する。ACPへ公開する側は、任意機能を制限しても必須の応答・エラー・取消の意味を守る。「ACPに似た内部API」と「互換なwire実装」を区別する。

標準の通信・型・要求IDは公式SDKを使う。文字列ID等を独自の狭い型に変換して受理範囲を減らさない。不正・未知の終了理由やRPCエラーをend_turnへ置換しない。独自拡張は名前空間を付け、未対応の必須要求には明示的な結果を返す。

## 6. プラグインの自由度

内蔵Rust、Wasm、外部プロセス、ネットワーク接続を同じ呼び出し寿命へ強制しない。Wasmのinvoke終了、モデルの応答終了、runの終了、sessionの終了は別である。継続状態の保持や複数回呼び出しはランタイムが担当する。

全プラグインがすべての機能に対応する必要はない。能力に応じてtext-only、継続なし、途中介入なし等の範囲で利用できる。ただし存在しない継続・取消・安全性を補完して見せない。提供する権限と寿命が利用条件を満たさない機能は無効化し、別の方法を親が選べるようにする。

設定はプロバイダーが公開する選択肢を保持する。特定製品のモデル一覧・既定値をeneの型へ焼き込まない。モデルの自動選択は後回しにできるが、利用者が事前設定する経路は用意する。

## 7. ツール・認証

ホストツールの定義・検証・実行・認可は一か所とし、親と内蔵の子は直接利用し、外部の子にはMCPで公開する。Rigの既存ツール契約を優先する。全部の内部呼び出しをMCPにせず、外部ツールをわざわざWasmへ書き直させない。

MCP接続には、対象sessionと許可されたツール・資源に束縛した能力を与える。ホスト所有者の全権トークンを子へ渡さない。外部の子が自前で持つツールをeneのツールと混同せず、親の心への直接書込は許さない。

外部の子はそのハーネスの認証・モデルを利用し、親と内蔵の子はeneのプロバイダー接続を利用する。認証拡張はAPIキー一個に閉じず、必要な開始・状態取得・更新・失効をアダプターへ委譲できる設計とする。ただし特定の契約が任意の利用を認めると保証せず、実際の連携と提供条件を確認する。

## 8. 停止・保存・再開

runは実行中、入力／承認待ち、停止処理中、終端結果を区別する。sessionの利用可能性とrunの状態を一つのenumへ混在させない。キャンセルは子のロックやモデル応答を待って初めて受付可能になる経路にしない。権限取消も別の制御入力で到達させる。

セッション一覧と保存結果は作業IDで取得する。設定のbindingをキーに最後の一件を上書きしない。進捗の全文をトークンごとに再保存せず、意味のある状態変化と復旧に必要な記録を保存する。終端は成功だけでなく失敗・取消・不明も通知する。

親の会話と作業記録の関係、入力・結果・外部の再開参照を保持し、記憶から作業を参照できるようにする。記憶と実行ログを全文複製しない。再開できない相手には、明示した新しいsessionへ必要な情報を渡す。外部キャッシュの寿命を作業の同一性や記憶の保持期限にしない。

再接続やクラッシュ後、成否不明な外部操作を自動で再送しない。副作用のexactly-onceを一般保証せず、ホストの受付重複防止、相手の再送契約、照合可能な結果を分ける。停止済みと報告する範囲も、確認できたプロセス・ツールに限る。
