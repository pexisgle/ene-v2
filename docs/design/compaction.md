# コンテキスト圧縮（Compaction）とセッション管理詳細設計

状態：Alphaの採用設計（2026-11-11策定）。[全体アーキテクチャ](../architecture.md)、[技術スタック](tech-stack.md)、[心と自動記憶](mind.md)、[チャット機能仕様](../features/chat/README.md)を参照する。

## 1. 目的と設計原則

デスクトップ常駐AIコンパニオンとして無期限・長時間の対話を破綻なく継続するため、LLMのコンテキストウィンドウ枯渇を防止しつつ、過去の対話の文脈を失わない持続性を担保する。

### 基本原則
1. **会話の正本（永続ログ）とプロンプト用ビューの分離**:
   - 会話の生ログは追記型（Append-only）の線形ログとしてディスクに完全保存され、改ざん・物理削除されない。
   - Compactionによる要約は、LLMへ送信する「アクティブプロンプト窓（View）」の構築時のみに利用される。
2. **機械的なコンテキスト上限保証（Mechanical Safety Boundary）**:
   - 閾値による目安だけでなく、送信直前に**すべての構成要素（ツール・人格・記憶・履歴・動的文脈）のトークン合計を機械的に検証**し、コンテキスト上限超過を数学的に遮断する。
3. **KVキャッシュ（Prefix Caching）の最大化**:
   - 毎ターン変動する情報（日時・知覚要約）をプロンプトの末尾側に配置し、静的設定および過去ログのキャッシュヒット率を最大化する。
4. **割り込み耐性と会話テンポの最優先**:
   - バックグラウンド要約処理の遅延や失敗によって、ユーザーへの発話応答を待たせない。

## 2. 会話ログの構造（線形ログ ＋ スナップショット）

レビューの指摘に基づき、複雑なDAG（有向非巡回グラフ）ではなく、**追記型線形ログ（Linear Append-Only Log）＋ スナップショットチェックポイント**のシンプルな構造を採用する。

```rust
use chrono::{DateTime, Utc};

/// 追記型会話エントリ
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct ConversationEntry {
    pub sequence_no: u64,
    pub timestamp: DateTime<Utc>,
    pub role: ConversationRole,
    pub content: String,
    pub tool_calls: Vec<ToolCallRecord>,
    pub tool_results: Vec<ToolResultRecord>,
}

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub enum ConversationRole {
    User,
    Assistant,
    Context, // ホスト注入コンテキスト
}

/// セッションのチェックポイント
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct SessionSnapshot {
    /// 直前のCompaction完了時点の要約テキスト
    pub compaction_summary: Option<String>,
    /// 要約に含まれた最終シーケンス番号（これ以前はプロンプトの生ログから除外）
    pub compacted_through_sequence: u64,
    /// 最後に保存された版番号
    pub revision: u64,
}
```

## 3. アイドル検知とCompaction発動条件

### 3.1 厳密なユーザーアイドル検知（InactivityTracker）
- **判定基準**:
  - アイドルタイマーのリセット契機は、**「ユーザーからの明示的な発話・チャット入力、または承認アクション」の受信時のみ**とする。
  - コンパニオン自身による自発的な独り言・見守り発話・スケジュール実行などのキャラクター側の発話は、アイドルタイマーを**リセットしない**。

```rust
pub struct InactivityTracker {
    pub last_user_interaction_at: std::time::Instant,
}

impl InactivityTracker {
    pub fn on_user_activity(&mut self) {
        self.last_user_interaction_at = std::time::Instant::now();
    }

    pub fn idle_duration(&self) -> std::time::Duration {
        self.last_user_interaction_at.elapsed()
    }
}
```

### 3.2 発動トリガー（ソフト閾値とハード強制閾値）
- **ソフト発動（バックグラウンド非同期）**:
  - トークン使用率が **65%〜75%** を超過し、かつユーザーのアイドル時間が **60秒** 以上継続した場合に発動。
- **ハード強制発動（同期安全弁）**:
  - ユーザーが休まず連続対話してアイドルが一度も訪れず、トークン使用率が **85%〜90%** に達した場合、次ターンの推論前に同期実行し、コンテキスト溢れを決定論的に防止する。

## 4. 割り込み耐性とPre-compaction継続

Compactionはアイドル時に非同期バックグラウンドジョブとして実行される。

```text
[対話進行中] ──→ (アイドル検知 & ソフト閾値超過) ──→ [バックグラウンドCompaction開始]
                                                          │
               ┌──────────────────────────────────────────┴─────────────────────────────┐
               ▼                                                                        ▼
   [Compaction正常完了]                                                       [ユーザーからの割り込み発話]
   ・新Snapshot (要約 + compacted_through) を確定                             ・Compaction完了を待たずに即時応答
   ・次ターンから要約以降のログのみをプロンプト化                             ・開始前のSnapshot (pre-compaction) で推論
   ・記憶自動整理 (Consolidation) 完了                                        ・実行中のCompaction結果は破棄/延期
```

### 割り込み時の挙動
1. バックグラウンドCompaction実行中にユーザーが発話した場合、ホストはCompactionの完了を待たずに**開始直前のSnapshot（Pre-compaction Snapshot）を用いて即座に推論し、応答を返す**。
2. 実行中だったCompactionの結果は破棄され、次回のアイドル時またはハード閾値到達時に再試行される。

## 5. 機械的コンテキスト上限検証とフォールバック

### 5.1 過大な単一入力の入口遮断（Ingress Limit）
- **受信時の即時検証**:
  - `SendMessage` APIの受付時点で、入力テキストのサイズ・トークン数（上限: **8,000トークン / 約32,000文字**）を検査する。
  - 1件の入力だけでモデルのコンテキスト窓を破綻させるような過大な入力は、**そもそも会話ループに受け付けず、即座に明示的エラー（`InputTooLargeError`）を返して拒否**する（勝手な末尾切り捨ては行わない）。

### 5.2 送信直前の機械的検証と窓切り詰め（Window Trimming）
モデルへのリクエスト送信直前に、ホストは以下の安全条件を機械的に検査する：

$$\text{Total Input Tokens} + \text{Max Output Tokens} \le \text{Model Context Limit}$$

長大な会話履歴やツールの出力が蓄積し、かつバックグラウンド要約が未完了または失敗・タイムアウトした場合：
1. **会話テンポ優先のターン単位切り詰め**:
   - 永続ディスクログ（正本）は一切削除せず保持したまま、**アクティブプロンプト窓から最も古いメッセージを完全なターン単位（User ＋ Assistant、または ToolCall ＋ ToolResult の完全な往復）で一時的に除外**してモデル窓に収める（ToolCallとToolResultを分断する切り詰めは禁止）。
   - プロンプトのContext枠に `[System Notice: 過去の一部ログを一時的に省略して対話を継続しています]` を付与し、モデルが文脈の飛躍を理解できるようにする。
2. **履歴全除外でも収まらない場合の明示的失敗（ContextExceededError）**:
   - 削れる過去履歴をすべて除外してもなお、「固定部分（ツール定義＋ペルソナ＋Pinned記憶）＋ 今回の入力 ＋ 出力予約トークン」がモデルのコンテキスト制限を超過している場合、**上限に収まらない要求をモデルへ送信せず、直ちに `ContextExceededError`（文脈上限超過エラー）を返す**。
   - 無理な送信によるモデルプロバイダー側の400エラーや勝手な末尾文字化けを防止し、ユーザーへ「入力情報またはシステム設定がモデルの許容上限（○トークン）を超えているため処理できません」と誠実に通知する。

## 6. プロンプト構築順序（Prefix Caching 最適化）

Anthropic Claude、OpenAI、Geminiの **KVキャッシュ（Prefix Caching）** ヒット率を最大化するため、キャッシュ境界を壊さない「静的先・動的末尾」の順序を厳格に維持する。

```text
 ┌────────────────────────────────────────────────────────┐
 │ 1. Tools Definition (最も静的・セッション間共通)       │
 ├────────────────────────────────────────────────────────┤
 │ 2. System Persona & Core Profile (静的・キャラクター核) │
 ├────────────────────────────────────────────────────────┤
 │ 3. Pinned Core Memory (重要度10の中核事実・予算内)     │ ── 一致するPrefixが
 ├────────────────────────────────────────────────────────┤    キャッシュヒット！
 │ 4. Compaction Summary (前回の会話要約・低頻度更新)     │
 ├────────────────────────────────────────────────────────┤
 │ 5. Recent Dialogue History (追記型の会話生ログ)        │
 ├────────────────────────────────────────────────────────┤
 │ 6. Dynamic Context (現在日時、知覚要約、作業状態)      │ ── 毎ターン変動するため
 ├────────────────────────────────────────────────────────┤    履歴の「後ろ」に配置
 │ 7. Latest User Turn (今回のユーザー発話)               │
 └────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **動的コンテキストの配置位置**:
> 「現在日時」や「目の知覚要約（開いているウィンドウ）」などの毎ターン変動する情報を会話履歴の前に置いてしまうと、その位置以降のPrefix Cacheがすべて無効化される。
> したがって、**動的情報は会話履歴の後ろ（最新ターンの直前）に配置**し、過去の会話履歴全体がキャッシュされるようにする。

## 7. 検証条件と受け入れ基準 (Alpha Compaction Invariants)

| 不変条件 | 検証方法 | 合格基準 |
| :--- | :--- | :--- |
| **厳密なアイドル判定** | コンパニオンの自発独り言や定期tickを連続発生させる | ユーザー入力がない限りアイドルタイマーがリセットされず、経過時間通りにCompactionが発動すること |
| **過大入力の即時遮断** | 8,000トークンを超える単一テキストをSendMessageで送信 | 会話ループに入らず即座に `InputTooLargeError` が返され、メモリや窓を圧迫しないこと |
| **割り込み即時応答** | バックグラウンドCompaction中にユーザー発話を入力 | Compaction完了を待たずに直前スナップショットから推論リクエストがディスパッチされ（ディスパッチ遅延 500ms以内）、実行中結果が安全に破棄されること |
| **機械的上限検証とフォールバック** | 長大テキストを入力し、要約APIをタイムアウトさせる（通常ケースと履歴枯渇ケース） | 削れる過去履歴があればターン単位で切り詰めて応答を返し、全履歴を除外しても収まらない場合はモデルへ溢れリクエストを送信せず `ContextExceededError` を返すこと |
| **Prefix Cache保護** | 同一セッションで連続発話し、プロバイダーのキャッシュ使用量を検証 | 過去会話履歴のプレフィックスがキャッシュヒットし、入力トークン課金・レイテンシが削減されること |
