# 圧縮（要約）の設計メモ

状態：実装済み（2026-11-10）。[実装監査](../reviews/ene-host-audit-2026-11-10.md)のA5段階2。実装は `apps/ene-host/src/host/mind/summary.rs` と `src/host/kernel.rs` の `fit`。

## 1. 目的

窓だけでは、長く続いた会話の古い部分が毎回捨てられ、モデルは文脈を失う。捨てる代わりに、古い範囲を要約して残す。会話の正本（Rigのセッションログ）と `GetHistory` は変えない。変えるのは、そのリクエスト専用の履歴ビューだけである。

## 2. 決めたこと

| 論点 | 決定 |
| --- | --- |
| 要約を作る主体 | ホストの別モデル呼び出し（`purpose=memory` のGrantと接続）。ターンのモデル呼び出しを妨げない |
| 実装の土台 | `rig_memory::compaction::CompactionPolicy` と `summary_author()`。Rigの `rig_basics::compaction` と同じ方式 |
| 要約エントリの著者 | `summary_author()`（`AuthorKind::Plugin("compaction")`） |
| `GetHistory` での扱い | 出さない。要約はそのリクエスト専用の履歴にだけ入り、会話の正本（セッションログ）には入らない |
| 自動整理への再投入 | 起きない。要約はリクエスト専用の履歴にしか無く、会話の正本を読む `collect_batch` には現れない |
| 整理カーソル | `MessageId` のまま変えない。`splice` は範囲外のエントリの `id` を保つので、畳んだ後もカーソルは一致する |
| 窓との関係 | `Fit` で窓をかけ、落ちた範囲を要約して次回以降の要求の先頭に置く。窓は最後の手段として残る |
| 要約の保存先 | エージェントの `Summary` コンポーネント（メモリ内、`through` と本文）。再起動後は最初の刈り込みで作り直す（保存keyを増やさない） |
| 再試行 | 失敗、または要約用のモデルが無い場合は、その位置を試行済みとして記録し、会話がさらに進むまで要求しない（呼び出しの連鎖を作らない） |

## 3. 変えないこと

- セッションログ、`GetHistory` の全件性、整理カーソル、`GetMessage`。
- 要約は「保存されないリクエスト専用の履歴」にのみ入り、会話の正本を書き換えない。要約を正本へ保存する変更は、別の設計判断として扱う。
- 打ち切りの事実は `Notice` でクライアントに見せる（`window_truncated_unconsolidated` と同じ経路）。

## 4. 実装の確認と残り

実装で確認済み：`splice` 後も残ったエントリの `id` は変わらない（整理カーソルは `MessageId` のまま有効）。要約の入力は窓で落ちる範囲のうち未要約の部分だけ。失敗してもターンは止まらず、窓だけで続行し `Notice { code: "summary_failed" }` を出す。

実装していないもの：

- 利用者が明示的に「ここまでを圧縮」と頼む経路（`CompactReason::Asked`）。
- 古いツール出力の掃除（`ClearToolOutputs`）と `TrackArgument`。
- 会話の正本や `GetHistory` への要約の反映（このADRでは採らないと決めた）。
- 要約の取り消し（`undo_summary` 相当）。
