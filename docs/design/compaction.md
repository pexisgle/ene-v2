# コンテキスト圧縮（Compaction）とセッション管理

状態：Alphaの採用設計（2026-11-10初版、2026-11-11改定）。[全体アーキテクチャ](../architecture.md)、[心と自動記憶](mind.md)、[チャット機能](../features/chat/README.md)を参照する。

## 1. 目的と基本原則

デスクトップコンパニオンとして長時間・無期限に対話を続けるにあたり、LLMのコンテキストウィンドウの枯渇を防ぎつつ、過去の対話の文脈を失わない持続性を担保する。

- **会話の正本（セッションログ）との分離**:
  会話の完全な生ログ（Rigセッションログ）は正本として保ち、`GetHistory` などのAPIで改ざんなく取得できる。要約はプロンプト生成用の「揮発的・リクエスト専用ビュー」にのみ挿入され、過去の生ログを物理的に破壊しない。
- **要約と長期記憶の分担**:
  Compactionによる「会話要約」は直近の話題や作業の流れを繋ぐ短期〜中期の連続性を提供し、好み・思い出・実務手順といった持続的知識は[心と自動記憶](mind.md)（エピソード記憶・スキル記憶）が担う。
- **ユーザー体験の最優先**:
  要約処理の負荷や待ち時間によって、ユーザーへの発話応答やリアクションをブロックしない。

## 2. 発動条件とアイドル検知

Compactionの発動は、トークン消費量とユーザーの操作停止（アイドル時間）の組み合わせによって制御する。

### アイドル時Compaction（Soft Trigger）
- **発動条件**:
  コンテキストの推定トークン数が**ソフト閾値（例: ウィンドウ上限の 60〜70%）**を超過しており、かつ**アイドル時間が一定以上（例: 30〜60秒）継続**した場合に、バックグラウンドで自動実行する。
- **厳密なアイドル検知**:
  - アイドルタイマーの基準は「**ユーザーからの明示的な発話・チャット入力、またはユーザーのアクション**」の不在である。
  - コンパニオン自身による自発的な独り言、見守り発話、スケジュール実行による定期自律発火など、理由なきキャラクター側の発話はアイドルタイマーを**リセットしない**。

### 強制Compaction（Hard Trigger）
- ユーザーが休まず連続して発話を続け、アイドル状態が一度も訪れない場合に備え、**ハード閾値（例: ウィンドウ上限の 85〜90%）**を設定する。
- トークン数がハード閾値に到達した場合、アイドル時間を待たずに次ターンの推論前に同期的に強制Compactionを実行し、コンテキスト溢れ（Context Overflow）によるセッション破綻を確実に防止する。

## 3. バックグラウンド実行と割り込み耐性（Branching）

Compactionはユーザーとの対話を邪魔しないよう、アイドル時にバックグラウンドジョブとして非同期に実行される。

```text
[対話中] ──→ (アイドル検知 & ソフト閾値超過) ──→ [バックグラウンドCompaction開始]
                                                         │
               ┌─────────────────────────────────────────┴─────────────────────────────┐
               ▼                                                                       ▼
   [Compaction正常完了]                                                      [ユーザーからの割り込み発話]
   ・新要約をキャッシュに反映                                                ・Compactionを待たずに即時応答
   ・古い生ログをプロンプト枠から退行                                        ・Compaction前の状態から分岐継続
   ・記憶整理ジョブ完了                                                      ・実行中Compaction結果は破棄/次回延期
```

### 割り込み時の挙動（Pre-compaction 状態からの分岐）
Compaction実行中にユーザーが発話・チャット入力を送信した場合：
1. **即時応答**:
   Compactionの完了を待たず、Compaction開始直前の履歴ビュー（pre-compaction state）を用いて即座にモデル推論を行い、応答を返す。
2. **結果の破棄と延期（Option B 採用）**:
   Rig（Rust）におけるセッションログと並行更新のマージ複雑性・不整合リスクを回避するため、割り込みが発生したバックグラウンドCompactionの生成結果はコミットせず破棄（または次回のアイドル時へ延期）する。
3. **オーバーフロー回避の安全性**:
   ソフト閾値を低め（60〜70%）に設定しているため、一度Compactionが破棄されても直ちにコンテキスト上限に達することはなく、安全に次のアイドルまたは強制Compactionへ引き継がれる。

## 4. プロンプト構築順序（Static First, Dynamic Last）

Anthropic Claude、OpenAI、Google Gemini などの各モデルプロバイダーが提供する **KVキャッシュ（Prefix Caching）** のヒット率を最大化し、応答レイテンシとAPIコストを最小化するため、コンテキスト内の情報配置は「静的なものから動的なものへ」の順序を厳格に維持する。

| 順序 | 項目 | 内容 | 更新頻度 / キャッシュ性 |
| :---: | :--- | :--- | :--- |
| **1** | **Tools** | 利用可能なツール定義（親の最小ツール群） | 最も静的（セッション間不変） |
| **2** | **System Prompt** | キャラクターのコア設定、人格・口調・振る舞い | 静的（キャラクター不変） |
| **3** | **Pinned Core Memory** | 重要度10の中核記憶、共有プールの基本プロファイル | ほぼ静的（基本事実） |
| **4** | **Compaction Summary** | 過去の古い対話の要約 | 低頻度更新（アイドル時のみ更新） |
| **5** | **Retrieved Episodic Memory** | 当該ターンの話題に応じて検索されたエピソード記憶 | 中頻度更新（話題変更時） |
| **6** | **Dynamic Context** | 「目」の知覚要約、「手」の稼働状況、現在日時 | 高頻度更新（毎ターン変動） |
| **7** | **Recent Dialogue History** | 直近のユーザー発言とコンパニオン返答の生ログ | 毎ターン追記 |

### 除外事項（関心の分離）
- 「手」（Hands / WorkSession）が保持する実務スキル一覧（`Available Skills`）は、「頭」（Brain / コンパニオンAgent）のプロンプトには**含めない**。「頭」は実務を「手」へ自然言語委託するため、スキルの詳細や一覧を持つ必要がなく、KVキャッシュの保護と認知負荷の削減を両立する。

## 5. 記憶自動整理（Consolidation）との同期

Compactionの発動（アイドル時）は、[心と自動記憶](mind.md)のバックグラウンド自動整理（Consolidation）ジョブのトリガーと連動する。

1. アイドル検知により、未要約の会話範囲がCompactionへ送られると同時に、未整理の対話ログと直近の記憶引用実績（`cited_memories`）が記憶整理モデルへ渡される。
2. 記憶整理モデルは：
   - 新しいエピソード記憶の抽出（1〜10の重要度、発生時刻、感情タグの付与）。
   - 既存記憶の統合や修正、引用実績に基づく重要度スコアの再調整。
3. これにより、対話セッションの文脈圧縮と長期記憶の定着が同一のアイドルサイクルで安全に完了する。
