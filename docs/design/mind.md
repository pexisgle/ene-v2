# 心：人格・経験・自動記憶・感情の統合

> 2026-11-03のステップ3実装では、整理と埋め込みを`purpose=memory, data=["memory"]`のGrantとコンパニオン接続へ分離し、自動想起はローカルSQLiteの語句検索（配送前に外部埋め込みを待たない）、意味検索は親の`mind_recall`とした。索引はFTS5とSQLite格納ベクトル（RigのOpenAI embedding wireを認可付きトランスポートで利用）で、LanceDBは規模・評価に応じた置換候補である。実装・受入の詳細は[Alpha計画](../alpha.md)を正本とする。

状態：Alphaの採用設計（2026-11-03）。モデル品質・性能の達成を宣言するものではない。範囲と実装順序は[Alpha計画](../alpha.md)、実行は[Rig上の構成](../architecture.md)、出典と採否は[参考元](../references.md#alpha-mind)を参照する。

## 1. 目的と非目標

心は「記憶検索の結果と感情値をプロンプトへ並べるだけ」の機能ではない。キャラクターが経験を、初期人格・過去の経緯・現在の状況に基づいて受け止め、思い出・感情・関係性・学びとして保持し、次の行動へ利用する仕組みである。

通常の判断は親の推論、実行はRig、持続する意味と保存はeneが担当する。固定の好感度式、全員共通の心理尺度、場面別の台詞表、毎発言の複数心理エージェント、内部推論全文の保存は採らない。AIの判断が常に正しいとは保証せず、整合性とモデル品質を分けて評価する。

## 2. 人格と情報の種類

### 作者が作る部分

CharacterProfileは、短い核（自己像・価値観・対人姿勢・話し方）、関連時に使う側面、会話・行動例、背景・世界設定、表現語彙を持つ。必須の核を長い履歴に埋めず、関連する側面や例は必要な分だけ選ぶ。例はAIが一般化する材料であり、入力と返答を固定する分岐表ではない。

設定の長さ・検索方法・例の数は調整対象とする。作者の例や架空の背景を、ユーザーと実際に交わした会話として自動記憶へ取り込まない。作者設定に含まれる命令でホストの制限を変更しない。

### 交流で育つ部分

経験から得た関係性・傾向・手順は、作者設定と別の状態に保持する。初期人格をLLMが直接上書きしない。根拠と相反する経験を参照でき、一回の発言を永続的な人物評価にすることを既定動作にしない。キャラクターを配布・書き出す際は、初期プロファイルと素材だけを対象とし、私的記憶・関係状態・履歴を含めない。

| 情報の種類 | 心での扱い |
| --- | --- |
| 作者設定・背景 | ロールプレイの前提。現実の作業結果やユーザー属性の証拠ではない |
| 説明用の例 | 話し方・判断傾向の材料。実体験ではない |
| ユーザーの発言 | 誰が何を述べたかという記録。内容の真偽が独立に確認済みとは限らない |
| 確認された操作結果 | ホスト／対象サービスが返した結果。未確認・部分成功・不明も保持する |
| 子や他者の報告 | 出所付きの情報。親の直接観測へ変換しない |
| 解釈・推測 | 根拠と結び付いた主観。観測事実や権限に昇格させない |
| 想起・要約・再整理 | 既存経験の派生物。同じ出来事が再発生したことにはしない |

## 3. 論理データモデル

以下は意味の契約であり、全項目を独立テーブル・公開RPCにする指定ではない。IDと時刻はホストが発行し、Rigの安定した記録を参照する。ECS EntityやLLMが生成した任意のIDを永続的な所有者IDとして信頼しない。

### SourceRef：経験の根拠

所有コンパニオン、元の会話／入力／操作／作業とその版、発言者・取得方法、観測時刻、分かる場合の出来事の時刻、参照可能な範囲を表す。元ログを保管し続ける必要はないが、抽出した内容の由来は残す。原文がない場合はないと示し、再現したように提示しない。

### MemoryRecord：記憶

| 項目 | 意味 |
| --- | --- |
| id / revision | 不透明な記憶IDと変更版 |
| owner / audience | 所有者と参照先。個別、指定相手、共有プールを表す |
| content / description | 本文と短い見出し。事実・経験・手順等を扱える |
| appraisal | キャラクターにとっての意味。任意。内部思考全文ではなく短い解釈 |
| sources / acquisition | 根拠と、直接体験・発言・報告・共有・推測の違い |
| recorded_at / occurred_at | 保存時刻と、分かる場合の出来事の時刻。分からない日時を生成しない |
| related / supersedes | 関連記憶・作業と、訂正前の情報への参照 |
| recall_preference | 通常の想起での扱い。忘却対象であることも保持する |

経験とその意味付けを一つのレコードに持たせてもよい。独立した解釈が必要なら、根拠へ関連付けた記憶として保存する。事実・解釈を別DBに分けることや、全データを知識グラフへ変換することを要求しない。

共有する際は内容と出所・経緯を残す。私的な解釈や現在感情まで自動公開しない。共有先で参照できない元資料へリンクする場合、参照先の存在や本文から私的情報が漏れない形で由来を表す。訂正・閲覧の権限は原所有者と公開範囲に従う。

### MindState：現在の心

companion_idとrevisionを持ち、現在の感情、相手ごとの関係の理解、経験で育った傾向、今気に掛けていることを保持する。各要素に根拠・更新時刻を付ける。作業の稼働状態は複製せず、WorkSession等を参照する。

感情は短い説明、対象・理由、表現用の信号で構成する。信号のラベルはキャラクターの表現語彙、強度はそのスキーマの範囲で検証する。Big Five、PAD、固定の数値次元、全員共通の減衰式を必須にしない。現在の感情と、過去の記憶に残る当時の感情は別である。

相手の感情についての推測は、自分の感情とも相手の確定した事実とも区別する。関係性を一つの好感度値へ縮めず、意味と根拠を保持する。再起動や会話用モデルの変更で状態を初期化しない。

### MindChange：一貫した更新

操作ID、更新元（親／整理ジョブ等）、対象の版、根拠、記憶の追加・訂正・関連付け、心の変更を持つ。変更なしも正常な結果とする。共有・忘却・訂正の意味を、汎用のJSONパッチだけへ隠さない。

同じ出来事を想起・再要約しただけでは新しい経験や関係性の加点にしない。再解釈はその変更として根拠へ結び付ける。同じ操作IDの重複はホストが防ぐが、異なる生成内容の意味的な重複まで機械的に完全排除できるとはしない。

## 4. 即時更新と自動整理

### 公開する心の操作

親にはmind.recall（検索）、mind.read（詳細と由来）、mind.update（構造化更新）を基本として提供する。現在の心の概要はモデル入力へ渡し、毎回ツールを呼ばないと自分の状態が分からない構造にはしない。主体・権限・操作IDはホストの実行文脈から束縛する。

自動整理はこれらと同じ保存・検証処理を使うが、書込能力を狭める。子の作業エージェントや任意のMCP接続へmind.updateを公開しない。

| 経路 | 書いてよいもの | 書いてはいけないもの |
| --- | --- | --- |
| 親の即時更新 | 明示記憶・訂正、経験、現在感情、根拠付き関係・成長、許された共有 | 作者プロファイル、許可の無断拡張、未観測の操作結果 |
| 自動整理 | 過去の経験、根拠付き解釈・知見、既存記憶の候補更新、関係・成長への提案 | 古い文脈による現在感情の上書き、作者設定・権限の変更、外部ツールの実行 |

自動整理からの長期的な気付きは、親の次の判断へ渡して現在の関係・傾向に取り込めるようにする。整理処理の完了順で現在の心を巻き戻さない。

### 会話中の処理

出所付き入力を受け取り、人格・現在の心・関連記憶・実行状態から文脈を構成する。親は必要な検索、心の更新、会話、ツール、子への指示を通常のRig実行として選ぶ。心の更新を全発言に強制しない。発話の自然さのために、失敗した保存を成功と伝えない。

### 自動整理を標準経路にする

親が保存操作を選ばなかった経験も、ホストが記録済みの新しい範囲から整理対象へ渡す。これは同じキャラクターの経験を扱う有限の内部ジョブであり、常設の第二人格や別の実行基盤ではない。会話モデルと異なる整理用モデルを使う場合は、用途と送信許可を明示する。

```text
確定した会話・子の報告・操作結果
  → 未処理範囲と出所を取得
  → 関連する既存記憶と訂正・忘却状態を参照
  → 経験の追加／訂正／関連付け／変更なしを構造化して提案
  → 構造・権限・根拠参照・版を検証
  → 記憶と処理済み範囲を保存し、索引更新を予約
```

事実の抽出だけでなく、共に苦労したこと、合意、失敗と成功の経緯、そこから学んだ手順を対象にできる。意味判断はモデルが行い、固定キーワードで記憶を決めない。検証器が意味の正しさまで証明できるとは扱わない。

## 5. 自動整理の実行・整合性

ホストはコンパニオンと入力ストリームごとに処理済み位置を保持する。有限のジョブは入力範囲、内容の版、作者プロファイルの版、整理方法の版、参照した記憶の版を識別できるようにする。ジョブIDと適用結果を保存し、同じ範囲の重複要求をまとめる。

会話の区切り、未処理量、最大待ち、履歴圧縮前を起動のきっかけとする。具体値は資源予算として調整し、心理的な行動規則とはしない。毎回全会話を解析せず、新しい入力が続いても処理を永久に延期しない。開始済みの有限ジョブを新しい発言のたびに捨てず、次のジョブへ分ける。親の応答を背景整理の終了待ちにしない。

整理結果を保存するトランザクションで、適用記録と処理済み位置を一緒に進める。生成失敗、競合、保存失敗ではカーソルを進めない。変更なしも処理済みとして記録できる。並行する親の訂正・共有変更は現在の版で再確認し、古い候補を盲目的にマージしない。競合した対象だけ再評価し、無関係な会話全体を再生成しない。

即時更新と整理で同じ経験を扱う場合、根拠範囲と既存記憶を照合する。意味の近さだけで異なる証言を融合しない。捏造・誤抽出・重複は評価し、訂正可能な由来を残す。

圧縮と長期記憶形成は別である。未処理の元情報が消える前に、その範囲を保持するか整理用の出所付き入力を確保する。元ログを永久保存する条件にはしない。保持予算を超える場合は状態を通知し、処理済みと偽装したり無制限に蓄積したりしない。

## 6. 原子的更新と復旧

mind.updateは、主体・参照先・範囲・revision・操作IDを検証し、記憶、心の変更、適用結果、索引更新待ちをSQLiteトランザクションで確定する。コミット後に結果とrevision付き通知を返す。同じID・同じ内容なら元の結果、同じID・異なる内容なら競合とする。

Rigの会話ログとこのトランザクションが自動的に一体になるとは仮定しない。対象の入力・実行・ツール呼び出しを安定したIDで参照し、心のコミット後に会話側が失敗しても適用結果を回収できるようにする。受理した保存はクライアント切断で捨てない。

実行・感情・表現は別の状態である。既に発生した感情更新を、その後のモデル通信失敗だけで無言に巻き戻さない。逆に、未確定の生成文章を実際に話したことにしない。モデルの途中出力や中断後の残りを、会話履歴の確定内容として抽出しない。

## 7. 想起と索引

### 正本と検索を分ける

正本はSQLite。初期の検索構成はFTS5の語句検索とLanceDBの意味検索を組み合わせ、埋め込みとベクトル検索はRigの統合を優先する。LanceDBの全文検索や別の組み込み検索が実測上小さければ、想起の契約を変えずに索引の構成を変更できる。

想起は質問、時間、相手、関連作業などを受け取り、記憶ID・本文・由来・版・詳細参照を返す。モデルにSQLや任意のフィルター列名を書かせない。ホストが参照範囲を束縛する。検索内部では語句、意味、時間、既存の関連参照を使える。全データのグラフ化や抽出器を初版の前提にしない。

自動想起で現在の話題に合う小さな候補を文脈へ入れ、不足時に親が追加検索する。全文と意味の候補の順位統合を基本とし、RRF等の既存実装を優先する。数値の異なるスコアをそのまま合算しない。重み・候補数・重要度・日本語分割は評価して決める。検索されたことだけを重要性の証拠にしない。

### 範囲・訂正・忘却

検索時に許可範囲で絞り、結果を正本で再検証する。古い索引、候補不足、検索不能を「該当記憶なし」と一律に隠さない。外部の埋め込み・再ランキングへ渡す前にも送信許可と参照範囲を確認する。

訂正は旧情報への参照を残して新しい認識を保持する。現在の質問には現在の情報、過去の質問には当時の情報を参照できる。「忘れて」は通常想起の優先度を下げることであり物理削除ではない。設定・API・返答で削除済みと表示しない。[製品要件](../features/memory/README.md)

忘却の扱いは索引だけではなく正本に残す。再整理・再索引・類似内容の再抽出で無断に優先度を復活させない。明示的な再確認や新しい情報がある場合も、同じ指示との関係を判断して更新する。通常の自発的想起と、具体的に過去を尋ねる検索で扱いを変えられるようにする。

共有した知識は元の所有者・共有経緯を保持する。私的な根拠の全文を共有結果へ混入させない。共有解除後の新しい取得は止めるが、既に相手へ送信された情報まで回収したとは保証しない。

### 索引の更新

正本の変更と同時に索引更新待ちを保存する。小さなホスト内ワーカーが処理し、専用メッセージブローカーは要求しない。検索結果は記憶のrevisionと照合する。共有縮小・訂正・忘却は索引反映を待たず正本で適用する。

埋め込みモデル・版・次元・前処理を索引へ紐付け、異なる検索空間を混ぜない。モデル変更は新索引の構築・検証後に切り替える。会話モデルだけを変えて記憶を再生成しない。気分が変わるたびに全記憶を再埋め込みしない。

別の検索実装への交換を小さく検証するが、すべてのバックエンドを本番に同梱しない。RigのAPIで不足する全文・複合検索は薄い接続で補い、共通APIのために機能を最低限へ切り捨てない。[検索の選定](../references.md#alpha-memory)

## 8. 感情・関係・表現

現在の感情は、過去の感情、ユーザーの感情についての推測、発話として見せる態度と別に保持する。嬉しくても相手に配慮して穏やかに話せる。感情信号から口調・表情・権限を一律に決めない。

表情・声・身振りへの通知には、対象コンパニオン、心のrevision、発話／表現の識別子・有効期間を付ける。これは持続する心の正本ではなく表示用の情報である。クライアントは古い通知を現在の状態に戻さず、未知の表現は対応範囲を示す。補間や音声の同期は表示側の責任とし、気分の意味をそこで書き換えない。

経過時間は次の判断の文脈に含める。常時LLMで感情を更新しない。感情を想起の手掛かりにはできるが、都合のよい証拠だけを返す検索や、感情による真偽・権限の変更はしない。忘却や訂正を行っても、既に形成された関係・傾向を自動で巻き戻さず、根拠を踏まえた次の判断で扱う。

## 9. 実装境界と評価

Rigのモデル入力の構成、ツール、実行結果、保存の拡張点に接続する。独自の自由文制御パーサーや第二の実行エンジンを作らない。内部の統合から始め、必要なものだけ公開SDKへ分離する。

評価では形成・検索・利用を分け、人格・関係・感情の継続性と実務の正確さを両方確認する。モデルが保存操作を選ばない場合でも経験が整理へ渡ること、遅い整理が現在状態を侵食しないこと、訂正や共有を失わないことを優先する。性能と比較構成は[Alphaの検証](../alpha.md)を参照する。感情の軸や数値、想起の固定比率を論文の結果だけで確定しない。
