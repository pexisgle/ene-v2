# 心・記憶・会話圧縮の設計

この文書では [用語集](../terms.md) と [全体アーキテクチャ](../architecture.md) を前提に、`人格設定`・`記憶`・`心の状態`・`記憶の整理`・`会話の圧縮`・スキル記憶の設計規則と契約をまとめます。
テーブルの細かな列定義やファイル構成およびチューニング用定数は実装コードへ譲って不変条件と処理境界へ絞り、利用面からの狙いは [記憶とスキル](../features/memory.md) と [感情とキャラクターの成長](../features/mind.md) を参照できる構成です。

## 人格設定と心の状態の分離

作者が用意する静的な `人格設定` と対話を通じて育つ動的な `心の状態`・`記憶` は明確に分け、配布用パッケージには静的な要素（「姿」「声」「心」のひとまとめ、または要素単体）だけを含めます。
パッケージには互換性確認用の形式版情報を付与し、取り込み先に該当の「声」プロバイダーやモデルが無い場合も読み込み全体を失敗させず代替設定へ安全に切り替えられる構造とします。
また同梱モデルなどに再配布禁止のライセンス条件がある場合は書き出し時に検査し、警告表示や対象アセットの除外によって無断再配布を防ぐ方針です。
`人格設定` は名前・人格の核・話し方・性格の側面・会話例・背景・表現語彙の 7 項目で構成し、日々の会話や `記憶の整理` からは書き換わらない契約です。
作者が書いた架空の会話例や背景は対話で蓄積した `記憶` や会話ログとは別の出所として扱い、作成画面のプレビューでも編集中の設定と単発の試し入力からツール無しの応答だけを返し、コンパニオンや会話ログ・`記憶` へ保存しません。
動的な `心の状態` は感情・関係性・傾向・関心の 4 領域をスキーマ付きの構造データとして保持し、発話ごとに出す一時的な表情や仕草の指示とは区別します。
感情は出来事で更新されたあとも時間経過で `人格設定` の人格の核や性格の側面に基づく本来の落ち着いた状態へ戻る一方で長期の関係性・傾向・関心は保ち、設定や状態の更新時はそれぞれの版番号を使った楽観的ロックで上書き競合を防ぎます。

## 記憶の可視範囲・想起・忘却

エピソード記憶は 1 事実を 1 件の `記憶` として分割保存し、参照できる範囲は「特定コンパニオン固有」か「全コンパニオン共有」かの単一軸だけで制御します。
検索は FTS5 trigram 全文検索（短い語は部分一致検索へ切り替え）とインメモリ上のベクトルキャッシュを順位統合し、モデル・接続先・次元数・前処理版の複合識別子で埋め込み空間を隔離する構成です。
想起スコアは重要度による減衰係数と関連度・重要度・直近性を掛け合わせて計算し、重要度 `0〜10` の意味づけと共有範囲の運用規則は次の表のとおり定めます。

| 区分・基準 | 役割と境界ルール |
| --- | --- |
| 重要度 `0〜1` | 忘却扱いとし、自動想起および常時注入の対象から外して明示検索でのみ参照する |
| 重要度 `2〜9` | 通常の想起段階（数値が高いほど優先され、訂正された古い記憶は最大 `2` までに抑える） |
| 重要度 `10`（常時注入枠） | 会話の前提として常に注入し、文字数上限を超えた場合は最終参照や更新が新しいものを優先して溢れた分を通常想起へ回す |
| 共有範囲の昇格・解除 | 「全コンパニオン共有」への登録は話題や利用者指示に基づき行い、誤共有時も即座に「特定コンパニオン固有」へ戻して他コンパニオンの想起対象から外せる |

日常の忘却は重要度を `0〜1` へ下げる論理処理として扱い、訂正時も古い記憶と置き換えの関係を結ぶため過去の記録を壊さず明示検索から参照できます。
検索候補としてプロンプトへ注入しただけでは最終参照日時を更新せず、明示的な参照・更新操作での確定利用と、`記憶の整理` が抽出した引用候補をプロンプトへ実際に注入した一覧と照合して一致した推定利用だけを更新対象とする方針です。
一方で利用者が機密情報の完全消去を求めた場合は日常の忘却と分けた物理削除経路を用意し、保存済みデータと検索索引から対象を取り除ける契約とします。
永続データの運用では起動時のスキーマ移行と状態ディレクトリ単位のバックアップ・リストアを想定し、障害復旧時の一貫性を保つ方針です。

## スキル記憶の分離と段階的開示

再利用できる作業手順はエピソード記憶から分け、コンパニオンごとに登録件数の上限を設けた専用のスキルストアへ独立して管理します。
普段の会話を受け持つ「頭」の文脈を圧迫しないよう本文を常時注入せず、まず名前と概要の一覧を確認したうえで必要な手順だけを読み取り、学習時に手順として保存・更新する段階的開示の方針です。
「手」へ作業を委譲する際もその仕事に必要な文脈だけを引き継ぎ、エピソード記憶や `人格設定` を書き換える権限は与えません。

## 会話の圧縮と記憶の整理

会話の生ログは追記型のファイルストアへ不変保存し、`会話の圧縮` の要約に加えて `記憶の整理` による事実の抽出と `心の状態` の振り返りを同じ区間の 1 パスで処理する構成です。
要約スナップショットと、再送時に同じ発話を二重登録しないための受付記録はいずれも会話ログ内の付帯記録として追記し、外部への履歴 API にはこれらの付帯記録を除いた読み取り専用の投影だけを返します。
要約と `記憶の整理` の 1 パス処理は、トークン使用率がターン境界で所定の閾値を超えたときだけコンパニオンごとに同時実行を 1 件に限って起動し、直前の要約終端から今回の終端までを整理区間として重複を防ぎます。
その 1 パス処理で抽出した `記憶` と `心の状態` の更新案はそれぞれの版番号を使った原子的な比較更新で対話側の即時更新との競合を検知して破棄する仕組みです。
あわせて忘却済み記憶（重要度 `0〜1`）の自動復活も禁止したうえで、永続化が成功したあとにだけ要約スナップショットを保存する手順です。
単一入力の許容量上限はメッセージ受付時に検証し、送信直前の容量調整で要約が間に合わないときは完全ターン単位で過去履歴を一時切り詰めます。
全履歴を除いても上限を超える入力は送信せず、明示エラーを返して安全性を担保する構成です。

## プロンプト配置と動的末尾の非永続注入

プロンプトは不変の静的先頭、低頻度更新の会話履歴、応答のたびに変わる動的末尾、そして最新入力の順に並べ、LLM の KV キャッシュを保ちます。

```text
+-----------------------------------------------------------------------------------+
| 1. 静的先頭（不変 / セッションをまたいでキャッシュ対象）                          |
|    共通ルール・ツール定義・`人格設定`（7 項目）                                   |
+-----------------------------------------------------------------------------------+
| 2. 会話履歴（追記型ファイルストア由来 / 低頻度更新）                              |
|    要約スナップショット + 直近の生会話ログ                                        |
+-----------------------------------------------------------------------------------+
| 3. 動的末尾（メモリ上のみで結合 / 会話ログへ非永続・ターン固定）                  |
|    現在日時・ユーザー基本設定・知覚・`心の状態`・常時注入枠の記憶・自動想起の記憶 |
+-----------------------------------------------------------------------------------+
| 4. 最新入力                                                                       |
|    今回のユーザー発話または発端種別に応じたトリガー本文                           |
+-----------------------------------------------------------------------------------+
```

動的末尾はリクエスト構築時にメモリ上だけで結合して会話ログへは書き込まず、`記憶の整理` による記憶の再学習や履歴 API への内部文脈漏えいを防ぎます。
また 1 ターン内のツール反復中も同じ内容を固定し、KV キャッシュの無効化を抑える契約です。
自動想起の検索語は直近の発端種別（通常発話・知覚報告・作業報告・スケジュール）から判定し、非ユーザー発話のターンで過去の発言を再利用しないようにします。
