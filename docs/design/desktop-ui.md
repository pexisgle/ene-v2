# デスクトップUI

eneの通常ウィンドウは1つです。日常の主画面を会話とし、avatarは別の透明な常駐ウィンドウに表示します。ウィンドウを隠してもクライアントの制御は継続します。会話画面はコンパニオンへの入力・発言確認を担当し、ホスト接続・描画・将来の音声の寿命を所有しません。

## 対話と設定

起動時に会話の保存先を選びます。会話を始めた後は接続先を設定の1項目に収め、常設タブ・アプリ名の見出し・正常時の接続バッジは置きません。会話の入力欄のそばに「設定」を置き、設定からは「会話に戻る」で復帰します。開始前に設定を開いた場合は起動画面へ戻ります。設定やトレイの操作でも新しいOSウィンドウは作りません。入力中の文章、会話の閲覧位置、設定の下書きとカテゴリを維持します。

設定は「外観」「コンパニオン」「AIサービス」「送信許可」「接続先」に分けます。この基盤段階では端末設定とデモを利用できます。実ホストへの画面接続・設定更新は後続PRで追加します。`--demo`では「試してみる」から固定応答の会話を試せます。デモは外部送信せず、会話は終了時に消えます。

| 対象 | 保存する場所 | 内容 |
| --- | --- | --- |
| この端末 | `client.json` | 外観、avatarの位置・表示・サイズ・fps、ローカルVRM・VRMAと再生設定。将来の音声機器・音量・読み上げ切替 |
| コンパニオン | ホスト上のコンパニオン | 名前、共有する姿・声・性格、会話用・作業用AIの割当 |
| ホスト・外部接続 | クライアントの接続情報／ホストのサービス設定 | ホストへの接続と、ホストから利用するAI・音声サービスを区別。サービスの秘密情報はホストの資格情報ストア |
| 権限とデータ | 対象のコンパニオン・接続先・実行環境に対応する権限 | 送信先と用途、作業対象、操作範囲 |

ローカルパスは端末上の素材の場所です。別端末でも読める共有設定とは扱いません。将来は共有するモデル参照と、端末側のファイル解決を分けます。

## 操作の原則

`ui-ux-pro-max`のMinimalism、Error Recovery、Focus Statesを参照し、デスクトップ向けに適用します。WebのLP構成やモバイル専用の操作は採用しません。Slint用のスタック資料はないため、入力・フォーカス・描画はSlintの部品と実測で検証します。

細部は[FirefoxのAbout導線](https://support.mozilla.org/en-US/kb/find-what-version-firefox-you-are-using)、[KDEの入力部品とホバー表現](https://develop.kde.org/hig/getting_input/)、[GNOMEの標準メニュー項目](https://developer.gnome.org/hig/patterns/controls/menus.html)も参照します。モバイル向けの44ptという値をデスクトップ全体へ適用せず、文字量と入力手段に合う密度にします。

バージョンとクレジットは専用の「eneについて」に置き、設定の末尾とトレイから開きます。「外観」には表示を調整する項目だけを置きます。[Slint公式の案内](https://github.com/slint-ui/slint/blob/master/FAQ.md?plain=1)に沿ってAboutSlintを表示し、周囲の余白をリンクにしません。ページの切替で未保存の設定は破棄しません。

- 利用頻度で配置を決めます。会話と入力を主役にし、設定は必要なときに開きます。接続先の管理はその中に置きます。
- 正常な接続は会話画面に表示せず、入力を妨げる接続切れ・設定不足を操作の近くに表示します。保存結果・エラーはホバーせず読めるようにします。アイコンだけの操作は送信など文脈が明白な場所に限ります。
- 一般的な操作を説明する常設文は置きません。Enter／Shift+Enterの入力仕様はドキュメントに記載し、送信アイコンには短いツールチップと読み上げ用の名前を付けます。ラベルやボタンで分かる保存手順を本文で繰り返さず、未保存の変更・操作結果・進めない理由を必要な場面に表示します。同じエラーは一か所にまとめます。
- システムのライト／ダーク設定と日本語フォントを尊重します。補助文字・メッセージ・エラーにはテーマ別の意味付き色を使います。
- 会話の空状態では入力を促し、履歴を遡ったときには最新のメッセージへ戻る操作を用意します。
- 装飾アニメーションを追加せず、非表示の画面を操作対象にしません。

## 保存と即時操作

フォームの変更は下書きに保持します。「保存」で検証・永続化した後に外観と描画へ反映し、設定画面に留まります。失敗時は下書きとエラーを残し、保存済み値と稼働状態を変更しません。「元に戻す」で最新の保存済み値へ戻ります。

フォントの一覧は検索対応のセレクターにします。開くと選択欄自体で文字を入力でき、検索欄を別に追加しません。大文字・小文字を区別せず、空白で区切った各語の部分一致で候補を絞ります。上下キーは候補の移動、Enterまたは候補のクリックは確定、Escape・外側のクリックは取消です。検索や候補の移動だけでは下書きを変更しません。該当なしを表示し、一覧更新時も検索語と保存済み・一覧外の選択値を保ちます。候補行は仮想化して大量の一覧をスクロールできるようにし、長い名称はツールチップでも確認できます。

表示切替・中央へ戻す・描画再起動・再生状態・繰り返しは即時操作です。モーションは現在の実行状態を文字で表示し、再生・一時停止を1つのアイコン付きボタンで切り替えます。ボタンの幅は切替時も固定し、隣の「繰り返し」チェックボックスでループを切り替えます。素材ファイルの変更は保存後に反映するため、ファイルが未保存の間は再生操作を無効にします。これらは設定の下書きを保存しません。フォームから変更された項目だけを最新の設定へ反映するため、編集中のドラッグや表示切替が後の保存で巻き戻りません。ファイル選択のキャンセルは変更せず、破棄・保存や新しい編集後に届いた古い選択結果は無視します。

設定の接続先を開くだけでは、端末設定の下書きや会話を破棄しません。「会話に戻る」で同じデモの会話に戻れます。将来、異なるホストを選ぶ際には会話・権限・非同期応答の所属を接続先ごとに分離します。端末設定はホスト選択をまたいで保持します。

トレイが利用できる場合、×は非表示です。トレイがなければ×で終了処理に進みます。トレイは会話、設定、キャラクター、終了に分け、表示切替はチェック状態で示します。隠した後にトレイが消えた場合はウィンドウを復帰します。明示的なクライアント終了では描画を停止して回収し、ホストは終了しません。未保存の設定や未送信の文章がある場合だけ、破棄して終了するか画面へ戻るか選択します。

編集画面は`ui/widgets/settings/page.slint`の`SettingsPage`で作ります。ページ見出し・本文のスクロール・結果表示・保存欄をこのテンプレートが管理し、項目群は`SettingsSection`、項目行は`SettingField`、補足文は`SettingsSupplement`、補助操作は`SettingsActions`を使います。画面ごとに大きいタイトルや独自のラベル配置を足しません。ラベル幅と項目間隔は`UiState`の共通値を参照します。通常幅ではラベルと値を左右に揃え、本文幅が560×倍率未満では同じ入力部品を保ったまま縦並びにします。

## 幅・文字サイズ・入力への対応

初期サイズは900×760、最小サイズは420×480です。DPIはSlintの論理座標で扱います。レイアウト判定の倍率は`max(1, 文字サイズ / 16)`です。

- 内容幅が640×倍率以上では文字付きの設定カテゴリを左に、それ未満では上部の選択欄に配置します。設定カテゴリと本文を合わせて最大1024×倍率に収め、大きなウィンドウでは外側の余白を広げます。カテゴリと本文の間隔は維持します。
- 外観・デスクトップ表示・モデルとモーションの設定は、どの画面幅でも上から下へ同じ順序で並べます。フォームは840×倍率を上限にし、幅に応じて各項目のラベルと入力だけを横並び／縦並びにします。画面の高さが低ければ本文をスクロールし、保存ボタンは画面内に残します。リサイズでは入力部品を作り直さず、編集中の値を保持します。
- フォントはSlintが使うシステムのフォント一覧から選び、フォントと文字サイズの直後に「プレビュー」と明示した項目で日本語と英数字を表示します。サンプルには選択中のフォントと文字サイズを反映します。既存設定の未インストールのフォントも保持し、代替表示を案内します。
- フォーム幅が560×倍率以上ではラベルと入力を横並びにし、それ未満では縦に並べます。
- 送信ボタンは入力欄の右側に固定します。同じ入力コンポーネントを配置し直し、リサイズでIME・選択範囲・フォーカスをリセットしません。
- 会話本文は800×倍率を上限にして長い行を避けます。入力は内容に応じて伸び、画面の約3分の1と240×倍率の小さい方を上限に内部スクロールします。縦長の画面でも入力欄が履歴を占有しません。終了確認は中央の読みやすい幅に収めます。履歴を読んでいる間は新着で末尾へ移動せず、自分の送信時には末尾へ移動します。
- フォーム本文をスクロールし、保存操作は画面下に置きます。カテゴリ選択と即時操作は背景や枠を抑え、保存ボタンは内容に合った幅にします。保存と元に戻す操作には短い文字ラベルを付けます。狭い画面では保存状態を操作ボタンの上に分け、状態文を省略しません。長い説明・パス・エラーは折り返し、入力不正時は該当項目へ移動します。
- 通常の操作部品は高さ32論理px、アイコン16論理pxを基準にし、文字サイズや折り返しに応じて拡張します。ボタンは内容に合う幅と高さを基本とし、行全体の選択を表すナビゲーションだけ明示的に幅を広げます。クリック領域とホバー・フォーカスの枠を一致させ、余白では操作を発火しません。状態は文字でも表示し、非表示の画面の操作を無効にします。

## 音声・作業機能を追加する際の配置

音声入力は「押して話す」を基本として既定でオフにします。聞き取り中・応答待ち・発話中を文字でも表示し、テキスト入力と発言記録を利用可能にします。読み上げ切替、発話停止、作業停止を別操作にし、設定画面からも共通領域でアクセスできるようにします。現段階では利用できる音声ボタンを置かず、準備中と案内します。

ホスト設定の更新は対象ごとの保存とし、[ホストAPI設計](api.md)のrevisionで競合を検出します。資格情報登録、疎通確認、送信許可は別の操作として結果を表示します。

## 実装と検証

Rustのアプリ層が保存済み設定・下書き・会話モデル・稼働状態を保持します。Slintの`UiState`はその表示用の状態で、各画面に制御器を持たせません。ウィンドウと画面の稼働中は同じモデルと入力部品を保持します。

`just verify`は整形とClippy（テストを含む型検査）を実行します。テストは対象の挙動を変更したときに`just test`で実行します。合格済みの検査を変更せずに繰り返す必要はありません。

変更頻度の高い画面構成・配置の検査と開発用スクリーンショット出力は削除しました。画面を変更した際は必要な操作と表示を確認します。KDE/KWin上のトレイ表示、ネイティブIME、ポータルのファイル選択、モニター間のDPI変更は実機で確認します。
