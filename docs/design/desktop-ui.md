# デスクトップUI

eneの通常ウィンドウは1つです。日常の主画面を会話とし、avatarは別の透明な常駐ウィンドウに表示します。ウィンドウを隠してもクライアントの制御は継続します。会話画面はコンパニオンへの入力・発言確認を担当し、ホスト接続・描画・将来の音声の寿命を所有しません。

## 対話と設定

起動時は「ホスト管理」で、このPCのホストの状態を確認して接続します。会話画面では右上にホストアイコンと設定アイコンを置きます。ホストアイコンは状態表示と管理への入口を兼ね、下部に状態テキストや管理リンクを並べません。現在の接続先はこのPCなのでモニターのアイコンを使い、状態マークで接続済み・未接続・処理中・異常を区別します。ホバーでは「ホストの状態」という短いツールチップだけを表示し、フォーカスだけでは詳細を開きません。クリックまたはEnterで、ホストの稼働状態とアプリの接続状態を色と文字で示すポップオーバーを開きます。詳細は同じアイコンの再クリック・外側のクリック・閉じるボタン・Escapeで閉じ、フォーカスが残っても再表示しません。管理画面への移動は、詳細内の「ホスト管理」から行います。

設定の入口は右上の設定ボタン一つにまとめます。接続済みでAI設定が必要な場合は、同じボタンから必要な設定カテゴリへ進みます。入力欄のそばに別の設定ボタンや準備の案内文は置きません。設定や送信ボタンのツールチップから、必要な設定や送信できない理由を確認できます。デモ表示と送信の受付確認中の表示も上部に置きます。設定からは「会話に戻る」で復帰し、開始前に設定を開いた場合は起動画面へ戻ります。設定やトレイの操作でも新しいOSウィンドウは作りません。入力中の文章、会話の閲覧位置、設定の下書きとカテゴリを維持します。

設定は「外観」「コンパニオン」「AIサービス」「送信許可」「ホスト管理」に分けます。ホストに初めて接続したとき、会話準備ができていなければAI設定へ進みます。APIが返す未完了の理由に合わせて、モデル・APIキー・送信許可の設定へ案内します。通常起動はホスト接続を使います。デモは`just run-demo`で明示的に起動し、外部送信せず仮応答を試せます。デモ中も「実際のAIを設定」から接続先の選択へ進めます。切替時は入力中の文章と端末設定を保持し、デモの履歴は実際の会話へ送りません。

回答の最初の文字を待つ間は、吹き出し内に横一列の3点を明滅させます。点の位置と吹き出しの大きさはアニメーションで変えず、最初の文字が届いたら本文に切り替えます。生成中の案内文を本文の上に重ねません。会話画面を離れると明滅を停止します。読み上げでは「回答を作成中」を伝え、点の変化は読み上げません。失敗・中断は文字で表示し、その文も吹き出しの幅計算に含めます。

| 対象 | 保存する場所 | 内容 |
| --- | --- | --- |
| この端末 | `client.json` | 外観、avatarの位置・表示・サイズ・fps、ローカルVRM・VRMAと再生設定。将来の音声機器・音量・読み上げ切替 |
| コンパニオン | ホスト上のコンパニオン | 名前、共有する姿・声・性格、会話用・作業用AIの割当 |
| ホスト・外部接続 | クライアントの接続情報／ホストのサービス設定 | ホストへの接続と、ホストから利用するAI・音声サービスを区別。サービスの秘密情報はホストの資格情報ストア |
| 権限とデータ | 対象のコンパニオン・接続先・実行環境に対応する権限 | 送信先と用途、作業対象、操作範囲 |

ローカルパスは端末上の素材の場所です。別端末でも読める共有設定とは扱いません。将来は共有するモデル参照と、端末側のファイル解決を分けます。

## 複数のコンパニオン

1体の場合、日常の会話には選択欄を置きません。ホストから複数体が返る場合、会話領域を含む内容幅が1120×倍率以上なら左側に相手の一覧、それ未満なら会話の上部に選択欄を表示します。一覧は独立してスクロールでき、本文の読み幅は800×倍率を維持します。ホスト設定にも設定対象の選択欄を表示します。同じ名前の場合はIDを併記して区別します。選択を安定したIDで保持し、一覧順や名前の変更では対象を変えません。選択中の相手が削除された場合は送信を止め、選び直しを案内します。

履歴と下書きはコンパニオンごとに保持し、メッセージ送信・履歴取得・モデル割当・名前・送信許可に対象IDを渡します。処理中、受付確認中、未保存のホスト設定やAPIキーがある間は切り替えを止めます。ホスト設定の編集は明示的に元に戻すこともできます。APIサービスと資格情報はホスト共通、モデル割当と送信許可はコンパニオン単位として画面でも説明します。

現在の端末側の表示設定と描画プロセスは1体分です。相手の選択でVRMを切り替えることはありません。複数体の作成・同時描画は後続機能とし、その際はコンパニオンIDと端末側の表示インスタンスを関連付け、全体の外観設定と各個体の素材・配置を分けます。

## 操作の原則

`ui-ux-pro-max`のMinimalism、Error Recovery、Focus Statesを参照し、デスクトップ向けに適用します。WebのLP構成やモバイル専用の操作は採用しません。Slint用のスタック資料はないため、入力・フォーカス・描画はSlintの部品と実測で検証します。

細部は[FirefoxのAbout導線](https://support.mozilla.org/en-US/kb/find-what-version-firefox-you-are-using)、[KDEの入力部品とホバー表現](https://develop.kde.org/hig/getting_input/)、[GNOMEの標準メニュー項目](https://developer.gnome.org/hig/patterns/controls/menus.html)も参照します。モバイル向けの44ptという値をデスクトップ全体へ適用せず、文字量と入力手段に合う密度にします。

バージョンとクレジットは専用の「eneについて」に置き、設定の末尾とトレイから開きます。「外観」には表示を調整する項目だけを置きます。[Slint公式の案内](https://github.com/slint-ui/slint/blob/master/FAQ.md?plain=1)に沿ってAboutSlintを表示し、周囲の余白をリンクにしません。ページの切替で未保存の設定は破棄しません。

- 利用頻度で配置を決めます。会話と入力を主役にし、設定は必要なときに開きます。ホストの管理は会話画面と設定から開けます。
- ホストの稼働とアプリの接続を区別して表示し、入力を妨げる接続切れ・設定不足は操作の近くに表示します。保存結果・エラーはホバーせず読めるようにします。アイコンだけの操作は送信など文脈が明白な場所に限ります。
- 一般的な操作を説明する常設文は置きません。Enter／Shift+Enterの入力仕様はドキュメントに記載し、送信アイコンには短いツールチップと読み上げ用の名前を付けます。ラベルやボタンで分かる保存手順を本文で繰り返さず、未保存の変更・操作結果・進めない理由を必要な場面に表示します。同じエラーは一か所にまとめます。
- システムのライト／ダーク設定と日本語フォントを尊重します。補助文字・メッセージ・エラーにはテーマ別の意味付き色を使います。
- 会話の空状態では入力を促し、履歴を遡ったときには最新のメッセージへ戻る操作を用意します。
- 装飾アニメーションを追加せず、非表示の画面を操作対象にしません。

## 保存と即時操作

外観設定は、有効な項目を変更時に反映します。文字入力が不正な場合はその項目だけ保留し、入力の近くにエラーを表示します。反映済みの設定と配置は専用ワーカーが変更後300msで原子的に保存し、終了時にも未保存分を保存します。保存失敗時も反映済み値を維持し、未保存表示と再試行を提供します。

フォントとモデルの一覧は検索対応のセレクターにします。開くと選択欄自体で文字を入力でき、検索欄を別に追加しません。大文字・小文字を区別せず、空白で区切った各語の部分一致で候補を絞ります。上下キーは候補の移動、Enterまたは候補のクリックは確定、Escape・外側のクリックは取消です。検索や候補の移動だけでは下書きを変更しません。該当なしを表示し、一覧更新時も検索語と保存済み・一覧外の選択値を保ちます。候補行は仮想化して大量の一覧をスクロールできるようにし、長い名称はツールチップでも確認できます。

表示切替・中央へ戻す・描画再起動・再生状態・繰り返しは即時操作です。モーションは現在の実行状態を文字で表示し、再生・一時停止を1つのアイコン付きボタンで切り替えます。ボタンの幅は切替時も固定します。素材ファイルの変更も即時反映し、読み込み失敗は実行状態として表示します。設定には配置を含めず、編集中のドラッグを巻き戻しません。ファイル選択のキャンセルは変更せず、新しい編集後に届いた古い選択結果は無視します。

ホスト管理を開くだけでは、端末設定の下書きや会話を破棄しません。「会話に戻る」で同じデモの会話に戻れます。将来、異なるホストを選ぶ際には会話・権限・非同期応答の所属を接続先ごとに分離します。端末設定はホスト選択をまたいで保持します。

トレイが利用できる場合、×は非表示です。トレイがなければ×で終了処理に進みます。トレイは会話、設定、キャラクター、終了に分け、表示切替はチェック状態で示します。隠した後にトレイが消えた場合はウィンドウを復帰します。明示的なクライアント終了では描画を停止して回収し、ホストは終了しません。未保存の設定・未送信の文章・処理中の要求がある場合に、破棄して終了するか画面へ戻るか選択します。

## 接続とAI設定

ホスト画面は一覧を中心にし、状態と操作をホストのカードにまとめます。通常時はホストの稼働状態とこのアプリの接続状態だけを表示し、準備完了の案内文は出しません。会話へ戻る導線は画面上部の一か所だけです。[参考製品と採用理由](../research/references.md#host-management-ui)に基づき、追加操作とホストごとの操作を分けます。

| 状態 | 表示と操作 |
| --- | --- |
| ホストなし | 右下の「＋」でこのPCのホストを追加・起動して接続。現在はローカルホスト一台に対応 |
| ホスト停止・アプリ未接続 | カード内の「起動して接続」 |
| ホスト稼働・アプリ未接続 | カード内の「接続」 |
| ホスト起動中／接続・同期中 | 進捗表示と「接続を中止」。重複する接続ボタンは表示しない |
| 再接続待ち | 次の接続までの秒数と「再試行」 |
| 起動・接続失敗 | 失敗理由と「再試行」 |
| 接続済み・設定不足 | 「AI設定が必要」と「AI設定」 |
| 接続済み・準備完了 | 「接続済み」と「接続を解除」。追加の成功メッセージや会話へ戻るボタンは置かない |

詳細アイコンから、会話の準備状況、接続先URL、最終確認からの経過秒数、直近の接続結果、状態の再確認を開きます。認証トークンは表示しません。設定不足の具体的な内容も詳細で確認できます。進捗や対処が必要なエラーはカード上に表示します。

ホストの状態は会話の購読とは独立して確認します。非公開の接続情報を検証し、待受と認証付きの設定取得を確認した後、3秒待って再確認します。この確認はホストを起動せず、AIサービスにもアクセスしません。接続を解除した後も更新を続けます。起動・接続の中止はカード内に置き、小さいウィンドウでは操作を縦並びにします。キーボードで操作へフォーカスすると本文をスクロールし、その操作を表示します。再接続の残り秒数は毎秒読み上げません。

ホストへの接続と、ホストからAIへの接続を別の操作として扱います。「＋」「起動して接続」「接続」は、非公開の接続情報を検証してローカルホストの待受を確認し、未起動ならデスクトップと同じフォルダーの`ene-host`（`ENE_HOST_BIN`で変更可能）を起動します。起動中は操作の重複を防ぎ、最大10秒待って接続します。稼働中のホストは再利用し、不正な接続情報がある場合には起動しません。起動できなかった場合は理由と再試行の案内を表示します。接続の中止・解除やデスクトップ終了後もホストは稼働を続けます。起動中の接続中止でもホストを停止しません。接続解除後も会話の表示と入力中の文章を残します。

未確認の送信がある間は接続解除を無効にします。手動再試行は必要ならホストを起動し、既存の再接続ループを起こしてIdempotency-Keyを維持します。自動再接続ではホストを起動し直しません。接続失敗は理由と自動再試行予定を示し、設定画面やトレイからも接続状態を確認できます。

AI設定はサービス選択、APIキー、モデル選択の順です。送信許可の確認と変更は「送信許可」画面にまとめ、AIサービス画面に会話の許可状態を重複表示しません。項目群は画面幅にかかわらず上から下へ並べ、サービスを選んでからモデルを設定するまでの読み順を維持します。各項目のラベルと値は外観と同じ基準で横並び／縦並びにします。設定本文は840×倍率を上限にし、カテゴリと本文を一まとまりに配置します。通常の設定で接続先URLを編集する必要はないため、URLとプラグインの再走査は「接続の詳細」に収めます。モデル一覧の取得には資格情報とメタデータ送信許可が必要なので、モデル未選択でも接続先を保存できます。疎通確認は任意です。実行できない操作は無効にし、その前提を近くに表示します。

設定の見出しは短い項目名にし、設定済みでも初回の手順説明を繰り返しません。モデルは一覧とID入力を切り替えて使い、一覧がない場合は直接入力できます。提供元の一覧にない保存済み・手入力のIDも保持します。モデルの仕様と任意の接続テストは「モデルの詳細」を開いたときに表示します。APIキーや許可が足りないときだけ、一覧を取得できない理由を示します。外部送信や履歴の破棄など、判断に必要な情報は操作のそばに残します。

外観は自動保存の状態と失敗時の再試行を表示します。コンパニオン・AIサービス・送信許可は共通の操作欄を画面下部に固定し、右側に「元に戻す」「保存」を置きます。未保存・保存中・保存結果も同じ場所に表示し、狭い画面では状態をボタンの上に分けます。「元に戻す」は開いているホスト設定の下書きだけを戻します。

編集画面は`ui/widgets/settings/page.slint`の`SettingsPage`で作ります。ページ見出し・本文のスクロール・結果表示・保存欄をこのテンプレートが管理し、項目群は`SettingsSection`、項目行は`SettingField`、補足文は`SettingsSupplement`、補助操作は`SettingsActions`を使います。画面ごとに大きいタイトルや独自のラベル配置を足しません。ラベル幅と項目間隔は`UiState`の共通値を参照します。通常幅ではラベルと値を左右に揃え、本文幅が560×倍率未満では同じ入力部品を保ったまま縦並びにします。

接続、名前・口調、送信許可は別々の下書きとして保持します。AIサービスの「保存」は接続・モデルとAPIキーをまとめて反映します。キーの入力・環境変数の選択・解除は保存まで保留し、取消ではホストの資格情報を変更しません。モデル未選択でもサービスとキーを先に保存できます。保存成功時には対象の下書きだけを確定し、入力中のキーを消去します。処理中は重複操作を防ぎ、失敗時はキーを含む下書きと結果を残します。エラーはスクロール本文の外で折り返して読めます。権限の操作対象は選択した接続とコンパニオンであり、別のAI接続に切り替える前に編集中の許可を保存します。

送信許可はチェックボックスと文字部分で切り替えます。行の右側に残る空白は操作対象にせず、広い画面でも意図しない変更を防ぎます。文字部分と余白を実座標でクリックする回帰テストで検証します。

## 幅・文字サイズ・入力への対応

初期サイズは900×760、最小サイズは420×480です。DPIはSlintの論理座標で扱います。レイアウト判定の倍率は`max(1, 文字サイズ / 16)`です。

- 内容幅が640×倍率以上では文字付きの設定カテゴリを左に、それ未満では上部の選択欄に配置します。設定カテゴリと本文を合わせて最大1024×倍率に収め、大きなウィンドウでは外側の余白を広げます。カテゴリと本文の間隔は維持します。
- 外観・デスクトップ表示・モデルとモーションの設定は、どの画面幅でも上から下へ同じ順序で並べます。フォームは840×倍率を上限にし、幅に応じて各項目のラベルと入力だけを横並び／縦並びにします。画面の高さが低ければ本文をスクロールし、自動保存の状態表示は画面内に残します。リサイズでは入力部品を作り直さず、編集中の値を保持します。
- フォントはSlintが使うシステムのフォント一覧から選び、フォントと文字サイズの直後に「プレビュー」と明示した項目で日本語と英数字を表示します。サンプルには選択中のフォントと文字サイズを反映します。既存設定の未インストールのフォントも保持し、代替表示を案内します。
- フォーム幅が560×倍率以上ではラベルと入力を横並びにし、それ未満では縦に並べます。
- 送信ボタンは入力欄の右側に固定します。同じ入力コンポーネントを配置し直し、リサイズでIME・選択範囲・フォーカスをリセットしません。
- 会話本文は800×倍率を上限にして長い行を避けます。入力は内容に応じて伸び、画面の約3分の1と240×倍率の小さい方を上限に内部スクロールします。縦長の画面でも入力欄が履歴を占有しません。終了確認は中央の読みやすい幅に収めます。履歴を読んでいる間は新着で末尾へ移動せず、自分の送信時には末尾へ移動します。
- フォーム本文をスクロールし、保存操作は画面下に置きます。カテゴリ選択と即時操作は背景や枠を抑え、保存ボタンは内容に合った幅にします。保存と元に戻す操作には短い文字ラベルを付けます。狭い画面では保存状態を操作ボタンの上に分け、状態文を省略しません。長い説明・パス・エラーは折り返し、入力不正時は該当項目へ移動します。
- 通常の操作部品は高さ32論理px、アイコン16論理pxを基準にし、文字サイズや折り返しに応じて拡張します。ボタンは内容に合う幅と高さを基本とし、行全体の選択を表すナビゲーションだけ明示的に幅を広げます。クリック領域とホバー・フォーカスの枠を一致させ、余白では操作を発火しません。状態は文字でも表示し、非表示の画面の操作を無効にします。

## 音声・作業機能を追加する際の配置

音声入力は「押して話す」を基本として既定でオフにします。聞き取り中・応答待ち・発話中を文字でも表示し、テキスト入力と発言記録を利用可能にします。読み上げ切替、発話停止、作業停止を別操作にし、設定画面からも共通領域でアクセスできるようにします。現段階では利用できる音声ボタンを置かず、準備中と案内します。

ホスト設定の更新は対象ごとの保存とし、[ホストAPI設計](api.md)のrevisionで競合を検出します。資格情報登録、疎通確認、送信許可は別の操作として結果を表示します。

## 実装と検証

Rustのアプリ層が保存済み設定・下書き・会話モデル・稼働状態を保持します。Slintの`UiState`はその表示用の状態で、各画面に制御器を持たせません。ウィンドウと画面の稼働中は同じモデルと入力部品を保持します。

`just verify`は整形とClippy（テストを含む型検査）を実行します。テストは対象の挙動を変更したときに`just test`で実行します。合格済みの検査を変更せずに繰り返す必要はありません。

変更頻度の高い画面構成・配置の検査、開発用スクリーンショット出力とホスト起動の確認用フィクスチャは削除しました。初期のファイル選択・返信取得の確認用テストも削除し、クライアントには安全な接続情報の読み込みを検査するテストを残しています。画面を変更した際は必要な操作と表示を確認します。KDE/KWin上のトレイ表示、ネイティブIME、ポータルのファイル選択、モニター間のDPI変更は実機で確認します。
