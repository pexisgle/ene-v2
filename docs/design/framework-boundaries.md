# 実装時に安全性を引き継ぐ境界

この設計では、認可、処理の所有権、永続化、同期、画面への反映を、それぞれの機能実装から共通の境界へ移す。新しい機能はその境界の内側に追加する。以下は既存コードの契約であり、コピーして使うテンプレートではない。

## ホストの操作と永続化

公開入口は `ene_core::application::HostApplication`。Connectのサービスは保存互換型へ変換した入力を渡すだけで、更新タスクの所有、終了待ち、通知の発行を担当しない。内部の `operations` は外部から呼べない。受け付けた更新は `MutationExecutor` が所有し、呼び出し元を破棄しても完了まで実行する。受付の停止とタスク登録は同じロックで直列化する。更新の受付数は実行中を含め64件、明示停止は独立して8件、プロバイダー操作は待機中を含め8件。超過時は永続レコードを作る前に拒否する。

外部実行の種類は `OperationKind` の列挙で定義する。目的、送信データ、制限時間、出力上限は一つの `spec()` から得る。種類を増やすと、この定義と実行入力の網羅的な分岐の更新が必要になる。`InvocationInput` は会話、接続チェック、モデル一覧を区別し、モデル一覧に生成入力を渡せない。生成入力は `Generation::new` で検証し、ロールは `ChatRole`、履歴は完了した対話の組だけを使う。現在の入力と人格は切り詰めず、古い対話を組単位で外す。

設定、grant、チェック結果の書き込みは `application::commit` に集める。DBコミット後にキャッシュを置き換え、snapshotと共通の境界の下で通知を発行する。会話受付も同じモジュールで、DBの受付、実行登録、通知、後続の所有権を結び付ける。チェック完了は、principal、キー、HTTPメソッド、対象、入力、Pending、request IDを確認し、設定とreceiptを一つのトランザクションで確定する。更新行数が1件でなければ成功にしない。

メッセージ更新は `MessageUpdate` の列挙で表す。開始、Unicodeスカラー位置を指定した追記、完了、失敗、取り消しを混ぜられない。ユーザー行や終了済みの行には遷移できない。不確かな終了書き込みの再確認は、終了状態と失敗内容の完全一致で行う。後続の会話は終了状態の保存が確認できるまで開始しない。保存失敗が解消できなければホストを実行不可にし、`health.recovery_required` と通知に反映する。設定更新の保存失敗や受け付けた更新のpanicも、共通の障害遷移から `host.storage_failed` を発行する。保存できなかった設定を更新通知に載せない。リビジョンはチェック付き加算、通知番号が尽きた場合は新しいepochへ移る。

## プロバイダー、通信、資格情報

接続のkind・adapter・endpoint・optionsと実装revision・送信先・資格情報の要否は、ホストがfingerprintに必ず含める。アダプターは追加の制約を渡せるが、基本の同意範囲を省略できない。この契約変更前に保存したgrantは、起動時にinvalidatedへ移し、明示的な再同意を必要とする。

レジストリは `resolve()` で実装とポリシーをまとめた `ProviderBinding` を返す。操作途中で別の実装を取り直さない。現在の認可との照合は、送信直前、受信の前後、成功結果の確定直前で行う。取り消された操作は、再grantでも復活しない。待機中の会話は開始時のモデルと人格を使い、受付時に取り消された実行を再開しない。

外部HTTPは `ene-outbound::AuthorizedTransport` を通る。OpenAI/Rig、プラグインのbroker、公開カタログに共通する境界で、リダイレクトと暗黙の再送を無効にする。実装が受け取る `Invocation` には生の秘密を取り出すAPIがない。Core内部のtransportが認可済みURLとHTTPメソッドを検証して資格情報を付け、そのまま送信する。署名だけを行うAPIや資格情報付きリクエストを返すAPIは公開しない。`ene-outbound` はこの送信境界にRigのHTTP契約を適用する。公開送信先はモデル情報のGETだけを許し、生成本文や認証情報を付けない。通信エラーに資格情報付きURLを含めない。

資格情報の保存候補は、参照をDBへ結び付けるまで候補として所有する。途中で終了した場合、候補のDropはアプリケーションの削除ワーカーへ引き渡すだけで、非同期処理を独立して開始しない。削除は一つのワーカーが所有し、1回の試行を6秒以内とし、失敗を `health.credential_cleanup_pending` に残す。終了時に再試行しても削除できなければ成功終了としない。Secret Serviceのblocking処理も8件までに制限する。タイムアウトした保存がまだ動いている間は、削除のNoEntryを完了扱いにしない。タイムアウトしたblocking呼び出しはTokioから中止できないため、ホストのruntime終了待ちも5秒で打ち切る。起動時の読み出しは制御ロックを持たず、8並列・全体10秒以内で行い、遅れて得た古いキーで新しい登録や取り消しを上書きしない。

`test-support` は境界攻撃テスト用の明示的な機能。ホストと通信クレートのdev-dependencyでだけ有効にし、通常の依存で有効にしない。通常ビルドではInvocationの生成入口と生成入力の未検証入口を公開しない。

プロバイダーIPCは`ene-ipc::provider`のRemoc RTC契約を使う。モデル一覧と生成終了理由はRPC結果、生成テキストとHTTP応答本文はremote MPSCで流す。ホストは各Invocationに束縛した`HttpBrokerClient`を渡す。プラグインはrequest ID、grant、目的、資格情報を選べない。呼び出しのdropによる取消とclientのdropによるサーバー終了はRemocが扱い、ホストは制限時間と子プロセスの回収を所有する。PythonプラグインもPyO3製`ene-provider` SDKから同じ契約を使う。

## snapshot、SDK、デスクトップ

snapshotの予算はコンパニオン別ではなく応答全体で16MiB。設定の上限は4MiB、履歴ページは4MiB。実行中の応答と対応する入力を先に確保し、残りを履歴に配る。文字列は途中で切らず、外した行へ戻れるcursorを付ける。必須データだけで収まらない場合は `resource_limit` を返す。

`rules::evaluate` は実行入口、会話のreadiness、`HostService.GetAvailability` に共通する純粋な判定である。許可は granted / missing / partial / invalidated / unavailable、依存状態は別の値で返す。会話では対象接続へのモデル割り当てとモデルIDの検証も必要で、未設定・不正な場合は `model_unset`。接続テストとモデル一覧は割り当て前でも使える。モデルIDの検証は、設定保存、実行入力、モデル一覧、readinessで共通化する。UIはactiveなgrantの存在から実行可否を推測しない。接続テストとモデル情報のチェックボックスは、両方の操作への有効な認可がある場合にだけ有効許可として表示する。編集中の送信先と同意の版は、再読み込みでも置き換えない。

SDKの `SyncedSession` が、Connect購読の先頭snapshot→通知のバッファ→重複除外→適用→再取得を所有する。待ち手のキャンセルは適用タスクを止めない。通知は、適用済みの画面状態を公開してから渡す。入力バッファと通知キューはそれぞれ256件・16MiB、読み込んだ履歴は64MiBまで。番号の欠落、epoch変更、バッファ超過は新しいsubscriptionを要求する。`snapshot()` は適用済みcursorと同じ状態の本文を返し、可変本文をReplicaとSnapshotで二重に保持しない。通知・明示refresh・履歴追加は共通の公開境界で64MiBを検査し、超過した状態を公開しない。履歴再取得では取得済み本文を保持し、ページcursorは新snapshotの値から再開する。取得範囲の連続性を保証できない古いcursorや読み込み完了の `None` で欠落区間を隠さない。このため更新後に取得済みの行を再びページ取得する場合があり、IDで重複を除く。別のホストへ未確認操作を再送しない。

設定保存はSDKの `ConfigurationIntent` と `ConfigurationProgress` で、接続確認済み・割り当て確認済み・未確認を区別する。新規接続のIDとチェックのキーは再試行でも同じ値を使う。チェックの確認再送は120秒までで、再送前にhost IDを照合する。編集時の版を最新の版に自動で置き換えない。

デスクトップの `Command::policy` は受付区分、対象、編集対象、保存確定対象、フィードバックを一つの網羅的な分岐で決める。結果は対象とsessionを必須にした `ActionResultEnvelope` を使う。`HostUiModel` がコンパニオン・対象・要求ID・session・編集ID・u64版を照合する。Slintは編集を報告し、このモデルを表示する。資格情報だけを更新する操作は、未保存の接続設定を保存済みにしない。availabilityは取得中・取得済み・失敗を区別し、成功した要求だけを取得済みにする。同条件で失敗した場合は明示的な再試行、または「元に戻す」で再取得する。未取得中は送信許可の編集を無効化し、取得状況を表示する。長い接続チェックは独立した実行枠で所有し、通常の更新を直列化する枠を塞がない。

## アバターと検証

`LeasedFrame` は画像、入力領域、サイズ、scale、生成世代、連番、ring leaseを分離できない値。画面側はその内部を取り出せない。`AvatarPresenter` が現在の表示条件に一致する最新のフレームを選び、画像と入力領域を同じ提示で反映し、そのleaseを次の提示まで保持する。取得に失敗した場合は表示と入力領域を更新しない。マスクの容量超過時も、再計算に使う画像はキャプチャ済みの同じtextureである。

通常の検証は `just verify`、`just test`、`just build`。Vulkanを使うring・マスク再試行のテストは、GPUがある環境で次を明示的に実行する。

```sh
cargo test -p ene-avatar --locked gpu_overflow_preserves_captured_masks_and_leases_prevent_ring_reuse -- --ignored
```

回帰テストでは、待ち手の破棄、停止と受付の競合、許可取り消し、provider panic、receipt不一致、Unicode位置、複数コンパニオンの容量、同期中断・通知あふれ・番号欠落、編集状態の競合、リダイレクト、資格情報の秘匿、受信途中の認可変更、SSEの容量を検証する。実際のWayland提示とVRM/VRMAの動作は、ネイティブ環境でも確認する。

生成契約、端末操作のreceipt、表示lease、音声の取消世代とキューの上限は[Connectの境界](connect-rpc.md)に記す。新しい通信DTOをSerdeで重複定義せず、保存とプラグインとの変換を境界に限定する。
