# ホストへの接続とアクセス制御

状態：2026-11-08の暫定採用設計。**外部アクセス制御への委譲は未実装**で、現行実装はOwner Bearerのみ。利用者から見た動作は[ホストとクライアント](../features/hosting/README.md)、実装状況は[ホストREADME](../../apps/ene-host/README.md)を参照する。

## 目的と採用方針

eneは一人の所有者がローカルPC・自宅サーバー・VPSにホストを置き、複数のクライアントから使えることを目指す。アクセスを許可されたクライアントにはホストの同等の管理権限を与え、アカウント・ロール・端末別のホスト権限を自作しない。

**ホストへ到達できる主体の認証・アクセス制御は、OSまたは選択した遠隔接続サービスへ委譲する。** 安全な入口だけがホストAPIへ到達できる構成では、ene独自のOwner/Device Bearer、端末登録・承認・失効を重複実装しない。ただし「外部サービスがある」「HTTPSである」だけでは認証済みとはみなさない。認証なしAPIの提供は、入口への到達制限が実際に成立した場合だけ許す。保護できない構成では接続を拒否し、無認証の公開にフォールバックしない。

ホストAPIは接続方式に依存しないConnect RPCとする。ホスト固有のLLM・プラグイン・ファイル・端末操作の許可判定は[権限の設計](permissions.md)に従い、接続できることだけで端末内操作や外部へのデータ送信まで許可しない。

## 信頼する入口

| 経路 | 接続可否を保証する境界 | 条件 |
| --- | --- | --- |
| ローカル | ホストと同じOS利用者の保護領域、またはアクセス権を制限したローカルソケット等 | ループバックTCPは別OS利用者からも接続できるため、`127.0.0.1`だけを同一OSユーザー認証とみなさない。他のローカル利用者を含め全員を信頼できる場合に限り、単純なループバックHTTPを許容できる |
| Tailscale | Tailscaleによる接続元認証とtailnetのアクセス制御 | **Serve**を利用し、eneホストへの到達をGrants等で意図した主体に限定する。インターネット公開の**Funnel**を同等の保護経路として扱わない |
| Cloudflare | Cloudflare Tunnelと**Access**の認証・認可 | Tunnel単体は利用者認証ではない。保護されたAccessアプリだけを通し、可能な構成では`cloudflared`のAccess JWT検証も有効にする。ホストへの別の直接・無保護経路を作らない |
| その他 | 同等の安全なアクセス制御を提供するサービス・プロキシ | 認証・暗号化・到達制限・失効方法が確認できること。満たせないものは無認証ホストAPIの入口にしない |

Tailscaleのtailnetへ参加しただけではeneへの到達権を無条件に与えない。Cloudflare Accessのユーザー単位認証を「端末単位の取り消し」と同一視しない。ネットワーク経由で接続できる主体はホスト操作を全面的に実行できるため、外部のアクセス許可範囲を狭く維持する。

参考： [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)、[Grants](https://tailscale.com/docs/features/access-control/grants)、[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)、[Accessによる保護](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/)、[cloudflaredのAccess検証](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/origin-parameters/)。

## ホスト・クライアントと外部サービスの責務

- **クライアント**：接続先の選択・記憶、接続方式ごとの認証開始・ログイン状態の表示、通信経路の確立・切断を行う。接続方式を交換可能にするのはクライアント側であり、特定サービスへの依存を共通RPCへ持ち込まない。Tailscaleアプリの別途導入を許容し、可能な範囲でGUI設定を支援する。
- **ホスト外のサービス**：Tailscale Serve／`cloudflared`などをホストマシン上で実行・設定して、適切に制限した入口からホストへ転送する。これはene-host本体のWasm/ACPプラグインではない。ホスト側にサービス固有の認証ロジックを追加しない。
- **ene-host**：信頼された入口だけにConnect RPCを提供し、会話・設定・作業・端末操作の実効権限とデータ送信範囲を管理する。外部プロバイダーのトークンをホストの資格情報として無条件に受理したり、認証済みを装う任意のHTTPヘッダーを信頼したりしない。

接続元の追加・取り消しは外部サービスの管理機能で行う。eneのGUIからその管理画面へ案内できるようにするが、すべてのサービスで個別端末の承認・失効を自動化できるとは約束しない。切断済みの端末が再接続できないか、既存の長寿命接続がいつ終了するかは、各サービスの実際の仕様で検証し、保証できない場合は明示する。

## 安全性の境界と将来の未決事項

- ホストを直接インターネットまたは無制限のLANへ待ち受けさせない。プロキシ設定の誤り・Access保護の欠如・予期しない別ポート公開を検知できない場合は、認証なしへの移行を完了とみなさない。
- 複数の信頼されないOS利用者がいる共有マシンではループバックのみで保護したことにしない。ローカルソケットのアクセス権や適切なプロセス・ネットワーク隔離を検証する。
- **ローカルHTTPのブラウザ防御（Origin検証・DNS rebinding対策）**:
  ene本体のWeb版クライアントの有無にかかわらず、同一PC上のブラウザで開いた外部Webページからローカルホスト（`127.0.0.1`）へ不正アクセスされる脅威（DNS rebindingやCross-Origin fetch）を防ぐため、ローカルHTTPサーバーは `Host` ヘッダーの検証（`localhost` / `127.0.0.1` のみ許容）と予期しない外部 `Origin` ヘッダーの遮断を行う。また、保護が完了するまではOwner Bearerトークンによる認証を必須とし、ブラウザスクリプトからの無断APIアクセスを防御する。
- **ブラウザ版クライアント固有の機能は後回し**: Cookie・セッション・WebUI画面提供など、ブラウザ版アプリ特有の機能は将来の必要段階で定める。外部サービスのログインだけをブラウザAPI安全性の証明としない。
- **ヘッドレスVPSのGUI初期セットアップは未決**：最初のアクセス制御済み入口を誰がどう作るか（インストーラ、ホスティング管理画面等）は、GUIのみで完結させる目標とは別に具体化する。初期セットアップ時に無保護APIを一時公開して回避しない。
- インターネットに依存しないローカル利用を維持する。外部接続サービスの障害がホストのローカル機能・自律実行を止めない構成とする。

## 現行PR #10からの移行

現在の実装は、ループバックHTTPと`connection.json`のOwner Bearerだけで保護されている。Deviceトークン・端末登録・承認・失効・端末ごとのpermissionは削除済みで、端末操作は認証済みクライアントが要求の`device_id`で識別する。**外部アクセス制御への移行は未完了であり、Owner Bearerは維持する。**

移行時は、まずOS・外部サービスの到達制限と取り消し条件を実機で検証し、ホストを無保護の経路から利用できないことを確認する。その後、不要になったOwner Bearerを削除する。端末内のファイル・Computer useなどの許可と、遠隔操作の配送・結果・表示権管理は別責務なので、Owner Bearerの削除だけを理由に一括削除しない。移行が完了するまではOwner Bearerを維持する。
