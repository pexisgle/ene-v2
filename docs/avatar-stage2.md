# 第2段階：VRMキャラクターの常駐表示

## 実装

`ene-avatar`を別プロセスとして追加しました。Bevy 0.19.1＋bevy_vrm1 0.9.5は既定機能を無効にし、VRM、描画、シーン、アニメーション、PNG、型登録に必要な機能を選択しています。描画プロセスにWinit、UI、音声、ゲームパッドは導入していません。bevy_vrm1のシーン複製には`reflect_auto_register`が必要で、これを省くとモデルの読込が成功しても描画されないことを実描画試験で確認しました。

Smithay Client Toolkit 0.21.1でWayland layer-shellのTopレイヤーを作り、キーボード操作はNone、exclusive zoneは0です。非対応環境は会話画面にエラーを表示し、XWaylandへ切り替えません。

VRMA対応以前はBevyへネイティブハンドルを接続する構成を検証しました。現在はBevyで透明なオフスクリーンImageへ描画し、非同期GPU readbackで取得した画素をSCTKの`wl_shm`へ送ります。alpha > 8の画素を論理座標の横方向runへ変換し、**その画像と対応する入力領域を同じWayland commitで表示**します。直接GPUウィンドウへ描画してから遅れて入力領域を変える方式では、動く腕の古い輪郭がクリックを奪うため、この経路へ変更しました。描画結果は描画プロセスの中だけで扱います。

readbackは最大4件を並行処理し、遅着した古い連番を破棄します。初回・DPI変更・カメラ調整・一時停止境界では、寸法と世代が一致する結果だけを反映します。入力を受け付ける前にも現在の描画輪郭を確認します。輪郭外はクリック透過し、輪郭内のクリックは会話表示、ドラッグは右・下からの余白変更です。バッファの倍率と入力領域も同時に変更します。ドラッグではWaylandの相対ポインター移動を累積して、押下時の余白を基準に配置します。サーフェス相対座標を移動量へ再利用せず、同じ大きさのconfigureで描画先を再作成しません。相対ポインター非対応や相対移動を送らない入力では、ウィンドウを動かさず最新座標を保持し、ボタンを離した時に配置を反映します。

初期値30fps、設定で60fpsを選べます。非表示時はBevyとGPU資源を解放し、bufferのないlayerへ置き換えて描画を停止します。再表示時はモデルを読み直します。単にbufferを外してlayerを再利用すると、未処理のconfigure通知とunmapによるserialリセットが競合することが分かったため、roleを作り直します。終了・置換時は処理中のreadbackを排出し、250ms経過時点で次の反復を行いません。GPU呼び出しが応答しない場合は、親の3秒後の強制終了で停止します。

出力名・論理座標・整数buffer scaleを扱い、出力の取り外しでは残っている出力へ作り直します。小さくなった作業画面から位置が外れないよう余白を制限します。1.25倍などの非整数倍率はWaylandの整数buffer scaleとコンポジターの縮小で表示します。専用のfractional-scale/viewporterは使用していません。

VRMA 1.0の選択・再生・一時停止・繰り返しに対応しています。腰の静止位置をカメラの基準にし、水平の移動を固定して上下移動と回転を保持します。未選択時は初期ポーズです。詳しい挙動と検証は[VRMA対応](vrma.md)を参照してください。音声に連動する口の動きや対話から自動で選ぶモーションは後続段階です。

## モデル・設定・起動

```sh
just fetch-avatar
just run-desktop
# 描画だけを単独起動する場合
just run-avatar
```

固定された公式Seed-sanの取得元、SHA-256、ライセンス、クレジットは[モデル利用条件](../licenses/Seed-san.md)に記録しています。モデル本体は開発用キャッシュに置き、起動時にネットワークから自動取得しません。設定画面の「VRMを選ぶ」「VRMAを選ぶ」はSlintのアプリ内ファイル選択画面を開きます。フォルダ移動と直接パス入力に対応し、一覧取得の失敗や存在しないファイルは画面に表示します。VRM 0.x、埋め込みでない外部ファイル参照、壊れたモデルは拒否します。選択モデルの作者・利用条件URLを設定画面に表示します。

フォント、文字サイズ、VRM、VRMA、再生・繰り返し、表示、fps、出力名、右・下の余白を`$XDG_CONFIG_HOME/ene/client.json`へ保存します（未指定時は`~/.config/ene/client.json`）。0600の一時ファイルへ書き込み、同期してrenameします。保存失敗は設定画面または会話画面へ表示します。設定を閉じてから開き直すと、未適用の変更は保存済みの状態へ戻ります。

## IPC・監督

共通クレート`ene-shared`に`AvatarSettings`、`AvatarRequest`、`AvatarEvent`を置きます。標準入力・出力は最大64KiBのNDJSONで、ログは標準エラーへ送ります。資格情報、会話本文、画像フレームはこのIPCへ送りません。

要求は`configure { settings }`と`shutdown`です。configureでモデル、表示、fps、配置、出力をまとめて指定します。通知はready、position_changed、show_chat、visibility_changed、error、stopped、motion_state、motion_errorです。VRMAのエラーでは会話とVRMの静止表示を維持します。

UIの別スレッドが子プロセスを監督します。停止要求から3秒以内に終了しなければkill後にwaitし、再起動では旧プロセスを回収してから新しく起動します。子の標準入力をnonblockingにし、応答しない子が停止の制御経路を詰まらせないようにしています。SlintのコールバックがRcを保持し続けても終了できるよう、UIのイベントループ終了後に監督スレッドを明示的にshutdown/joinします。親の異常終了は標準入力のEOFで検知します。

トレイから表示切替・再起動・クライアント終了を操作できます。描画失敗は会話画面に表示し、再起動を用意しました。会話画面の×は従来どおりトレイへの非表示で、キャラクターはそのまま表示します。

IPC通知は`upgrade_in_event_loop`からSlintのイベントループを起こし、UIのスレッドで反映します。会話画面を隠した状態でもキャラクターのクリック通知を受け取れます。起動前に溜まった通知用に100msの補助タイマーも設けています。

## 検証

クラウドで起動した専用Sway 1.10.1（headless＋pixman）、Mesa LavapipeのCPUアダプター、Vulkanで実描画・入力を検証しました。実機KDE/KWinの検証とは区別します。ComputerUse用の操作可能なデスクトップはないため、Wayland仮想ポインターと実際のD-Busトレイ操作を使用しました。

- `just verify`: フォーマット、check、警告をエラーにしたclippy、テスト、全targetビルド。
- 自動テスト: alpha領域の穴とDPI、VRM 1.0・外部参照拒否、Unicode IPC、設定保存と権限、正常終了と3秒後の強制終了・回収。
- `just test-avatar-wayland`: 実モデル、輪郭外・内のクリック、ドラッグ、非表示・再表示、2倍・1.25倍の出力設定、出力取り外しと復帰、IPC EOFによる終了。
- `just test-avatar-client`: 実際のSlintクライアントを起動し、×で会話を隠して実際のキャラクターのクリックで会話を戻す操作、トレイで表示切替・再起動・終了、設定保存、旧子プロセスの回収、親の強制終了後のIPC切断と子の終了を確認。専用のD-Bus Watcherと一時設定フォルダを使用します。
- `just test-desktop-wayland`と`just test-desktop-tray`: Weston desktop-shellで既存の入力・会話・設定・トレイを回帰検証。

ポインター試験は`ENE_AVATAR_TEST_PRIVATE_COMPOSITOR=1`とHEADLESS出力のみのSwayを要求し、クライアント結合試験はさらに専用D-Busセッションを要求します。試験用の`test_pointer`・`test_tray`はexamplesで、アプリの実行依存ではありません。Python/Pillow/grimは開発検証だけに使います。

検証ログは[validation](validation/)の`avatar-stage2-2026-10-01.txt`へ保存します。画像は`target/avatar-seed.png`、`avatar-desktop.png`、`avatar-hidden.png`、`avatar-dpi2.png`、`avatar-dpi125.png`、`avatar-client.png`へ保存します（ビルド成果物のためGitへ含めません）。

## 待機時の資源使用量

リリース版を同じソフトウェアGPU環境で測定しました。VRMA対応後の結果は[測定JSON](validation/avatar-vrma-resources-2026-10-01.json)を参照してください。旧構成の測定も履歴として保存しています。CPUは複数コアの合算で100%を超えます。5秒程度の観測で、描画プロセス単独のPSSです。UI・ホストを含むアプリ全体の合計値やハードウェアGPUの値ではありません。非表示時のPSSにもアロケーター等の常駐領域が残ります。

GPUメモリはソフトウェアGPUのため未計測と記録し、メモリ上限を新たに設定していません。配布サイズは描画バイナリ単独の値で、モデル・UI・システムライブラリを含む配布物全体の値ではありません。

## 実機で残る確認

KDE/KWinの実GPU、実マウス、1.25／1.5／2倍の混在DPI、物理モニターの接続・取り外し、日本語入力とのフォーカス干渉、KDE上でのアプリ内ファイル選択、手持ちVRMの読み込み・利用条件確認が残っています。今回のクラウド試験の成功だけで、この実機受け入れを完了とはしません。ホスト接続・ファイル作業・音声・3日5件の実用評価は後続段階です。
