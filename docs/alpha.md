# Alphaホスト：範囲・実装順序・受入条件

状態：採用する設計方針（2026-11-03）。未実装・未測定の段階を含む実装計画であり、全体の動作完了の宣言ではない。ステップ1は実装・モック検証に加え、OpenAIとOpenRouterの実モデルで受入確認まで進んだ。ステップ2（人格と心の即時更新）は基盤を実装し、実モデルで受入確認した。ステップ3（自動記憶と検索）の基盤も実装し、通常の会話からの自動整理・自動想起・意味検索を実モデルで確認した。作業相手（ステップ4以降）は未実装である。旧[MVP](mvp.md)は歴史的資料として残し、本書を現在のホスト開発範囲の正本とする。

## 目的

クライアントの完成を待たず、会話、キャラクターの心、交換可能な作業相手、共有ツールが一連の動作として成立するAlphaを作る。主要な意味と責務を先に固め、細かな操作やUIの追加で中核を作り直さずに済む状態を目指す。将来の変更が一切不要になることは保証しない。

## 実装範囲

| 必須 | 到達点 |
| --- | --- |
| 親と推論 | 最新正式Rigを基盤にした会話・ツール反復、入力の追加、停止、永続化、通知 |
| 人格・心 | 小さな人格の核、関連する側面・例・背景、根拠付きの経験と解釈、現在感情、関係性・成長の保存と利用 |
| 自動記憶 | 即時更新に加えて、保存済みの新しい経験が自動の増分整理へ渡る。語句と意味を使った自動想起と追加検索 |
| 作業相手 | 内蔵の簡単な子と外部接続一系統。継続的な指示・相談・報告、別件の並列実行、個別停止 |
| ツール共有 | 同じ認可付きホストツールを親・内蔵の子・外部の子で利用する |
| 権限と認証 | Rig等の既存機構を優先。ホストへの到達はOS・外部接続サービスのアクセス制御へ委譲し、ツールの操作許可とは分離する。新規許可と任された範囲内の判断を区別し、取消と制限の実効範囲を示す |
| API | クライアントから会話・心・作業・設定・相談・停止を扱える。UI内にオーケストレーションを実装しない |

再考予約の最小機構は含める。全文の定期配信サービス、画面見守り、複数端末の実運用、Windows/macOS全対応、本番音声・デスクトップUI、汎用ファイルワーカーの全操作、すべての外部ハーネス対応は後回しにできる。ホストと端末の所在、送信先、操作権限を混ぜるAPIにはしない。

記憶や感情は型だけの仮実装ではなく、実際の会話・作業へ反映させる。巨大な心理シミュレーター、固定の好感度式、毎発言ごとの複数の心理判定モデル、独自の汎用オーケストレーター・OSサンドボックス・ポリシーDSLは初期の必須にしない。

### ホスト接続認証の移行（一部実装、外部入口は後続工程）

[ホスト接続の設計](design/host-access.md)に従い、将来のホストAPIは安全なローカル入口または外部アクセス制御済みの遠隔入口だけに公開し、独自の端末登録・Owner/Deviceトークンを二重に保持しない方針とする。複数端末の実運用はAlphaの必須ではない。現在の実装はloopback上のOwner Bearerだけで、Deviceトークン・端末登録・承認・失効・端末ごとのpermissionは削除済み。**外部入口の検証とOwner Bearerの削除は未完了であり、無条件の無認証化はしない**。

検証条件：未認証・公開入口からの到達を拒否し、Tailscale Serveの限定されたGrantsまたはCloudflare Tunnel＋Accessの保護（Tunnel側のAccess検証を含む）、保護を迂回できる直接経路がないことを確認する。ローカルでは信頼するOS利用者の範囲を確認する。取り消し後の新規接続拒否と既存接続の終了条件を実測し、満たせないプロバイダーは保証を付けずに表示する。Web対応は別途検証する。

## 実装手順と終了条件

### 1. Rigへの接続

固定版のモデル接続、受信箱、ツール、保存、停止、Wakeを一人の親へ接続する。現行Rig依存からの変更量、Tokioとの接続、待機時CPU、保存失敗・途中停止の扱いを確認する。AvatarのBevy Appとは結合しない。

終了条件：実モデルと一つの無害なツールで会話が通り、追加入力を失わず、停止が推論待ちにならず、待機中にLLMとフレームを回し続けない。同じ状態を二つの実行管理が所有しない。

<a id="alpha-step1-implementation"></a>
#### 実装記録（2026-11-03、PR #10）

- 採用版：Rig v0.46.0（公式リリース 2026-10-31）。`rig-core`・`rig-http`・`rig-ecs`・`rig-memory` を0.46.0で`Cargo.lock`に固定した。調査基準v0.46.0と一致することをリリースとcrates.ioの索引で確認した。
- 実行管理：`rig-ecs`の`AgentPlugin`・`SessionLogPlugin`を専用のヘッドレススレッドで動かし、コンパニオンごとに一つの親エージェントを持たせた。受信箱（`Incoming`/`Deliver`）、ターン、モデル呼び出し、ツール呼び出し、停止（`StopTurn`）、セッションログをRigへ委譲した。AvatarのBevy Appとは別のAppで、描画・フレーム更新を持たない。
- 入力と保存：追加入力は`Steer`で受信箱に入れ、ターンの次のモデル呼び出しへ届ける。会話・受信箱・ターンはRigの`DirStore`セッションログ（`<state>/rig`）へ保存し、履歴取得はそのログを読む。SQLiteから旧メッセージ表への書込みは行わず、旧行は削除しない（会話の移行はしていない）。
- 停止と起床：`Stop`はカーネルへの停止要求を渡した時点で完了し、モデル応答・ツール完了・実行枠の空きを待たない。待機中は起床シグナルと最大1秒の期限だけでフレームを回し、固定周期の推論を行わない。
- モデル接続：認可済みHTTPトランスポート（既存の送信先・資格情報・取消境界）をRigのモデルへ渡す。親の会話は当初、組み込みOpenAI（Responses API）とRigカタログ上のツール対応モデルに限定した（追加受入でOpenRouterを加えた。下記）。Wasmプロバイダーは接続確認・タスク推論で継続利用するが、親会話経路には未接続。資格情報はRigへ渡さず、送信境界で付与する。
- 認可と取消：各送信とストリーム受信で、現在の設定・資格情報・送信許可を再確認する。設定・資格情報・送信許可の変更は、実行中のターンを停止し、次の入力時にモデル連接を作り直す。
- 保存失敗：セッションログの書込み失敗をホストの`HostHealth.recovery_required`へ反映し、新しい会話の受理を止める。停止・失敗・未確認を成功へ変換しない。
- API：`SendMessage`は受理ID（`request_id`）だけを返す。ユーザー発言・返答は`MessageCreated`、実行の開始・終了は`TurnEvent`、文字片は`MessageDelta`（`stream_id`）で通知し、確定内容は`GetHistory`/`GetMessage`で取得する。旧`MessageStarted`/`MessageUpdated`と応答メッセージIDは削除した。
- 検証（モック）：スクリプト化モデルで、ツール1回を含む会話、処理中の追加入力がモデルへ届くこと、ツール実行中の停止が2秒以内に完了すること、待機400msのフレーム数が10未満であること、セッションログ書込み失敗が通知されること、再起動後の会話復元を確認した。ホストAPI統合テストで、受理・通知・履歴・同一要求キーの再送・停止・送信許可取消・再起動を通した。組み込みOpenAI Responsesの本番接続経路は、ローカルのSSEサーバーを相手に、認可済みトランスポート・リクエスト先・資格情報付与・ストリーミング解釈を通した。いずれもスクリプト化した応答で、実際のモデル品質や外部サービスは確認していない。
- 未確認：実モデル・実資格情報での会話（この環境に許可された設定がないため未実施）。会話文脈の自動圧縮・要約、Wasmプロバイダーの親会話経路、旧メッセージの移行は未対応である。

#### 追加受入（2026-11-03、実プロバイダー）

上の実装記録の「未確認」のうち、実モデル接続を次の条件で確認した。検証用の一時stateディレクトリ・一時コンパニオンだけを使い、既存データは変更していない。鍵はリポジトリの `.env` から検証プロセスが読み、ホストの通常の資格情報APIへ渡した。値・Authorizationヘッダー・`.env`全体は出力・保存していない。会話は合成の短い文だけである。

- 経路：実ホストプロセス（`ene-host`）を一時`XDG_RUNTIME_DIR`/stateで起動し、認証付きConnect RPCで接続・資格情報・Grant・モデル割当を設定した。`SendMessage`で受理し、Rigカーネルが実プロバイダーを呼び、`current_time`ツールを実行し、結果をモデルへ戻し、最終応答を保存した。Rigのセッションログでツール要求（`"current_time"`）とツール結果（`"type":"toolresult"`と時刻）を直接観測し、文章だけでは判定していない。
- OpenAI：モデル`gpt-6-luna`（Rigカタログのツール対応・低コストモデル。既存の組み込み指定）。2ターン（初回はツール往復を含む2回のモデル呼び出し、追撃1回）。取得できたusageは入力473・出力69トークン、Rigカタログ単価からの参考コスト0.0000818 USD。追加試行を含む呼び出し回数は別記する。
- OpenRouter：組み込みのOpenRouter接続（OpenAI互換Chat Completions）を追加し、OpenRouter自身の`/api/v1/models`・資格情報・送信先許可で`google/gemini-2.5-flash-lite`を呼んだ。2ターン・3回のモデル呼び出し。取得できたusageは入力444・出力70トークン、参考コスト0.0000724 USD。OpenAIの接続設定は流用していない。
- 共通の確認：`MessageCreated`・`MessageDelta`・`TurnEvent`の対応、確定テキストがツール結果の時刻と一致すること、次の発言で前の会話が引き継がれること、SIGTERM→再起動後に`GetHistory`で4メッセージが復元されること。
- 未取得：上記2回の成功シナリオ以外の試行のusageは一時領域の削除で失われ、記録していない。料金はプロバイダーの請求額ではなく、Rigがカタログ単価から計算した参考値である。

#### OpenRouterとプロバイダー拡張

- OpenRouterはRigのネイティブ接続（`OpenAIConfig::with_key(&OPENROUTER, ...)`とChat Completions）を親の会話に追加した。ホストのOpenRouter記述子・資格情報・送信先許可・モデル一覧（`/models`）を持つ。Rigカタログにあるモデルはその能力を使う。
- カタログにないモデルの制限は「未知＝非対応」とせず、接続の`options`の`{"tool_calling": true}`を明示した場合だけ、その宣言を根拠にツール対応として扱う。`false`は`model_cannot_call_tools`、指定なしは`model_capability_unknown`として区別する。未知のモデルを推測で対応済みにはしない。
- 現行Wasmプロバイダーは一つの推論のストリーム変換であり、ハーネスのツールループではない。ワイヤには`GenerationRequest.tools`と`Event::ToolCall`があるが、ホスト側アダプターは`tools: Vec::new()`を固定し、`ToolCall`を未対応として拒否し、ホストの`Generation`/`ChatMessage`はroleとtextしか運べない。ツール対応WasmプロバイダーをRigへ接続するには、ツール定義・ツール呼び出し・ツール結果を往復するホスト側契約と、Rigの`Serve`ハンドラーへの薄い変換が必要である。別のエージェントループは不要で、Rigがターンとツール実行を保持できる。前回の「別ループの複製が必須」という記述は、契約の不足とループの複製を混同していたため訂正する。
- OpenRouterの接続確認（`CheckConnection`）とタスク推論の単発生成は未接続で、呼ぶと明示的に非対応を返す。親の会話受入の判定とは別である。

#### 追加の不変条件（2026-11-03）

- 出力上限：ストリーミング文字数の上限に加え、RigのReview段階で確定前の返答文字数を検査する。単一の巨大イベントで上限を超えた返答は保存・通知せず、ターンを`output_limit`の失敗にし、入力を`RecalledInput`でクライアントへ返す。回帰テストで、返答メッセージが通知されず、履歴に残らず、入力が返ることを確認した。HTTP本文の8MiB上限は別の防御である。
- 受付と保存：`SendMessage`の受理は、Rigが入力を開始し、そのフレームのセッションログ書込みが成功した後に返す。セッションログが書けない場合は受理せず、エラーにする。再起動後に残った未確定の会話レシートは、同じ`request_key`の再送時にRigの保存済み会話・受信箱を`request_id`で照合し、見つかれば元の受理を返して再配送せず、見つからなければ503で確定する。この経路と二重配送がないことを統合テストで確認した。別の`request_key`で送り直した場合の重複は、元の受付応答を受け取れなかった場合に区別できないため残る。
- 待機時CPU：NixOS / x86_64、リリースでない標準テストビルドで、初期化1秒後から10秒間を観測した。CPU時間0.020秒（0.20%）、フレーム10回（1回/秒）、Rigの起床0回。1秒周期の期限起床は、遅延した再試行・期限確認のためのもので、完全休眠だけを目的に新しいスケジューラーは作らない。
- 旧SQLiteメッセージ：旧`messages`表は撤去し、会話の正本はRigのセッションログだけにした。履歴migrationは単一baselineへ統合し、旧版DBは起動時に明示的に拒否する。開発用DBは再作成する。
- 外部型の所有：Harnessの`SessionUpdate`は`agent-client-protocol-schema`の型を直接使い、独自5 variantとACP mapperを持たない。5種類以外はruntimeのvalidatorが拒否する。Bevyの未承認パスは`Deny`とし、クライアントが選んだmodel/motionのロードだけ`override_unapproved`する。

#### ステップ1の判定

OpenAIの実ホスト経路とOpenRouterのネイティブ接続で、実モデル・無害なツール1つ・ストリーミング・確定履歴・追撃・再起動を確認した。ステップ1の必須条件「少なくとも一系統の実モデルと無害なツールを通す」は満たした。追加入力・停止・取消のタイミング依存の性質は決定論的モックで確認しており、実モデルで同じタイミングを再現したとは扱わない。未対応はWasmプロバイダーの親会話接続、OpenRouterの接続確認・タスク推論、文脈圧縮、実クライアントUIである。ステップ2（人格と心の即時更新）へ着手できる状態だが、本変更では開始しない。

<a id="alpha-step2-implementation"></a>
#### ステップ2の実装記録（2026-11-03、PR #10）

著者設定と実体験・現在の心を分離し、親の通常のRig推論から心を更新・参照できる最小経路を実装した。会話の実行管理・ターン・ツール実行は引き続きRigが持ち、第二のエージェント実行基盤は追加していない。心と記憶の正本はSQLite、会話の正本はRigのセッションログである。

- 人格の核は既存の`Companion.mind`、側面・会話例・背景・表現語彙は`mind_companions.profile`に保存する。会話例は「実体験として記憶しない」とプロンプトで明示し、記憶テーブルへは自動的に入らない。著者プロファイルと権限は、モデル用の更新要求型からフィールドとして存在せず、`serde`の未知フィールド拒否で拒否される。
- 記憶は`mind_memories`、現在の心は`mind_companions.state`、操作の適用結果は`mind_operations`に保存する。`SourceRef`（受理入力・記憶・操作）、`MemoryRecord`（内容・評価・取得方法・出所・記録時刻・発生時刻・関連・訂正・想起優先度）、`MindState`（感情・関係・傾向・気にかけていること）、`MindChange`（操作ID・更新元・revision・記憶追加・訂正・心の変更）の意味を保持する。型ごとの独立テーブルや汎用traitは作っていない。
- `mind_update`は、所有者・操作ID・入力出所・更新元（親）をホストの実行文脈から束縛する。1回のSQLiteトランザクションで記憶・現在の心・操作記録を確定し、同じ操作ID・同じ内容の再試行は元の結果、同じID・異なる内容は競合、古いrevisionは競合として、部分変更を残さない。操作記録には更新元と出所も保存し、ツール結果の記録が失われた後に同じ内容・同じ入力出所で再送された場合は、新しい操作IDでも適用済みの結果を返して二重適用しない。変更なしも成功結果として記録する。参照する記憶IDは同一コンパニオンの所有物かを検証する。
- 親には`mind_recall`（検索）、`mind_read`（詳細・出所・訂正関係）、`mind_update`（構造化更新）をRigのツールとして接続した。mindツールを持つのは最初の（Alphaでは唯一の）親コンパニオンだけで、他の親・子・外部MCPには公開しない。現在の心の概要はsystem promptへ毎回入れ、呼び出しのたびに状態取得を強制しない。
- `mind_update`のコミット後、同じターンの次のモデル呼び出しへ現在の心とrevisionを反映する。モデルの再接続・ターン停止は行わない。接続時はSQLiteからプロンプトを再構成するため、会話用モデルの変更・再起動でも心は初期化されない。
- 検索は、クエリ全体と日本語文字bigramをSQLiteの`LIKE`で照合する最小の語句検索である。固定結果や全件返却ではない。FTS5・意味検索・自動想起・自動整理はステップ3に残した。
- ホストAPIに`GetMind`（著者プロファイルの核と追加材料、現在の心、profile/stateのrevision）と`UpdateMindProfile`（追加材料の著者編集。既存の`UpdateCompanion.mind`が核）を追加し、保存成功後に`MindUpdated`を通知する。`mind_update`の保存成功時にも通知する。記憶一覧のクライアントUIは未実装である。

- 未対応・ステップ3へ残すもの：自動整理ジョブ・自動想起・FTS5/意味検索・忘却・共有プール・古い整理の競合解決。今回はそれらの常設エージェント、汎用ジョブ基盤、空のモジュールを作っていない。ただし記憶の出所・操作ID・revision・更新元・取得方法・訂正関係は保存しており、後続の整理処理が同じ`mind_update`検証・トランザクションを再利用できる。

#### ステップ2の判定

終了条件「会話から記憶と現在感情を更新し、次の判断と表示用状態へ反映する。再起動しても保持でき、架空の会話例が実体験へ混入しない」は、機械検証と実モデル受入の範囲で満たした。ただし自動記憶・自動整理・長期的人格品質は未完成であり、ステップ3の完了を意味しない。

### 2. 人格と心の即時更新

終了条件：会話から記憶と現在感情を更新し、次の判断と表示用状態へ反映する。再起動しても保持でき、架空の会話例が実体験へ混入しない。

#### ステップ3の前提修正：呼び出し文脈（2026-11-03、PR #10）

心ツールの所有者を、共有された「現在のコンパニオン」と設定順の先頭で選ぶ方式から、**呼び出しごとの不変な文脈**へ変更した。

#### ステップ3の実装記録（2026-11-03、PR #10）

通常の会話から、親が保存ツールを呼ばなくても経験が整理され、後の会話で自動的に想起される経路を実装した。常設の第二人格や汎用ジョブ基盤は追加していない。Rigの親カーネル、既存のSQLiteトランザクション、認可付きトランスポート、タスク推論・埋め込みを使う。

- **自動整理**：`TurnFinished`後に起動する有限のホストワーカーが、処理済み`(last_sequence,next_offset)`の**直後から前向きに**Rigの会話を取得する。`next_offset`はその発言で次に処理する文字位置（末尾=完了）であり、途中と完了を同じ順序で比較する。最新側からページを取って古い順に並べる方式ではないため、未処理がページ上限を超えても古い分を飛ばさない。既に適用済みの範囲は`advanced=false`として過去結果を返し、成功通知を繰り返さない。各発言は`status=completed`を確認する。受理済みユーザー発言は失敗したターンでも経験として残し、失敗・停止・未完了のアシスタント文は実際に話した内容にしない。300ms待ちやTurnFinished通知だけの確定推測は行わない。1メッセージが8,000文字を超える場合は文字オフセットで分割し、`next_offset`が末尾に達するまでそのメッセージを処理済みにしない。2,000文字で切り捨てない。10,000文字の発言を8,000+2,000に分け、SQLite適用、別接続での再起動、同じ範囲の再送まで通す接続テストを持つ。
- **ページ走査**: 1ページの対象外フィルタが空でも終端しない。失敗・停止したアシスタントは終端としてカーソルを進め、未確定の応答は待つ。ユーザー発言はターンの状態が未確定なら待ち、完了ターンの応答が見えるまでユーザーだけの記憶を作らない。走査は有限ページ数で、終端だけを飛ばした場合はmodel jobを増やさず`skipped`に数える。
- **指数バックオフと再開**: 整理・埋め込み・索引保存は、一時障害のみ有限回（5秒/15秒/60秒/300秒相当）再試行し、権限不足・未設定・不正結果は即時に停止状態へ置く。`mind_index_pending`の`next_attempt_at`を使い、5秒tickで同じ失敗を無限に呼ばない。設定・Grantのcommitは`mind_retry_index`で待ちを解除し、新入力や再起動をユーザーに要求しない。
- **整理の生成**：専用の**memory purpose**と`data=["memory"]`のGrantで、コンパニオン自身の接続・モデルを使う。タスク割当・タスクGrantとは結び付けないため、作業接続を変えても記憶処理の可否・モデルは変わらない。確認済みの出来事に加え、人格の核・側面・例（作者材料と明示）、現在の心、今回の経験に関連する既存記憶（意味検索と語句検索）、忘却済みの既知記憶を渡す。出力は完全なJSONだけを受理し、最初の`{`から最後の`}`を拾う救済はしない。`memories`と空でない`reason`を必須とし、`{}`や欠損を変更なしにしない。Rigの終了理由を取得し、正常終了・打切り・通信失敗・不正生成・権限不足・競合を分ける。一時障害と不正生成は同じ実行内で有限回だけ再試行し、5秒ごとの無制限再試行はしない。失敗はobservableな状態にし、新しい確定入力・設定変更・再起動で再開する。
- **原子的な適用**：生成された記憶と処理済み位置を**同じSQLiteトランザクション**で確定する。処理済み範囲は操作ID（companion + from + through + method revision）で識別し、再試行は元の結果、同じIDで異なる内容は競合。生成失敗・保存失敗・memory revisionの競合ではカーソルを進めない。memory revisionは記憶の変更だけを対象とし、親の気分だけの変更では進まない。変更なしは成功としてカーソルを進める。
- **書き込み範囲**：自動整理は記憶の追加・訂正だけを行い、現在の感情・関係・作者設定・許可を直接上書きできない（`actor=consolidation`のstate変更をstoreが拒否）。古い整理は記憶の版（memory revision）の競合で適用されず、再生成される。記憶の版は記憶の追加・訂正・忘却/共有で進み、親の現在感情だけの変更では進まないため、無関係な気分の変化で整理バッチ全体を失敗させない。公開範囲は広げない。忘却済み・共有解除済みの記憶を復活させない（整理はその優先度・audienceを変更しない）。
- **索引と検索**：正本の記憶挿入と同時に`mind_index_pending`へFTS/vectorの索引待ちを入れる。FTS5（trigram）と埋め込み（OpenAI `text-embedding-3-small`、1536次元）を小さなホストワーカーが更新する。索引の失敗・遅延は正本・カーソルを失わせない。検索はFTS語句とベクトルのcosineを**RRF**で統合し、生スコアを足さない。候補はcanonicalのowner/audience/recall_preference/時刻で再検証し、古い索引が忘却・共有解除を破らない。索引が未処理・短い語・FTS失敗時はcanonical LIKEのfallbackを使い、検索不能を「該当なし」と混同しないため結果に`lexical`/`semantic`/`pending`/`reason`を返す。
- **意味検索の構成**：LanceDBは追加せず、SQLiteの正本と`mind_vectors`（memory id・model・dimension・前処理版・vector blob）に保存したベクトルの厳密cosineで実装した。Alphaの単一ホスト・少数記憶ではネイティブ依存を増やさず、同じ想起契約・RRF・canonical再検証を保てるためである。索引backendはstore内に閉じており、規模・評価で不足すればLanceDBやRigの検索統合へ同じ契約のまま置換できる。埋め込みのHTTP要求・応答変換は自作せず、RigのOpenAI embedding wireへホストの認可付きトランスポートを渡す。検索時はmodelと前処理版を照合し、次元不一致のベクトルを混ぜない。model/前処理/次元を索引に結び付け、会話モデルや感情の変更で再埋め込みしない。埋め込みモデルはOpenAI `text-embedding-3-small`の能力制限付き既定値で、設定・索引識別へ接続する。OpenRouter接続の埋め込みは未対応（明示的にsemantic unavailable）。
- **自動想起（完了経路）**: acceptは入力の保存確認後に返り、対象のモデル要求だけを`HoldOf`で保留する。ホストの非同期検索タスクが完了すると、通常の`Signal::Command`でカーネルへ結果を送り、カーネルは対象のrequest idのプロンプトを確定してholdを解除する。検索結果、現在の心、入力IDは同じ処理で構成する。停止時はカーネルがholdを解放し、遅延完了は送信済み要求を書き換えない。語句/意味検索はこの経路で自動投入される。
- **自動想起（旧記述）**：accept時に**ローカルSQLiteの語句検索だけ**で最大3件を選び、`runtime.deliver`より前に外部埋め込みを待たない。検索遅延や外部障害で配送順・停止の意味を変えない。想起結果はコンパニオンごとの短いプロンプト状態に保持し、mind.updateや自動整理の通知が現在の心を再合成しても、そのターンの想起を消さない。プロンプト合成は想起後に最新のMindStateを読み直す。入力が長い場合も200文字制限で無効にせず、4,000文字の予算と`query_truncated`の可視状態を使う。検索対象の有無に関係なく毎入力で埋め込みを呼ぶことはしない。意味検索は親の`mind_recall`で行い、失敗時は`lexical`/`semantic`/`pending`/`reason`を返す。全記憶を毎回渡さず、気分だけで候補を絞らず、検索回数だけで記憶を強化しない。
- **訂正・忘却・共有**：`ControlMemory`（forget/remember/share/unshare）を追加した。忘却は`recall_preference=forgotten`で通常想起から外し、物理削除しない。忘却済み記憶を`supersedes`/`sources`で参照する新しい記憶は、storeが`forgotten`として保存し、同じ根拠からの通常記憶の復活を防ぐ。共有の公開範囲は**本文・説明・ appraisal・訂正関係のid**であり、私的な入力出所は共有先へ渡さない。共有元の訂正関係は所有者の記憶から計算するため、共有先が共有記憶を読んでも関係が消えず、非公開の訂正本文は`mind_read`で取得できない。共有解除後はcanonicalのaudience再検証で、古いFTS行が残っていても返さない。共有・忘却は所有者だけが操作できる。
- **API・状態**：`MindView`に索引状態（FTS/vector待ち、埋め込みmodel・呼び出し数・トークン数）と整理状態（last_sequence、jobs、model_calls、input_chars、error/unconfigured）を追加した。`ControlMemory`は記憶id・audience・recall_preference・revisionを返す。
- **再起動・停止**：処理待ち・カーソル・索引待ちはSQLiteに残り、起動時にワーカーが再開する。親の停止は実行中の整理の完了を待たない。整理・索引のワーカーはホスト終了時に止まり、未コミットのバッチはカーソルを進めず再実行できる。
- **モデル要求の境界と所有**: 入力受付時に`SetMindPrompt`でローカル語句結果をagentへ置き、対象モデル要求だけ`HoldRecall`で保留する。非同期検索完了は`RecallCompleted`を通常のSignalで送り、カーネルがrequest idの`ModelRequest`とagent `SystemPrompt`を最新の心＋想起で確定し、holdを解除する。停止・期限切れ・キャンセルは`RecallCancelled`/Stopでholdと未適用結果を破棄し、遅い完了は送信済み要求やagent状態を書き換えない。検索結果がモデル要求より先に着いた場合はカーネル側のpendingに保持し、要求が現れたGateで適用する。試作のPromptState/版付きブリッジは削除した。
- **資源**：待機時は5秒周期の確認と通知だけで、定期tickが行うのは索引待ちの確認だけである。整理の失敗は5秒ごとに再試行せず、新しい確定入力・設定変更・再起動で再開する。全履歴を毎回処理せず、処理済みカーソル直後から1ページずつ読む。自動想起は埋め込みを呼ばず、意味検索は親の`mind_recall`と整理の関連記憶取得だけが埋め込みを使う。

##### 自動意味想起の現在地

- 正常・早期完了・停止・重複/遅延完了を接続テストで確認。早期結果はpendingとして保持し、モデル要求のGateで適用。停止後・二重完了では再送しない。
- 古い`StoredMind`を保持した`publish_mind`を適用前に待機させ、新しいprofile適用後に遅れて完了させる`a_stale_mind_publish_cannot_overwrite_a_newer_model_prompt`を追加。`publish_mind`はホスト内prompt sequenceで古い全文を無視する。
- モデル入力は「最新の人格・心（agent SystemPrompt）」＋「対象入力の想起一枠（RecallSection）」から一度だけ合成する。検索完了は想起フラグメントでその一枠を置換し、追記しない。これにより古い全文・古い「該当なし」・語句/意味の想起欄が併存する経路を削除した。完了・早着とも保留解除は失わない。ホスト内の単調なprompt sequenceを`SetMindPrompt`で比較し、古い全文の後着を無視する。実際に直接モデル接続へ渡した要求で新profileのみを確認。
- `unix_seconds`はRFC3339解析失敗時に実時間へ置き換えずエラーとし、旧テストの`"now"`値を有効な時刻へ修正。テスト時計はプロセスstaticではなく`HostApplication`のワーカー時計に限定。
- 検索失敗・期限切れのローカル結果保持、モデル一度だけ、遅延完了の非再送は`automatic_semantic_recall_holds_the_model_until_the_embedding_completes`で確認。検索中のMindProfile更新が最終モデル入力を巻き戻さないことも同テストで確認。
- 履歴接続は`consolidation_connection_walks_a_page_boundary_into_sqlite_cursor`一本で、テストページサイズ1のユーザー/次ページ応答、同一ターンへ同時受付したSteer二入力、失敗終端の後の確定入力、9000文字超の長文末尾＋後続短文を実際の`pending_messages`→batch→`mind_consolidate`→SQLiteカーソル→次回走査へ通した。失敗終端ユーザーをWaiting扱いして後続を止める分類不具合を修正し、終端範囲の再適用がないことを確認。

- 旧PromptState/版付きブリッジは削除した。active_request/active_recallとSetMindPrompt/RecallCompletedの所有・寿命は接続テストで確認。完全な構造一本化はしていない。

### 3. 自動記憶と検索

未処理範囲からの有限の整理ジョブ、自動想起、全文・意味検索、索引更新待ちを追加する。訂正、忘却、共有、版の変更を正本で検証する。記憶の形成が親の任意の保存操作だけに依存しないことを確認する。

終了条件：明示的な記憶依頼なしに関連情報が形成される。遅い整理が現在感情を巻き戻さず、再試行で重複せず、古い索引から非公開情報が漏れない。元情報の圧縮と整理待ちの関係を確認する。

### 4. 「手」（WorkSession）の協調プロトコル・同一キャラクター対話・進捗途絶検知

親（頭）と同一キャラクターとして振る舞う作業エージェント「手」を接続する。大掛かりな枠組みを強制せず、自然言語による軽量指示から実務まで柔軟に委託できるプロトコルを確立する。

- **WorkSession と Run の分離**: `WorkSession ≒ ACP Session` として外部プロセス接続と文脈を維持し、`Run ≒ ACP prompt turn` として指示を実行。通常のRun中断は ACP 標準の `session/cancel` を送信し、プロセス強制終了はセッション終了時や30秒タイムアウト時のみ実施。内蔵Rigはホスト内Tokioタスクとして実行。遅延完了通知による状態上書きを防止。
- **同一キャラクター一人称対話**: 「裏で作業してくれているみたい」等の第三者表現を排し、一人称（「私が今〜しているよ」）で報告・対話する。
- **定期進捗報告と途絶検知**: 「手」は定期的にActivity/Messageを報告し、報告が途絶した場合はホストが親（頭）へコンテキスト注入イベントを行い、親が自発的に進捗確認できるようにする。ターミナル等の待機中は中断して新指示を注入。
- **安全な中断と30秒タイムアウト強制終了**: 中断要求（CancellationRequested）時に子が協調的に一時ファイルを整理。外部ACPハーネスやプロセスが30秒以上応答しない場合はホストが強制終了（Kill）。送信済みメール等の巻き戻せない副作用はUndo可能と偽らず「取り消し不能」として報告。
- **実務スキルの分離**: `skills/<name>/SKILL.md` は「手」のみがオンデマンドで取得・実行し、「頭」のプロンプトを圧迫させない。

終了条件：軽量な自然言語指示と複数ステップ実務の両方が一人称で通ること。Run A中断後のRun B実行中に遅れたAの通知が状態を上書きしないこと。応答不能なプロセスが30秒タイムアウトで強制終了されること。

### 5. セッション管理・Compaction・静的先プロンプト順序

長時間の対話を破綻なく継続するためのコンテキスト圧縮と、Prefix Cachingヒット率を最大化するプロンプト構築順序を実装する。

- **追記型線形ログ ＋ `rig-memory` によるCompaction**: 会話履歴および要約（`Compacted`）は `rig-ecs` の `SessionLogPlugin` ＋ `SessionStore`（`DirStore`）を正本としてディスクに保存。ディスクへの完全な線形追記ログと版スナップショットで管理し、SurrealDBへの要約二重保存は行わない。
- **厳密なアイドル検知**: ユーザーの操作・発話不在時間のみをカウントし、コンパニオン自身の自発的独り言・見守り発話はタイマーをリセットしない。
- **割り込み耐性とPre-compaction継続**: バックグラウンドCompaction中にユーザー発話があった場合、Compaction完了を待たずに直前履歴（pre-compaction state）から即座に応答を返し、実行中Compaction結果は破棄/次回延期する。
- **機械的コンテキスト上限検証と縮退動作**: 送信直前に `Total Input + Max Output <= Context Window` を機械的に検証。要約失敗・トークン超過時はアクティブプロンプト窓から最も古い未要約メッセージを一時的に切り詰めて対話を継続。
- **静的先・動的末尾のプロンプト順序**: `Tools` ➔ `System Persona` ➔ `Pinned Core Memory` ➔ `Compaction Summary` ➔ `Recent Dialogue History` ➔ `Dynamic Context` ➔ `Latest User Turn`。

終了条件：アイドル時Compactionおよび連続発話時の強制Compactionが正常に作動すること。要約処理中の割り込み発話に対してpre-compaction履歴から遅延なく応答が返り、トークン上限を超過しないこと。動的コンテキストが履歴の後ろに配置され、Prefix Cacheが保護されること。

### 6. 記憶データモデル拡張とSurrealDB（SurrealKV）移行

心・記憶・関係性の表現力を高めるため、組み込みSurrealDB（SurrealKV）を採用し、エピソード記憶のデータモデルと想起スコアリングを実装する。

- **組み込みSurrealKV**: C++依存のない完全Rust製ストレージにより、Windows/macOS/Linuxで単一フォルダ永続化を実現。
- **MemoryRecordスキーマ不変条件**: `owner`（作成者コンパニオン不変保持）、`audiences`（共有先リスト）、`importance`（1〜10: 想起優先度）、`memory_revision`、`embedding_model`、`embedding_dimensions` を保存。
- **想起スコアリング**: $\text{Score} = 0.5 \cdot \text{Relevance} + 0.3 \cdot \text{Importance} + 0.2 \cdot e^{-0.05 \Delta t}$ によるHNSWベクトル検索と重要度・時間減衰の統合。
- **引用ガード（汚染ループ防止）**: 応答メタデータや明示操作（`mind_read` 等）で明示的に引用された場合のみ `last_accessed_at` を更新し、アイドル時整理で重要度再評価に活用。
- **Pinned Memory保護**: 重要度10であっても、優先度引き下げや訂正状態を必ず検証し、専用トークン予算（1,000トークン）内で注入。
- **認知グラフ関係性**: `companion->remembers->memory`、`memory->cited_in->turn` のグラフエッジを構築。遅延した自動整理ジョブが優先度引き下げ済みの記憶を元の優先度で上書きする競合をトランザクション内で拒否。

終了条件：SurrealDB上で記憶の作成・更新・HNSWベクトル検索が動作すること。未引用の想起でアクセス日時が更新されないこと、時間経過や優先度引き下げによる忘却（スコア低下）と重要度による保持が機能すること。優先度引き下げ済み記憶がPinned枠や再整理で不当に復活しないこと。

### 7. 権限・クロスプラットフォームSandbox・自動判定エンジン

安全性と自律性を両立する3層セキュリティアーキテクチャを実装する。

- **OSネイティブ隔離**: Linux（Landlock/bwrap）、Windows（AppContainer/Job Objects）、macOS（Seatbelt）によりファイルシステムとネットワークを隔離。
- **Sandbox非対応環境の縮退動作**: OSの分離機構が利用できない環境では、非隔離環境で実行される旨をユーザーに明示警告し、承認を得てから実行（無断実行の排除）。
- **多層判定パイプライン**: ハード禁止/毎回確認 ➔ 機械的ルール照合（パス・コマンドの完全一致） ➔ 入力遮断型AI補助判定 ➔ ユーザー承認 ➔ 実行直前検証。
- **承認要求の不変束縛**: 要求に対象操作の引数ハッシュを束縛し、引数改変時は承認失効。音声承認は同時に1件のみ有効（誤爆防止）。
- **「常に承認」の二元管理**: パス/ポート等の物理権限はSandbox構成へ直接追加し、セマンティック操作は構造化ルールとして保存。

終了条件：引数改変時に承認要求が失効すること。複数承認待ちがある場合に音声での一括誤承認が防止されること。Sandbox非対応環境で警告カードが提示されること。

### 8. 知覚（目）・リアルタイムモーション・音声パイプライン（拡張マイルストーン）

デスクトップ常駐コンパニオンとしてのリアルタイムな知覚・表現・流暢な音声対話を完成させる。
> **スコープ境界**: 本ステップは、Alphaのコア対話・実務エージェント・記憶・基本Sandbox（ステップ1〜7）を完了した後に、デスクトップ透過クライアント（`ene-avatar`）および本番音声エンジンを結合する拡張フェーズとして段階的に検証する。

- **「目」のハイブリッド知覚**: OSイベントフック ＋ 15〜30秒アイドルサンプリング、客観事実と推測の分離、動的Watcher（`set_eye_watch`）による優先割り込み通知。
- **リアルタイムモーション直接指示**: 発話中だけでなく、傾聴時やアイドル時にも親（頭）から `body_motion` を単独即時呼出。Bevy ECSでのVRMAクロスフェード合成とフレーム連動RMSリップシンク。
- **プラガブル音声パイプライン**: 採用TTSエンジンの仕様（VOICEVOX等の文単位HTTP API、ストリーミング、双方向Live API）に適応。
- **世代管理と順序制御**: `generation_id` による割り込み時の旧世代チャンク破棄（FlushBuffer）、文単位TTS並行合成時の `sequence_no` 整列再生、切替後の旧発話失効による逆戻り防止。
- **複数コンパニオン調停**: STT同報配信、各頭脳による自律該当性判断、着手時の同報通知（`work_started`）と同時着手時の後発側自律キャンセルによる作業重複の自律解消（ホスト受付排他は行わずLLM自律協調）、音声フロアの先着ディスパッチ、掛け合いリレーの上限制限（最大5往復）と安全なフロア解放。

終了条件：TTSエンジンの仕様に即した低遅延な初声再生と先行合成。割り込み時の旧世代音声バッファ破棄。発話時以外の単独モーション再生。複数コンパニオン間での作業重複の自律解消と掛け合いの正常終了。

| アイドル計測の厳密性 | コンパニオン自身の自発的独り言や定期tickはアイドルタイマーをリセットせず、ユーザー無操作時間のみを測定する |
| 音声世代管理と単一再生 | FlushBuffer発行後に遅れたチャンクを破棄し、クライアント側で同時に複数音声が鳴らず、切替後の旧発話チャンクが破棄され、実再生進捗が報告されること |
| 作業重複の自律解消 | 複数コンパニオンが同時に着手した場合、開始時刻が遅い側が自ら `cancel_work` を発行して重複が自律解消されること（ホスト受付排他は行わずLLM自律協調） |

体験評価では同じモデル・予算・履歴で、人格と履歴のみ、人格の側面と例、即時記憶、自動整理と持続する心を段階的に比較する。初対面、好みの自然な学習、協働の失敗と成功、後日の想起、訂正、一部共有、実務の再依頼を通す。固定台詞の一致ではなく、根拠の連続性と人格・関係・感情・記憶を別に評価する。[研究根拠](references.md#alpha-evaluation)

形成・検索・利用を混同しない。保存されなかった記憶、検索で落ちた記憶、渡したのに誤用した記憶を区別する。匿名の独自キャラクターも使い、モデルが有名キャラクターの名前から知識を補う効果を分離する。

性能は、追加推論数・トークン、初回応答と停止の遅延、待機時CPU、検索・索引構築中のメモリ、保存量を測る。数値目標は実測前に作らず、評価記録に環境・モデル・版を添える。品質の改善なく処理が増える要素は採用しない。

## 2026-11-09 ホスト書き直しの実装記録

`apps/ene-host` を `apps/ene-host-test` の最小構成を土台に書き直した。1つのヘッドレスRig Appを専用スレッドで動かし、APIからの読み書きを `Runtime::call` で直列化し、SQLiteは1接続、外部通信だけを非同期にした。`application` / `domain` / `ports` / `infrastructure` の層、独自エラー型、非同期DB、汎用レシート機構は削除した。

- 契約：`host.proto` を `HostService` / `ChatService` / `SettingsService` / `WorkService` / `ClientService` に置き換えた。`ene-plugin` が使うモデル記述型はクレート直下へ再exportする。
- 会話：Rigの `AgentPlugin` / `SessionLogPlugin` とセッションログを正本にし、受理は同一フレームのログ書込み成功後だけ返す。未確定レシートは再起動後に照合する。通知は `TurnEvent` / `MessageDelta` / `ConversationChanged` / `RecalledInput`。
- 心・記憶：`mind_recall` / `mind_read` / `mind_update` をホスト束縛の開いたツールとして登録し、所有者・入力出所・操作IDをホストが決める。記憶と処理済みカーソルは同じSQLiteトランザクションで確定する。自動整理は確定ターンだけを対象にした有限の `ModelRequest` 効果で、`memory` 許可とコンパニオン接続を使う。検索はFTS5 trigram。意味検索・埋め込みは後続。
- 設定・許可：組み込みのOpenAI Responses / OpenRouter Chat、資格情報ストア、送信許可（purpose / data kind / destination / fingerprint）、可用性を実装した。設定・許可・資格情報の変更は実行中のモデル呼び出しのpermitを失効させる。
- 作業：親の `start_work` が子エージェントを生成し、`send_work` / `stop_work` / `list_work` / 子の `report` を持つ。子は親の心・履歴・心ツールを持たない。ターン終了時の報告は `reported_run` で一度だけにする。
- 端末：`client_id` で端末を区別し、1コンパニオンにつきアクティブ端末1台。能力は端末が提示し、ユーザー許可済みのものだけ端末操作に使う。操作は `pending` / `dispatched` / `completed` / `uncertain` / `failed` を持ち、切断後の自動再送をしない。
- 検証：`cargo test -p ene-host` の単体・結合テスト、`--test process` の実プロセス（discovery、Owner Bearer、SIGTERM）、`cargo clippy -- -D warnings` を通した。実プロバイダーの受入は通常テストに含めない。
- 後続：意味検索・埋め込み、スケジュール、Web検索、音声、パッケージ、ACP/MCP/Wasm、ホスト側fs/terminal、汎用承認UI。Alpha設計のうち、これらを除くホスト側の範囲を実装した。

## 2026-11-10 実プロバイダー確認（簡易）

一時state/runtime（0700）と `ENE_HOST_SESSION_CREDENTIALS=1`（キーチェーンへ書かない）でホストを起動し、Connect APIを直接呼んだ。確認したのは次の経路である。

1. `ListProviders`：`kind` が `llm` として広告される。
2. `UpdateSettings`：`adapter` と `kind` を明示した接続を作成（設定revision 1→2）。
3. `RegisterCredentials`：セッション内だけに保存し、`credentialState` が `registered` になる。
4. `CheckConnection`：実OpenAI APIからモデル一覧を取得（96件、上限4 MiBの範囲内）。
5. `CreateGrant`：`https://api.openai.com` と `data_kinds=["conversation"]` の許可を作成。
6. `RevokeCredentials`、SIGTERMでの停止、`connection.json` の削除。

会話の往復は確認していない（コンパニオンのモデル割当を実在するモデルIDに合わせていないため）。鍵・Authorizationヘッダー・本文は出力していない。

## 2026-11-10 監査修正の実装記録

[実装監査](reviews/ene-host-audit-2026-11-10.md)のA1–A5段階1、B1–B12、C1–C14を、`apps/ene-host` に最小の差分で反映した。コミットは分割せず、作業ツリーで `cargo fmt --all -- --check`、`cargo clippy -p ene-host --all-targets --all-features --locked -- -D warnings`、`cargo test -p ene-host --locked`、`cargo test -p ene-host --test process --locked` を通した。テストは43件（ライブラリ）と1件（実プロセス）。

- **A1（致命的）**：`Database` の `Mutex` を `try_lock` にし、再入を `internal("database re-entered")` として返す。`ControlMemory` はトランザクション内で `Tx::get` / `Tx::get_memory` だけを使う。再入と忘却・共有の回帰テストを追加した。
- **A2・A3（高）**：`streams` は `With<TurnCall>` の呼び出しだけを配信し、`CallOf` からターンを引く（`ActiveTurn` に依存しない）。`chat::role_of` を追加し、ホスト注入の文脈を `context` として返す。`HistoryRequest.include_context` を追加（既定`false`）。自動整理は利用者の発言・モデルの返答・作業報告だけを読み、`[作業報告]` を付け、`acquisition` を許可リストで検証する。
- **A4（高）**：`PRAGMA user_version` を版とする連番migration（`src/host/db/migrations/001_baseline.sql`）。旧ベースラインDBは `user_version = 1` として引き継ぎ、未知・より新しいDBは拒否する。2件目以降の前に `VACUUM INTO` で `*.bak-v<版>` を作る。
- **A5（高）**：`PrepareSystems::Fit` の `fit` が `ModelRequest.history` を窓に収め、`max_tokens` を全モデル呼び出しに設定する。窓が不明なら刈らず `Notice` を出し、未整理の範囲が落ちたら整理を優先する。段階2の圧縮は `mind/summary.rs` で、落ちた範囲を `memory` 許可の別呼び出しで要約し、エージェントのコンポーネントに持って次の要求の先頭に置く（保存keyは増やさない。再起動後は最初の刈り込みで作り直す）。会話の正本と `GetHistory` は変えない。失敗は `Notice` を出して窓だけで続行する（[設計](design/compaction.md)）。
