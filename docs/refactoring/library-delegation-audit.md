# ライブラリAPI委譲の監査

## 対象と結論

ワークスペース全体の当初63項目の監査を完了しました。33項目の適用可能な変更を実装・検証し、非互換または既に委譲済みの30項目は根拠付きで見送りました。部分委譲を含む判定であり、アプリケーション全体に不具合がないという認定ではありません。

利用者向けの保存形式、承認と世代の結び付け、プラグインの認可境界は、置換の前提条件です。保守者向けには、各判定、変更コミット、固定バージョンのAPI根拠、検証範囲を[監査台帳](<../../docs/refactoring/library-delegation-audit.json>)へ残します。

T06は、外部のkillコマンドをrustixへ置き換えるテスト基盤の変更です。単なるテスト追加とは区別しています。H03、H07、H08、T08、T09などは部分委譲です。アプリケーション固有の予算、カーソル、命名、認可、所有権は残しています。

T09はワーカー単位の単一エントリーキャッシュとクリップごとのリセットです。FixedSync::Inputと、従来の丸めたサンプル数へのtruncateは残しています。有限長処理の全委譲や、クリップごとの全メモリ確保の削除は主張しません。

プラグインの実経路検証では、要求モデルの上書きと、表現できない生成オプションの黙殺も修正しました。対応できないtemperatureやtool choiceなどは、ゲスト呼び出し前に拒否します。ABIを拡張したり、別ベンダー用のJSONへ注入したりしていません。

## 検証

Linuxでワークスペース全体の整形、型検査、strict Clippy、全機能テスト、全ターゲットのビルドを実行しました。RPCのネイティブとWasmについて、client機能の有無をそれぞれ検査しました。Wasmの参照プラグインとOpenRouterプラグインもビルドしました。

通常テストでは、ホスト189件とプロセス2件、Avatar21件、ランタイム47件と結合17件、RPC1件、VRM23件が通過しました。新規ビルドした参照Wasmの結合1件と、GPU3件は別途明示して実行しました。外部STTの既存テストと無関係な無効化済みdoc例を、実行済みとは扱っていません。

実プロセスでは、HTTP/1とHTTP/2、JSONとprotobuf、認証、ページング、通知順、設定とレシートの再読込、MCPのstdioとHTTP、所有子プロセスの終了、遅延STT、承認と世代の結び付けを確認しました。描画側はWayland上の実行ファイルでポインター15項目とモーション7項目を確認しました。

承認モデルは2クライアント、1移動などの上限内で検査しました。4不変条件を満たし、4変異モデルはそれぞれ意図した違反を検出しました。承認後かつdispatch前の移動を公開APIから強制した実証ではありません。

## 残る制限と既存挙動

- Windowsのターゲット検査・実機とmultiseatは未実行です。
- 同一バッチ内での素早いポインター削除・復帰によるphantom clickは、Avatarのベースラインでも再現します。今回修正したポインター機能消失時の回帰とは別です。
- bwrapがない場合は、従来どおりIsolation::Missingを通知して非隔離で起動します。既存の[ホストREADME](<../../apps/ene-host/README.md>)の「拒否する」という説明とは一致していません。監査中に隔離方針を変更していません。
- プラグインの認可は資格情報のスナップショットを使用します。ブローカーハンドルは呼び出しやキャンセルをまたげます。失効だけでは配送済みキューを撤回しません。呼び出し単位の完全な隔離は主張しません。
- 移動後に新しい世代向けの承認カードが再発行される挙動は、単一承認のモデル外です。観測したカードを承認しても、既に拒否された呼び出しはdispatchされませんでした。
- 実クラウド、外部ACPエージェント、物理デバイスの操作、長期負荷とリーク、速度向上は検証・主張していません。

実プロセスで見つかった次の3件は、変更前のd26a49bをクリーンビルドして再現しました。今回の置換による回帰ではありませんが、未修正の既存不具合として残っています。

- HTTP/2でHostヘッダーがない場合、foreign・userinfo・不正portのauthorityを検証しません。有効な所有者Bearerは必要です。
- 重複Originでは先頭値だけを判定します。これも有効なBearerが必要です。ブラウザーからの実際の攻撃や未認証アクセスを実証した結果ではありません。
- 再起動すると復元済みエージェントの役割を認識できず、同じIDで作り直してretired/resetを追記します。会話履歴が見えなくなり、同じチャットキーで新たな受付とモデル呼び出しが発生します。再起動しない対照では履歴・受付・呼び出し数を維持しました。物理的なJSONL削除ではありません。SQLのmindレシートとメモリーIDは独立に永続化を確認しました。

このため、認証境界と永続化全体が正常という結論にはしていません。未修正の問題を直ったことにしたり、置換の成功と混同したりしていません。

## 判定を再検査する

```sh
direnv exec . python3 scripts/verify-library-delegation.py --self-test
direnv exec . python3 scripts/verify-library-delegation.py
```

検査スクリプトは、63件の網羅、全件の最終判定、実装コミットの祖先関係と実際の変更ファイル、検証と独立レビューの記録を確認します。テスト追加だけの完了扱いを拒否します。動作の正しさそのものは、回帰テストと実プロセスの証拠で確認します。

## 判断に用いた原則

Laziness Protocolにより、非互換な置換や新しいキャッシュ階層は追加しませんでした。Model the Domainにより、状態と所有権を既存の型、ハンドル、列挙型で表現しました。Prove It Worksにより、実行ファイルと実プロセスの読み戻しを要求しました。Attack the Premiseにより、共有ビルド出力を正しいと仮定せず、ルート専用のビルド領域と実行ファイルのハッシュへ検証を切り替えました。
