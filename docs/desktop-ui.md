# デスクトップUI

eneの通常ウィンドウは1つです。「対話」と「設定」を切り替え、avatarは別の透明な常駐ウィンドウに表示します。ウィンドウを隠してもクライアントの制御は継続します。会話画面はコンパニオンへの入力・発言確認を担当し、ホスト接続・描画・将来の音声の寿命を所有しません。

## 対話と設定

起動時は「ホスト選択」を表示します。ホストを選んだ後に「対話」を開き、設定画面の「ホスト選択」から入口へ戻れます。クライアント終了もホスト選択画面にまとめます。通常画面ではヘッダー右側の控えめな「設定」から設定画面へ移り、設定画面では「対話に戻る」で戻ります。対話を始める前に端末設定を開いた場合は「ホスト選択に戻る」を表示します。画面幅を占める切替ボタンは置きません。avatarやトレイのクリックは対話を開き、対話を開始する前はホスト選択を開きます。設定を開く際に新しいOSウィンドウは生成しません。文字入力、会話の閲覧位置、設定の下書きとカテゴリは、画面を切り替えても維持します。

設定は「この端末」「コンパニオン」「ホスト・接続」「権限とデータ」に分けます。現在編集できるのは端末設定です。実ホストの接続は準備中です。`--demo`で起動した場合は選択画面から「対話を始める」を選べます。デモの表示は対話画面上部にまとめ、入口・設定・各返信に説明を重ねません。通常起動時はホストの未対応状態を表示し、端末設定と終了を利用できます。実接続済みのようには表示しません。ホストへの画面接続・設定更新は準備中であり、他のカテゴリから架空の更新を行いません。

| 対象 | 保存する場所 | 内容 |
| --- | --- | --- |
| この端末 | `client.json` | 外観、avatarの位置・表示・サイズ・fps、ローカルVRM・VRMAと再生設定。将来の音声機器・音量・読み上げ切替 |
| コンパニオン | ホスト上のコンパニオン | 名前、共有する姿・声・性格、会話用・作業用AIの割当 |
| ホスト・外部接続 | クライアントの接続情報／ホストのサービス設定 | ホストへの接続と、ホストから利用するAI・音声サービスを区別。サービスの秘密情報はホストの資格情報ストア |
| 権限とデータ | 対象のコンパニオン・接続先・実行環境に対応する権限 | 送信先と用途、作業対象、操作範囲 |

ローカルパスは端末上の素材の場所です。別端末でも読める共有設定とは扱いません。将来は共有するモデル参照と、端末側のファイル解決を分けます。

## 保存と即時操作

フォームの変更は下書きに保持します。「保存」で検証・永続化した後に外観と描画へ反映し、設定画面に留まります。失敗時は下書きとエラーを残し、保存済み値と稼働状態を変更しません。「変更を戻す」で最新の保存済み値へ戻ります。

表示切替・中央へ戻す・描画再起動は即時操作です。これらは設定の下書きを保存しません。フォームから変更された項目だけを最新の設定へ反映するため、編集中のドラッグや表示切替が後の保存で巻き戻りません。ファイル選択のキャンセルは変更せず、破棄・保存や新しい編集後に届いた古い選択結果は無視します。

ホスト選択に戻るだけでは、端末設定の下書きや会話を破棄しません。「対話を続ける」で同じデモの会話に戻れます。将来、異なるホストを選ぶ際には会話・権限・非同期応答の所属を接続先ごとに分離します。端末設定はホスト選択をまたいで保持します。

×は非表示です。トレイが利用できなければ画面を残し、ホスト選択画面から終了できます。トレイの「ホスト選択・終了」も同じ入口を開きます。明示的なクライアント終了では描画を停止して回収し、ホストは終了しません。未保存の変更がある場合だけ、破棄して終了するか画面へ戻るか選択します。

## 幅・文字サイズ・入力への対応

初期サイズは720×760、最小サイズは420×480です。DPIはSlintの論理座標で扱います。レイアウト判定の倍率は`max(1, 文字サイズ / 16)`です。

- 内容幅が640×倍率以上では設定カテゴリを左に、それ未満では上部の選択欄に配置します。
- フォーム幅が560×倍率以上ではラベルと入力を横並びにし、それ未満では縦に並べます。
- 狭い対話画面では入力の下に送信ボタンを置きます。同じ入力コンポーネントを配置し直し、リサイズでIME・選択範囲・フォーカスをリセットしません。
- 入力は内容に応じて伸び、画面の約3分の1を上限に内部スクロールします。履歴を読んでいる間は新着で末尾へ移動せず、自分の送信時には末尾へ移動します。
- フォーム本文をスクロールし、保存操作は画面下に置きます。カテゴリ選択と即時操作は背景や枠を抑え、保存ボタンは内容に合った幅にします。操作領域44pxと見た目の強調は分けて扱います。長い説明・パス・エラーは折り返し、入力不正時は該当項目へ移動します。
- 操作領域は44論理px以上を基本とし、文字サイズに応じて拡張します。状態は文字でも表示し、非表示の画面の操作を無効にします。

## 音声・作業機能を追加する際の配置

音声入力は「押して話す」を基本として既定でオフにします。聞き取り中・応答待ち・発話中を文字でも表示し、テキスト入力と発言記録を利用可能にします。読み上げ切替、発話停止、作業停止を別操作にし、設定画面からも共通領域でアクセスできるようにします。現段階では利用できる音声ボタンを置かず、準備中と案内します。

ホスト設定の更新は対象ごとの保存とし、[ホストAPI設計](api.md)のrevisionで競合を検出します。資格情報登録、疎通確認、送信許可は別の操作として結果を表示します。

## 実装と検証

Rustのアプリ層が保存済み設定・下書き・会話モデル・稼働状態を保持します。Slintの`UiState`はその表示用の状態で、各画面に制御器を持たせません。ウィンドウと画面の稼働中は同じモデルと入力部品を保持します。

`just verify`で設定互換性、保存失敗、ライブ操作との競合、遅着ファイル選択、終了確認、レスポンシブ配置と日本語入力を検証します。ソフトウェア描画による実フォントのレイアウト試験も含みます。KDE/KWinでの実機確認ではトレイ、IME変換、DPI変更、OS標準ファイル選択、常駐表示を確認します。

Waylandセッション上のスモーク試験は通常のテストから分けています。ユーザーの設定を変更せず、一時設定でトレイ、非表示からの復帰、avatar制御、終了確認と描画プロセスの回収を確認します。

```sh
cargo build --locked -p ene-avatar
ENE_AVATAR_BIN="$PWD/target/debug/ene-avatar" \
  cargo test --locked -p ene-desktop native_wayland_window_tray_and_avatar_smoke \
  -- --ignored --nocapture --test-threads=1
```

IME変換中の実際のキー操作、OS標準ダイアログでのファイル選択、モニター間の移動によるDPI変更は、KDE/KWinで手動確認が必要です。自動試験では文字サイズ12・16・28、DPI倍率1・1.5・2、ライト・ダーク、長いパスとエラー、レイアウト境界の前後を描画・配置検証します。
