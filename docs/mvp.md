# MVP

本MVPでは、スコープを**「Linuxデスクトップに常駐するキャラクターへテキスト資料の整理・編集を任せ、日々の実用に耐えうる状態」**に絞り込みます。

[構想](vision.md)や[機能一覧](features/README.md)に描く完成像を念頭に置きつつ、本書では今回のフェーズで実装・検証する具体的な範囲を定義します。開発過程におけるスコープの追加は本書に照らし合わせて厳密に判断し、検証から得られた知見をもとに次期フェーズで見直します。

技術選定、構成要素の責務、永続化と検証の方針は[アーキテクチャ](architecture.md)に定めます。

## 1. MVPの目的

キャラクターとの対話を通じてPC内の実作業を依頼し、進行中の雑談や進捗確認、最終的な結果確認に至るまで、同一のキャラクターを一貫した窓口として完結できる体験を確立します。

最初の検証者は開発者自身とし、日常利用における実用性を検証します。なお、非技術者や一般ユーザー向けの導入の手軽さについては、今回の検証対象外とします。

## 2. MVPで検証する仮説

| 仮説 | 検証アプローチ |
| --- | --- |
| 自然な対話を通じて、意図通りのファイル作業を代行できる | コマンドやツール名を指定せず、自然言語での依頼と最小限の補足のみで目的を達成できるか確認する |
| 作業中も対話できることで、待ち時間や進捗への不安が和らぐ | タスク実行中に雑談や進捗確認を行い、対話と作業が並行して成立するか確かめる。利用後に、待ち時間の心理的負担や課題感を記録する |
| キャラクターとの対話と作業代行の統合体験が、日常の実用に役立つ | 後日、別の実作業においても自発的に利用を継続するか確認する |

なお、キャラクターの有無による定量的効果の比較や、長期的な愛着の形成プロセスまでは、本段階の評価対象としません。

## 3. 一連の利用シナリオ（エンドツーエンド）

1. **環境設定と起動**：自身のLinux環境で本ソフトウェアを起動し、LLMや音声合成の接続先、手持ちのVRM 1.0モデル、口調を設定します。
2. **権限の確認と許可**：作業対象フォルダを選択し、読み取り・編集の許可範囲、ならびに外部サービスへ送信されるデータの種類・用途・送信先を確認して承認します。
3. **対話の開始**：デスクトップ上に常駐したキャラクターとテキストで対話します。返答はテキストと合成音声の双方で受け取ります。
4. **作業の依頼**：「このフォルダのメモを話題別に整理し、見出しを整えて一覧を作成して」と自然言語で依頼します。
5. **自律実行と確認**：キャラクターが必要な論点のみを質問し、許可された範囲内で自律的に作業を進めます。
6. **並行対話と制御**：作業の進行中にも雑談や進捗確認を交わし、必要に応じて作業を停止（キャンセル・終了）します。一時停止・再開は扱わず、続行する場合は新しい依頼として伝えます。
7. **結果の確認**：完了報告を受け取り、実際のフォルダやファイルを開いて成果物を確認します。
8. **追加の修正指示**：「この分類名を変更して」といった修正を依頼し、意図通りに反映されることを確認します。

検証には小規模な `.txt` および `.md` 形式のテキスト資料を用い、分類・移動・リネーム・本文編集・一覧作成といった一連の操作を網羅します。

## 4. 実装スコープ（含める機能）

- **キャラクター表現**：手持ちのVRM 1.0モデルを1体読み込み、デスクトップへの常駐表示、ドラッグによる位置移動、透明領域のクリック透過、基本的な待機モーションに対応します。設定した口調プリセットに従って応答します。
- **対話と音声合成**：テキスト入力による対話、文脈（コンテキスト）の維持、応答の音声読み上げ、ならびに読み上げ機能のオン・オフ切り替えに対応します。
- **作業代行**：指定フォルダ内における `.txt` および `.md` ファイルの読み取り、分類、移動、リネーム、本文編集、一覧（インデックス）作成に対応します。タスクは単一実行（同時に1件）とし、作業中の対話・進捗確認・中断、完了後の追加修正指示を扱います。
- **権限管理と安全性の担保**：[権限とデータの管理](features/settings/permissions.md)に従い、アクセス許可範囲をプロンプトだけに頼らず実行基盤側で強制的に制限します。既存ファイルの変更前には復旧用バックアップを保持し、処理の成否を検証して報告します。通常操作ごとの過度な承認確認は求めません。また、アクセス範囲やデータ送信の許可状況はいつでも確認・解除でき、解除後は該当する操作や送信を直ちに停止します。
- **ローカル完結の運用基盤**：単一のPC上で[ホストとクライアント](features/hosting/README.md)を稼働させます。各種設定、対話履歴、最終報告を永続化し、ホストが稼働していればクライアントを閉じてもバックグラウンドで作業を継続し、再接続時に結果を確認できます。

なお、AIモデルや音声合成のAPI設定は開発者自身が行う前提とします。個別の技術・サービス選定は別途設計し、本MVPでは動作検証済みの接続構成をそれぞれ1系統ずつ提供します。

## 5. 対象外スコープ（含めない機能）

- **プラットフォーム拡張**：Windows・macOS対応、リモートホスト運用、複数端末間での同期、Webおよびスマートフォン向けクライアント。
- **高度なキャラクター体験**：マイクによる音声入力、複数キャラクターの同時読み込み、高度な感情モデル・成長システム・長期記憶、キャラクターパッケージの配布機構。
- **多様なツール・高度な実務**：PDF・Word・表計算ファイルの本文編集、Web検索、GUI自動操作、任意のシェルコマンド実行、プラグイン・拡張機能の組み込み。
- **自律的・高度なタスク制御**：スケジュール（タイマー）実行、キャラクターからの自発的な声かけ、複数タスクの並行実行。
- **不可逆・危険な操作**：ファイルの完全削除（物理削除）、許可フォルダ外へのアクセス、ホスト停止後のタスク自動再開。
- **配布と環境互換性**：一般公開向けのインストーラー・配布パッケージの整備、あらゆるLinuxディストリビューションでの動作保証。

これらは本MVPにおける対象外スコープであり、[構想](vision.md)に掲げる将来的な完成像から除外するものではありません。

## 6. 完了条件

機能の実装完了と、仮説の検証成否を明確に区別して評価します。実装上の完了条件を満たし、計画通りの検証を実施して知見を記録できた時点で、仮説の支持・不受容に関わらず本MVPフェーズは完了とみなします。

### 機能の完成条件

- 自身のLinux環境において一連の利用シナリオを最後まで完走でき、キャラクターからの報告内容と実際のファイル変更結果が過不足なく一致すること。
- タスク実行中に対話や進捗確認が行え、中断・停止指示後は新たなファイル操作が発生しないこと。また停止時には、それまでに変更された範囲が明瞭に報告されること。
- 許可範囲外へのアクセスが実行基盤側で確実に拒否され、権限の解除後は関連する操作や外部送信が直ちに停止すること。
- 接続エラー、書き込み失敗、ファイル名の競合といった異常系を完了扱いとせず、エラー理由と変更適用済みの範囲が正しく報告されること。
- 変更前のファイルがバックアップから正常に復元可能であり、ホスト稼働中にクライアントを切断・再接続しても作業結果を確認できること。

### 仮説の検証条件

- 3日以上の期間にわたり、日常の実用資料を用いて計5件の作業代行を試行すること。
- 暫定の実用性基準として「5件中4件以上において、手動でのファイル修正を要さずに目的を達成できること（対話での補足や追加指示は許容）」を設定し、その達否を記録すること（未達であっても貴重な検証知見として扱う）。
- タスク実行中の対話、および完了後の追加修正指示をそれぞれ少なくとも1回以上試行すること。
- 各依頼について、作業結果、対話での補足回数、発生した課題や心理的不安、再利用の意向を詳細に記録し、掲げた3つの仮説を多角的に評価すること。
