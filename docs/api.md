# AlphaホストAPIの意味と移行方針

状態：採用する設計方針（2026-11-03）。**この文書の操作名は論理APIの仮称であり、すべてが追加済みのRPCではない。** 現在利用できるwire契約は[host.proto](../crates/ene-rpc/proto/host.proto)と[ホストREADME](../apps/ene-host/README.md)が正本。2026-11-03のステップ1実装で会話の受理・履歴・停止・実行イベントを、ステップ2実装で心の取得・著者プロファイル編集・心の変更通知を、ステップ3実装で自動整理・自動想起・語句/意味検索・記憶の忘却/共有を実装した。

旧[MVP API案](history/mvp-api.md)は履歴へ移した。旧RESTパス、単一Task、長期記憶を除外する前提を現在のAPIへ重ねない。Alphaでは認証付きConnect RPCと購読・状態再取得を基本とする。既存音声経路の設計は別で、今回本番音声実装まで追加しない。

## 1. 共通の意味

IDはホスト内で安定した不透明な値とする。親、バックエンド設定、作業session、run、入力、質問、操作受付、通知カーソルを混同しない。ホスト／端末／外部サービスの所在を明示し、ある環境のパスが別端末でも開けると仮定しない。

状態変更は、認証主体・操作・対象・要求キー・内容を束縛する。同じ要求の再送は元の受付結果を返し、同じキーで異なる内容なら競合とする。更新はrevisionを検証する。秘密情報を再送比較用の本文やログへ複製しない。

受付は完了ではない。長時間処理の受付には追跡IDと対象IDを返し、配送・実行・終了は取得と通知で確認できる。停止も受付と停止完了・不明を分ける。APIの接続が切れても、受理済みの保存や作業を無言に取り消さない。

会話の受理は`request_id`を返し、Rigが入力を受け付け、そのフレームのセッションログ書込みが成功した後に返す。保存できない入力は受理として返さない。同じ`request_key`の再送は同じ`request_id`を返し、配送を確認できなかった受理は成功として返さない。再起動後に未確定の会話レシートが残った場合は、同じ`request_key`の再送時にRigの保存済み会話・受信箱を`request_id`で照合し、受理済みなら元の結果を返して再配送せず、未配送なら503で確定する。ユーザー発言と返答は`MessageCreated`、実行の開始と終了は`TurnEvent`（`streaming` / `answered` / `stopped` / `failed`）、文字片は`MessageDelta`（`stream_id`）で届く。確定本文は`MessageCreated`と`GetHistory`/`GetMessage`で取得し、文字片を確定内容として扱わない。停止は要求の受付を返し、停止完了は`TurnEvent`で確認する。失敗したターンが入力を会話から取り出した場合は`RecalledInput`で本文を返し、クライアントは入力欄へ戻せる。会話メッセージとしては保存しない。

知らない状態、壊れた応答、未知の終了理由は正常完了にしない。未対応、許可不足、競合、通信失敗、保存失敗、結果不明を区別する。エラーの詳細に資格情報・非公開記憶を含めない。

## 2. クライアントから操作できる範囲

| 領域 | 操作の意味 |
| --- | --- |
| 会話 | 発言の受付、追加入力、履歴・メッセージ取得、実行イベントと文字片の購読、生成の停止 |
| キャラクター | 初期プロファイルの取得・編集と現在の心の取得（`GetMind` / `UpdateMindProfile`）。作者設定と交流で育った状態を分ける |
| 記憶 | 親の`mind_recall` / `mind_read` / `mind_update`、ホストの自動整理・自動想起、`ControlMemory`（forget/remember/share/unshare）。クライアント向けの記憶一覧UIは未実装 |
| 作業 | session一覧・状態・結果、追加指示、相談への回答、個別runの停止 |
| 接続・ツール | プロバイダー・バックエンド・ツール一覧、能力、設定、認証の開始・状態・解除 |
| 許可 | 利用範囲の表示、ユーザーによる付与・変更・解除、承認要求の取得と回答 |
| 通知 | 会話・心・作業・許可・ホスト状態の変更と再同期 |

日常の記憶訂正・忘却は対話で行える。調査用の一覧を編集しなければ記憶が育たない構成にしない。開発者向けの読取操作と、他のコンパニオンや外部プラグインに許す能力は別にする。

クライアントに親のオーケストレーションを実装しない。通常の作業依頼・追加指示・相談回答は親へ出所付き入力として届く。特定の作業へ向けたユーザーの入力も、親が文脈と対象を理解できる形にする。作業バックエンドの検証用直接呼び出しは別能力として扱い、通常の会話と混ぜない。

## 3. 公開状態

### 心

`GetMind`は`MindView`を返し、`UpdateMindProfile`は著者プロファイルの追加材料を版検証付きで更新する。核は既存の`UpdateCompanion.mind`で編集する。MindViewはcompanion_id、核と側面・会話例・背景・表現語彙、profile revision、現在の心のrevisionと更新時刻、現在感情（短い説明・対象・理由・表現信号）、関係の理解、経験してきた傾向、気にかけていることを返す。感情・関係・傾向・懸念はキャラクター固有のJSONで、全員共通の数値尺度を強制しない。全私的記憶や内部推論全文を、アバター表示のためだけに送らない。現在状態と特定発話の表現指示を区別する。

MindViewは索引状態（FTS/vectorの処理待ち、埋め込みmodel・呼び出し数・トークン数）と整理状態（last_sequence、last_offset、jobs、model_calls、input_chars、error/unconfigured）も返す。索引・整理が未完了なことと、該当記憶がないことを混同しない。

`ControlMemory`は所有者だけが記憶の`recall_preference`（forget/remember）と`audience`（share/unshare）を変更できる。忘却は物理削除ではなく通常想起からの除外であり、`include_forgotten`で過去として参照できる。共有記憶は他コンパニオンの想起対象になるが、所有者の私的な入力出所は共有先へ渡さない。共有解除後はcanonicalのaudience再検証で、古い索引から返さない。同じ値への操作はrevisionを増やさない。

変更はSQLiteコミット後にだけ`MindUpdated`で通知し、revisionを含める。クライアントは古いrevisionの通知で現在状態を戻さない。`mind_update`は親のRig実行内のツールであり、クライアントRPCではない。所有者・操作ID・入力出所はホストが束縛し、著者設定・権限・他コンパニオンの記憶は変更できない。同じ操作ID・同じ内容の再試行は元の結果、異なる内容は競合、古いrevisionは競合とする。変更なしも成功である。

MemoryViewは本文、短い説明、出所・取得方法、時刻、共有範囲、訂正関係、想起の扱い、revisionを返す。取得側の権限に応じて情報を制限する。「忘れて」に対して物理削除済みのフラグや成功文を返さない。検索の能力不足・索引更新待ち・外部検索の失敗も、該当なしと区別できる。

### 作業

WorkSessionViewは親、BackendProfile、利用可能性、進行中run、最後の説明、未決Request、成果物参照、再開可能性を持つ。runには入力との関係、配送状態、実行状態、終了理由と失敗・不明の情報がある。backendの設定をキーに一件の履歴しか読めないAPIにしない。

RequestViewは質問と権限要求を区別し、対象session/run、request id、回答形式、影響、関連する許可、状態と版を持つ。許可の範囲は親が書いた説明文だけで決めず、ホストが対象操作に束縛する。

### 能力

機能の存在と、設定・認証・許可が整って実行可能かを区別する。入力形式、途中介入、再開、モデル設定、MCP、停止の実効範囲などを実装ごとに返す。利用できない機能の理由がクライアントと親の双方に分かるようにする。

## 4. 通知と再接続

通知にはホストの起動epochと順序を持たせ、対象IDとrevisionを含める。保存済み状態を正本とし、通知から取りこぼした結果も再取得できる。会話の文字片、意味のある子の説明、心の変更、runの終端は区別する。

購読開始と状態スナップショットの境界を定め、取得中の変更を取りこぼさない。遅延・溢れ・不明なカーソルでは再同期を要求し、重い通知送信が停止制御や保存を塞がない。成功だけでなく失敗・取消・不明も反映する。

文字片の再送と確定本文の取得、進捗の間引きと質問・終了の保持を分ける。クライアントは古いrevisionの通知で現在状態を戻さない。別端末へのファイル同期やプッシュ通知の完成を、この通知契約だけで保証しない。

## 5. 停止・取消

会話の生成停止、指定runの停止、コンパニオン配下の実行停止、ホスト終了を明確な対象で区別する。自然言語の「それを止めて」は親が対象を理解するが、UIの明示的停止はモデルを待たない制御経路を使う。

権限解除は許可のrevisionと実行側の適用状態を返す。ホスト管理下の新しい操作を禁止し、外部ハーネスの取消不能な処理や送信済みデータの扱いを隠さない。クライアント切断は停止要求ではない。

## 6. 移行

後方互換性のために旧REST案や単発ハーネス契約を温存しない。実装変更時にhost.protoとSDKを同時に更新し、必要なクライアント変更、DB・プラグインの移行や再設定を明示する。ステップ1の実装では、`SendMessage`の応答から応答メッセージIDを外し、`MessageStarted`/`MessageUpdated`を`TurnEvent`へ置き換え、`MessageDelta`を`stream_id`で相関させ、失敗時の入力返却を`RecalledInput`として追加した。旧メッセージ表の行は削除しないが、親の会話はRigのセッションログへ移り、旧行は読み込まない。既存データの破棄や旧許可の無条件継承を、互換性不要の意味にはしない。

ステップ2の実装では、`GetMind` / `UpdateMindProfile`と通知`MindUpdated`を追加し、`mind_companions`の著者プロファイル追加材料と現在の心、`mind_memories`の記憶、`mind_operations`の適用結果をSQLiteへ追加した。記憶と心の正本はSQLite、会話はRigセッションログのままであり、会話全文を複製しない。ステップ1の旧データは削除せず、心の初期状態は既存の`Companion.mind`から読む。

ステップ3の実装では、整理・埋め込みを`purpose=memory, data=["memory"]`のGrantとコンパニオン接続へ分離し、タスク割当・タスクGrantとは共有しない。自動想起はローカルSQLiteの語句検索で配送前に外部埋め込みを待たず、意味検索は`mind_recall`で行う。確定はRigの会話entryの`status=completed`で判定し、処理済み`(last_sequence,last_offset)`の直後から前向きに取得する。長い発言はオフセット分割し、末尾まで処理するまで処理済みにしない。埋め込みはRigのOpenAI wireに認可付きトランスポートを渡し、検索時にmodel・前処理・次元を照合する。共有の公開範囲は本文・説明・appraisal・訂正関係idで、私的な出所は渡さない。`mind_index_pending`・`mind_memories_fts`（FTS5 trigram）・`mind_vectors`（model/dimension/前処理/vector）・`mind_index_status`・`mind_consolidation`を追加し、`ControlMemory`、MindViewの索引/整理状態を追加した。自動整理は確定した会話範囲と処理済み位置を同じSQLiteトランザクションで進め、生成失敗・保存失敗・競合では進めない。FTSとベクトルはRRFで統合し、canonicalの所有者・共有範囲・忘却・時刻で再検証する。埋め込みはタスクGrantで送り、OpenRouter接続の埋め込みは未対応としてsemantic unavailableを返す。

本書は意味の契約と責務を定める。最終的なフィールド名・タグ・エラーコードは実装時のprotobuf/SDKを正本とし、同じwire仕様を手書き文書へ重複列挙しない。実装した能力だけを広告する。[実装順序](alpha.md)
